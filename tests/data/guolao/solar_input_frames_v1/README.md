# 果老太阳钟的参考系与同次太阳接线

此参考冻结18组给定TT／UT1数值对：三组来自修复前实际LAT请求的
数值时刻，另十五组是预先选定的代数控制，包含现代窗口两端和J2000
精确捷径的两侧。后者固定TT减UT1为64.184秒，只是输入，不代表对应
年代的实测ΔT、UTC或地球定向。三个请求时刻也不构成独立历法验收。

参考进程不导入FateBridge。太阳原生赤经／赤纬来自未改动的
[Swiss Ephemeris v2.10.03原作者代码](https://github.com/aloistr/swisseph/tree/175e1fcb3108bcd5c0d146c803f51dcf23508012)，
按其实际偏置、岁差和章动重建源框架；另用官方SOFA 2023-10-11计算
IAU 2006/2000A目标赤道和恒星角。远期按原先明确的完整边界三轴政策
延伸；这不证明远期物理准确度。原生坐标转到目标框架后，以独立FLINT
精确有理数算时角相位。来源、生成器和既有二进制在计算前后校验字节；
本次没有重新构建二进制，也没有把它们宣称为完整执行读取集证明。

真太阳时由同一个参考系中的太阳赤经和恒星角确定，定义见
[USNO均时差说明](https://aa.usno.navy.mil/faq/eqtime)；参考系与地球转角
的关系见[USNO Circular 179](https://aa.usno.navy.mil/downloads/Circular_179_bw.pdf)。
原生太阳位置和目标物理赤道中的赤经并非可直接相等的量。

比较前沿用既有参考门槛：角度一微角秒、钟相位0.0002秒，均属给定
数值模型的计算门槛，不是实测精度。三组诊断请求的两种赤经相差约
0.00045至0.00152角秒，错误的跨框架精确比较会拒绝有效LAT请求。
修复复用同次保留的坐标变换，将校验的太阳放到钟面的实际参考系；
不改太阳位置、物理瞬间、原有时间门槛或来源资格。

`reference.json`是固定数值目标，`provenance.json`包含比较前冻结
的哈希及范围。便携测试直接读取数值，无需原作者库、SOFA或FLINT
参考环境；实际生产运行仍需要当前引擎。生成器和完整原始记录在
provenance所指仓库外目录。

Swiss参考与SDK有共同祖先，SOFA和生产ERFA也共享标准实现来源；
这是分别执行的参考系及接线对照，不是两个独立天文模型。不能把
它用于宣称行星绝对精度、历史钟制、完整果老原典、预测或SOTA通过。
