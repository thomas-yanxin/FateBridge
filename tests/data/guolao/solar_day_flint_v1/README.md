# 果老太阳钟、日界与明确安命日政策

比较前冻结1280组太阳钟输入、420组黄经日端点、60组单调多项式钟
及4组必须拒绝的求根控制。太阳钟控制包含全部时支界、午夜、正午、
相邻binary64、次正规经度、±180度经线、民用时区标签和日期载体两端。
它们是代数控制，不是1280个真实出生样本。

独立进程以python-flint 0.9.0的精确有理数计算太阳相位、日序、时支、
到界距离及显示截断，民用日期使用官方SOFA 2023-10-11历法函数。
两个浮点交付量以整数商余数独立编码最近偶数舍入，不依赖生产
Fraction转浮点。端点参考按节气事件落在日前、日内或日后的离散关系
判断两种明确政策；不根据排盘结果选择原典读法。

单调钟的导数在完整三日窗有明确正下界，参考用FLINT有理数隔离根，
线性控制直接给精确根。生产有符号夹逼必须包含参考根，宽度仍不得
超过1毫秒，出生时刻必须严格处于两日界夹逼之外。固定窗口无根、
精确午夜、浮点分辨率不足和非单调整窗均保留报错。

另冻结20个完整排盘输入的实际TT／UT1数值，覆盖交节、经度日期线、
LAT，以及UTC零年和闰秒无普通datetime载体的分支。参考不导入FateBridge，
用未改动的[原作者Swiss 2.10.03源码](https://github.com/aloistr/swisseph/tree/175e1fcb3108bcd5c0d146c803f51dcf23508012)
和[官方SOFA](https://www.iausofa.org/2023-10-11c)分别重算同框架太阳赤经、
恒星角及日界，独立二分直到相邻binary64 UT1。完整模型与远期框架政策
沿用[太阳输入参考](../solar_input_frames_v1/README.md)。两种政策共40次
实际排盘，含12组不同出生TT／UT1。40条日界参考记录对应32个不同物理
夹逼，按两种政策重复比较80次，全部包含在生产夹逼内。沿用一微角秒坐标、
0.0002秒钟相位和1毫秒生产求根门槛。

真太阳时定义见[USNO](https://aa.usno.navy.mil/faq/eqtime)。安命条文来自
东北大学附属图书馆所藏陆位辑校本《新編評註通玄先生張果星宗大全》
卷1–2的第9张图，见[目录](https://touda.tohoku.ac.jp/collection/en/database/library/10020000001141)
及[既存扫描回执](../../../fixtures/guolao-small-limit-v1/reference.json)。本轮
是已知读法后的同图复核，不是独立专家校勘。“冬至日后”纳入当天与否、
原书历史日界及以日出辰寅为据的实际几何解释仍未裁定。

`reference.json.gz`只保存独立参考及给定输入，不把产品输出当作期望。
`provenance.json`保存参考、生成器、输入和实际库的哈希及仓库外原记录
位置。便携测试无需FLINT、原作者C或SOFA参考库。

首轮参考用极窄区间隔离线性根，当生产上端点恰好等于精确根时，区间
仍横跨该点，引发24个参考包含检查失败。参考侧改为精确线性解，原
文件和失败保留；输入、生产代码及判据不变。参考驱动参数拼写和LAT
构造路径的两次错误也保留原日志，均未作为算法失败或通过计分。

本轮实际天文对照限定原生Moshier与默认ΔT路径；没有重做IERS C04、
SWIEPH或JPL路径的独立对照。Swiss与生产SDK有共同祖先，SOFA和ERFA也共享标准来源。这是给定模型
的分别执行对照，不能代替独立物理星历、实测地球定向、历法钟制验收、
完整原典判断、预测或全局SOTA。
