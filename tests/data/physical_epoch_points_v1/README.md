# TT实点、闰秒区间与名义别名

参考源为未修改的 [IAU SOFA 2023-10-11 C](https://www.iausofa.org/2023-10-11c)：
由实际重编的 `iauCal2jd` 取得Gregorian整日，取同版 `dat.c` 的1972年后
整数TAI−UTC与精确32.184秒，以独立有理数计算全部27次正闰秒的TT半开区间。
生成参考时没有导入FateBridge。来源、原源码及库散列随参考保留。

每个start/stop取其最近binary64及左右各两个IEEE邻点，共270项边界观测；
若同一浮点值在不同边界记录重复，仍保留原边界身份，不当成独立历史事件。
其中134项处于秒60，显示微秒依既有向下取整格式，由精确点减精确区间起点求得。
事先固定的门槛是点分类精确相等及该显示微秒精确相等。

修复前分类241/270相同、秒60微秒字段2/134相同；修复后分别270/270、134/134。
原始失败、源表、参考指纹和基线原始标签保留。根因只有一个：物理TT实点入口
误用已舍入的名义边界，并把该舍入误差带入秒60的小数显示。

`legacy_nominal`另存原 `datetime_from_tt(float)` 的有意名义标量政策；
全部270项行为保持。物理入口不借名义午夜别名把闰秒内的实点移到新的一日。
例如冻结输入 `0x1.2bd16c0197aebp+21`（2012-07-01 stop最近浮点）比原子边界
早约15.184879微秒，应为 `2012-06-30T23:59:60.999984+00:00`，不能报7月1日零时。

完整UTC字串的普通微秒格式另作补充检查，共136项；采用最近微秒并保持在
原普通半开区间内。初次补充参考漏掉排除端点约束，将1972-07-01 start最近浮点
（距起点−0.282764微秒）误录成次日零时；正确普通标签为前日23:59:59.999999。
这项是补充格式参考的错误，初稿和订正在外部证据中保留；没有改生产算法、原
270/134项门槛或分母来迎合它。补充136项当前相同，不升级为原先预注册的门槛。

`reference.json.gz` 保留完整 270 项、基线、来源身份与补充格式对照。仓库回归入口为 `tests/astronomy/test_utc_clock_domains.py`，读取冻结的源表期望值。

公开反例输入通过生产逆算构造，只证明冻结点可从公开入口达到；参考点及分类
仍来自先冻结的SOFA源表，不把构造输入的逆算结果当成第三方真值。

这是选定浮点点语义与显示核对，不认证观测钟时、UT1 物理精度、所有历史分数调整或全部浮点域。
