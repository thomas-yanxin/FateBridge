# 历法边界、钟时载体与独立对照（2026-11-11）

本轮修复真实的年份边界故障，没有扩大个人出生服务的1900—2100年范围。
共享节气年表的民用年份为1—9999；所选模型、资料文件及各消费者仍有各自范围。
相邻年0／10000仅作为合法上下文所需的内部边界，不能单独请求其全年年表。

## 根因与实现

旧节月窗口无条件求相邻三个全年表，年初／年末会请求不可表示的0／10000年。
合法当地时间的UTC标签也可能落在这两个辅助年份；缓存键、时间回执、大运比较
强制转Python UTC datetime，因而另外溢出。9999年末晚子时的日期加一天也越界。

现在邻接交气与节月窗口先用本年表，仅在首尾求所需相邻交点。河洛跨季节消费者
保留原来完整的三个年周期；相邻年在模型范围内时保留自己的年profile，仅在范围
外才借用输入年的边界资格。`UTCCalendar`统一保存整数日序和
日内微秒，`ZonedCalendar`附加实际时区及扩展年标签；原子／历史钟时仍由同一个
`time_scales`所有者反解，普通datetime入口仅检查其可表示性。日序进位、大运半开
区间及缓存按实际UTC瞬间处理，不截年、不夹到午夜、不另造钟时算法。
流月显式传入完整瞬间时，年月日标签和节月均取该瞬间，不再混用旧年月参数。

果老没有唯一UTC标签的原子时调整点继续按主要TT比较。其年号只负责选择候选，
仍读取完整相邻年周期；不能把用于选年的七月占位日期当作实际事件来收窄窗口。
本轮扩大回归检出了这一回归，原51项调整点、半开区间及三端断言保持并重新通过。
独立Python3.10环境还复现了新载体对末尾`Z`标签的解析回归；已在ISO读取边界恢复
原有`Z`到零偏移的规范化，原始三项失败及整组钟时回归分别保留。

## 八字时运职责与流时钟表边界

2026-11-15完整审读[时运核心](../src/fatebridge/core/timing.py)的28个具名定义，包括1个类和1个嵌套边界函数，并将原2组13项粗清单细分为105项职责。缓存、历法委派、干支递推、起运换算、民用历逆像、可重放分钟、盘内关系和展示分别登记；28个定义不是28种算法，完整读过函数体也不代表所有分支和传统来源已通过验收。

本轮复现了流时缓存对有效钟时的误改。原实现先取得实际本地查询时刻，再截到整点并重新转换时区；在非整点缺口之后，这个名义整点可能不存在。例如1988年4月3日04:01 UTC在Goose Bay实际为02:01，原返回04时、甲寅，固定第三方时柱为癸丑。Chatham、Lord Howe和Kathmandu也有原始见证。修复后缓存只取得民用日期和小时，不构造整点瞬间；`analysis_datetime`另取实际查询时刻，保持原秒级字符串格式。公开参数和字段形状未增加。

独立时钟以项目实际固定的pytz 2026.6所带TZif文件为输入，按[RFC 9636](https://www.rfc-editor.org/rfc/rfc9636.html)单独解析显式转换点，并由原生C `localtime`读取同一文件投影UTC。它独立于生产ZoneInfo读取器，但不是独立编纂的第二套时区史料。[IANA的Chatham和Lord Howe规则](https://data.iana.org/time-zones/tzdb-2025b/australasia)也明确列有非整点规则；不能假设每个本地小时都有合法的00分。
