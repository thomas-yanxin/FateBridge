### 显式约定与未解决事项

- `is_diurnal=true/false` 可在 REST、MCP、CLI 明确选昼贵/夜贵。省略时卯至申为昼、酉至寅为夜。未自动计算当地星出星没；原文特别指出昼夜长短随季节变化。
- 金口诀 `di_fen` 应来自已确认的方位或起课方法；省略保留软件按时支的回退，并返回 `di_fen_source=hour_branch_fallback_not_observed_direction`，不把它当现场观测。
- 月将用实际民用瞬间判断中气；真太阳时校正用于日时柱，不把太阳钟的偏移再次应用到天文事件。已核对 2026 年 12 次交中气及不同时区的边界，未认证全部历史历法。
- 季节旺衰采用辰戌丑未整月土旺的工程口径，未认证季末十八日土旺等异法。课内已实现十二例共有的唯一不受克规则；多候选、日下旺衰、无克从旺取用及全部格局的综合裁决未覆盖，不能把阴阳用爻规则当作完整断课法。
- 金口诀转录本“甲子日亥时巳位”例称勾陈；按同本夜贵未逆行应得朱雀。保留冲突，等待刻本校勘。
- 辛酉课例称四位纯阳，但同本天乙己丑属阴。程序保留贵神固有属性，不为匹配此句改表。
- 神煞、旺衰、动爻提供传统结构依据，不把医学、灾祸、生死断言转成产品预测输出。

以上疑文登记在参考集的 `unresolved` 中，审计会明确列出。没有因疑文而修改预期标签、删除失败来源或把不支持算成通过。

### 重复民用钟与四柱缓存

40项专项、449项相关检查通过，REST／原生MCP／CLI完整和严格投影一致；最终专项与公开合同合计46项复核通过，各队列有重叠。54项比较复用既有资料的5个天文分钟锚点，不是54个新增天文观测；7个中气时区投影中，Metlakatla分钟边缘的不确定性保留。未重评或改动原PMO 21项失败、原典53/64与46/62成绩，尚未完成全历法、全原典和真实模型解释验收。详见本轮记录（本地数据：`validation/ren-civil-fold-validation-2026-10-22.md`）。

### 星历缓存隔离与实际模型

修复切换星历目录后仍沿用旧年度结果的问题。真实接口在2026-01-20 01:44:56 UTC复现了旧缓存子将、清缓存后丑将，以及金口诀将神随之改变；修复后不清缓存即符合当前所选数值环境的重新计算。缓存还识别同目录文件变化和库实例变化，不长期记住短暂求解失败。求根核对实际返回标志，五项交气依赖与快照公布实际模型和库版本，混用或无效模型不会成为已认证边界。

最终冻结副本221项相关回归通过；扩大队列617通过、4项已知风水投影失败。工作区实时复测因并行修改未通过源码稳定性门槛，另行保留失败；冻结副本的完整3,024项PMO比较仍3,003符合、21未通过，最大差30.905079秒，4,536组中气边界对符合。本轮全部分钟项实际模型为SWIEPH，不把缓存回归当作独立天文样本增分，也不把冻结成绩认证为后续工作区成绩。原典和真实模型解释未决项继续保留，详见第十一轮记录（本地数据：`validation/ren-ephemeris-cache-validation-2026-10-22.md`）。

### 交气时间尺度与边界序列化

旧共享求解器以 `calc_ut` 求得UT1交点，再用 `revjul` 直接标作UTC，混淆地球自转时间与民用时间。现改为TT求解太阳视黄经交点，再复用共享时间尺度模块转换民用标签：1960年前保留UT1/ΔT历史约定，1960年采用[SOFA历史UTC偏移与日漂移](https://www.iausofa.org/2023-10-11c)，1961–1971年采用IERS历史UTC漂移，1972年后采用冻结闰秒表。第七轮报告保留当时实现记录，本段按当前共享时间层更新；SOFA标准换算仍不认证当地钟表记录或实际UT1。未来闰秒在表到期后保持末值是假设，五个实际交气依赖逐项公开时间尺度、转换方法、到期日及假设是否触发。节气字符串保留数值小数秒，避免先舍入后判断边界；这些位数不代表微秒物理精度。

完整重跑3,024个紫金山天文台分钟值，按原30秒准则有3,003项符合、21项未通过，最大差30.905079秒；原五项仍在队列，全部未通过项保留。此前整秒比较的3,019/3,024是历史结果，不能继续作当前成绩。4,536组中气边界对均符合。既有JPL原始响应的12个太阳坐标有10项符合预先冻结的0.1角秒准则，1900与2099两项未通过；这不是12个独立求得的交气时刻，本轮也未取得新的在线JPL响应。

200年香港天文台完整日期队列复测仍有7项节气日期差异；日期级约束比较未发现新增计算差异，交节当日未定探针及326日不可用农历继续单列。原典与自由文本解释的未决项不因本轮修复而改变，现实预测验证按用户要求暂缓。详见完整验收与来源（本地数据：`validation/ren-timescale-validation-2026-10-22.md`）。

### 完整年表队列与历法依据

独立核对1901–2100全部200份香港天文台年表，覆盖73,049个日期。日柱、所测时柱及年/月柱和月将的日期约束比较均未发现差异，72,723个可用农历日期一致；另有326日农历超出现有库范围。交节当天的前后两种可能仍作为未定探针单列，不能把年表日期当成精确交气认证。4,800项节气日期有7项近午夜差异，全部保留，详见第五轮记录（本地数据：`validation/ren-calendar-validation-2026-10-22.md`）。完整历法域仍未认证。

随后取得紫金山天文台《1900—2025年日历》，先冻结全部126年3,024个分钟值，再比较。五处旧历日期差异有该书明确脚注，1979大寒与印刷分钟相差5秒；2084尚缺此层资料。全量分钟准则比较仍有五项31秒差异，3,019/3,024符合预定30秒准则；没有调宽门槛。三个固定时区的4,536组独立中气边界对均符合月将交接。新证据追加在分钟比较报告（本地数据：`validation/ren-calendar-pmo-audit-2026-10-22.json`），原七处日期差异未删除。

发现并修复三个实际问题：天文失败后的静默线性回退可使2026雨水附近月将差错达六个多小时；跨夏令时时使用墙上钟相减会使节气间隔日数差一小时；校正后的太阳钟被快照误标成直接时间。三工具和三式内六壬现在核验实际交气提供者，失败返回503依赖错误；`calendar_policy` 与快照明确民用输入、日时取用钟、23:00子初换日及归属日期。真太阳钟只用于日时柱，交节和中气仍据民用瞬间。提供者可用不等于精度获证，七处日期差异未被强行改判。

六壬新增 `guiren_profile`：默认 `liuren_common_v1` 保留既有甲戊庚牛羊等表；`tanyuan_xieji_v1` 按《探原》遵《协纪辨方》的十干日夜贵人歌。20 个日夜起点和 4 个原文落宫、顺逆例符合。两表不同的十干位置不再混称同一原典；该选项只换六壬贵人表，不改变三传支序，也不改变金口诀本课的古本贵神表。规则轨迹与结果注明实际配置及来源。

涉害深度相等、且多个候选同落孟位时，原算法直接返回第一候选并标成“见机”。现在进入复等裁决并记录剩余候选；戊辰干上子、戊辰干上亥、戊戌干上亥三例符合《探原》缀瑕说。三传未变，但课体名称和解释依据得到修正。

历法补验了真太阳时的时辰边界：2026-04-04 20:57、Asia/Shanghai、121.5°E，按 [NOAA/Meeus 公式](https://gml.noaa.gov/grad/solcalc/calcdetails.html)独立算得约 +3.053590 分钟，应跨过 21:00，六壬与金口诀均得到亥时。现用的共享 Swiss 实现与该参考相差在 1.2 秒容差内；旧按日期正弦近似会漏过这个边界。这是有限时刻的独立数值与接线核验，不是全时期天文精度认证。NOAA 此计算器已停止维护，不能据其参考宣称官方认证。

```bash
uv sync --locked --extra dev

  --output /tmp/ren-classical-audit.json
uv run --locked --extra dev python -m pytest -q \
  tests/test_ren_classical_depth.py tests/test_ren_transports.py \
  tests/test_metaphysics_reference.py
```

审计分开报告 5 个明确原文课例、73 项所选规则/课例比较、12 个官方中气边界、720 局软件 oracle 和 2 处待校勘疑文。73 项包含这 5 个课例，不重复相加当样本量。`selected_checks_passed` 仅表示所选比较通过。启用完整目标门槛：

```bash

  --require-full-conformance
```

当前该命令返回非零：`classical_acceptance_passed=false`、`authority_certified=false`。这不是应该通过改测试来消除的工程失败。

三端测试使用真实 FastAPI、原生 FastMCP 客户端和 CLI，覆盖完整输出、严格字段投影、昼夜覆盖、非法地分拒绝。它们属于本地协议验收，不代表生产部署或真实对话模型已验收。

### 解释忠实与现实预测

结构化事实引用可使用已有 `fatebridge.validation.claims.verify_calculation_claims`，绑定原始完整结果的 `run_id` 和业务结果 SHA-256。当前测试核验金口诀贵神名称，拒绝错引为旧值、跨结果或篡改完整结果；自由文本是否忠实仍需独立人工或盲评，不能由结构化校验代替。

前瞻评估可复用已有 `scripts/audit_prediction_study.py` 与 `fatebridge.validation.predictions`。本轮没有真实外部结果数据，`real_world_prediction=not_tested`。开始正式研究前，需要：

1. 固定一个可客观裁定、有限时间窗内的单一事件目标，写清未发生和无法裁定的条件。
2. 在收集结局前冻结完整样本队列、规则/代码/解释策略、概率校准方法、对照基线和分析计划。不能从传统旺衰或动爻直接编造成功概率。
3. 分开开发、校准和锁定测试集；若同时研究六壬和金口诀，预注册比较方式和多重检验处理。
4. 由不了解预测的人裁定结局，记录可信外部时间戳和原始证据。拒答、缺失、不利结局仍计入覆盖率，不事后筛选“有缘”的样本。
5. 报告覆盖率、Brier 分数、相对基线的改进、置信区间及适用范围；用新独立样本复现。比例区间参照 [NIST Wilson 方法](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

原典记载的应验故事属于历史文本，不是随机对照、独立留出或前瞻数据。任何有限样本即使全中，也只能说明那个样本的结果，不能认证所有问题、所有未来情境都满分。
