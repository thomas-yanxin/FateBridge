# 八字未来钟时事件的显式转换表索引

在已加载的 TZif 显式转换表覆盖范围内，钟时事件现在直接按转换时刻枚举，再由原 `ZoneInfo` 对象核对前后偏移。此前的逐秒扫描完整保留，用于表外区间、没有显式转换表的文件及无法确认身份的时区对象；没有改成粗粒度采样。

索引按 [RFC 9636 第3.1—3.2节](https://www.rfc-editor.org/rfc/rfc9636.html#section-3.2)读取版本1的32位或版本2及以后的64位显式表。它仅服务于当前解析器加载、散列守卫通过且对象身份相同的规则。相同名称的其他 `ZoneInfo` 对象不会借用此索引；文件变化仍触发原来源错误。窗口超过最后一个显式转换时刻时继续逐秒扫描，不自行解释 POSIX 尾部规则，也不据此预测未来法律。

事前协议（本地数据：`validation/bazi-tzif-explicit-scan-v1/protocol-first.json`）保留原源码、时区数据及选择范围。独立参考（本地数据：`validation/bazi-tzif-explicit-scan-v1/reference-first.json`）包含全部597个声明时区的40,556个显式转换时刻，以及预先选定10组日期的原始逐秒结果。参考过程不导入 FateBridge。首个候选曾在参考输出冻结前写入，但没有执行或评分；该候选另存，原源码恢复后才生成参考，再原样重放候选。此顺序及没有盲测信用的事实单独保留。

验收记录（本地数据：`validation/bazi-tzif-explicit-scan-v1/report-first.json`）区分证据范围：

- 全597个时区的显式转换时刻与未改动的标准库读取器一致；10组单日及九日窗口与原完整逐秒扫描均无事件增删。
- 最终32项冻结检查通过，包含旧同名对象、多次跳变、午夜与可表示日期边界、表外回退，以及完整与字段投影的 REST／MCP 应用协议／CLI 输出一致性。1,897个输入运行后散列不变，加载路径未泄漏到原工作区。另22项共享时区来源回归通过，其1,898个冻结输入也未变。
- 独立 stdio 进程分别加载旧内核与最终候选，同一历史跳时用例的完整业务 JSON 相同；这是一个明确请求的比较，不是全量队列验收。
- 8组符合索引条件的九日窗口，原扫描耗时合计约3.47秒，最终索引约0.00064秒；另外2组仍走回退。这是并发负载下的一次工程耗时观察，不能推断全量复算加速比例或增加准确率成绩。

首次25项通过、2项失败以及路径守卫误报均保留。后续仅改为核对结构化错误原因，补齐已有时区夹具，并将 macOS 路径规范化后核对加载来源；原逐秒参照与生产候选数值未改。

第二轮31项通过后，又发现公元1年空表区间的快捷返回绕过了原日期溢出检查。新增对照首先保留一次失败，再把原起点转换和偏移检查移到快捷路径之前；最终32项与22项回归针对该修订。此处确实修正了候选代码，不把较早候选的通过记录当作最终修订验收。

首次归档的整树差异守卫发现19个路径变化，其中3个是本轮已有文件的修改，其余属于本轮之外的工作区变化；该断言失败保留。另行冻结当时完整源码后，26项三端与时区来源集成检查通过，1,903个输入未变。本轮不覆盖其他修改，也不将这些检查称为其他模块的完整验收。

本修改用于降低历法验收的扫描成本。原40,219条失败证据、最近一次完整结果的54,818条严格失败、41项浮点边界冲突、26处分歧历史及旧五例机械0／5均不因此关闭。正在运行的原冻结复算不重启、不替换内核；本轮无新模型执行、安装包发布或既有 MCP 连接更新。
