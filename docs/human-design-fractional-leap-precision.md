# 人类图闰秒输入标签与完整解释核验

本轮修复已接受的亚秒偏移闰秒输入：保持原始UTC标签的小数秒，并使完整固定解释核验按该输入核对，保留浮点TT的实际逆算显示。它不改变星历使用的TT，也不认证当地钟的真实授时实现。独立参考、原错误回执、三端、安装包及完整回归证据见复核报告（本地数据：`validation/human-design-fractional-leap-verification.json`）。

例如虚构输入2016-12-31当地23:59:60、时区`-0.0000000025`小时，按既有恒定偏移模型对应UTC `23:59:60.000009`。原输入解析器保留了相应TT，却把UTC标签写成`60.000000`。这个错误的完整解释核验也通过了：两个民用标签在单个双精度儒略日上发生重合，不能再靠反算浮点TT找回丢失的9微秒。

偏移为`-0.00001`小时时，预期UTC标签是`60.036000`，原盘显示由TT反算的`60.036008`，完整核验反而拒绝该成功返回的结果。闰秒最后1微秒还会与下一日零点共享浮点TT，原结果错误显示下一日零点及非闰秒标记。原始失败和误通过回执均保留，不能将其解释为输入记录无效而删掉。

修改生产代码前已冻结135项计划：原27次已公布正闰秒，各取原实现接受的零偏移、9微秒、36毫秒、半秒及最后1微秒五种情况，没有按通过与否筛选。使用未修改的[IAU SOFA 2023-10-11 C源码](https://www.iausofa.org/2023-10-11c)独立生成两部分TT参考，所有原源码指纹和0.0002秒门槛固定。修复前135项都接受，只有27个精确UTC标签，54份完整解释核验通过；其中27份恰是9微秒标签丢失后的误通过。原81项闰秒参考与全部既有案例保持原字节。

现在输入解析器将UTC锚点的微秒保存在闰秒标签中，`following_utc_midnight`明确指闰秒结束的零点。主盘采用经日历表确认的原始输入标签与闰秒标记；它不再用双精度TT的逆算显示覆盖输入。`design_solver.civil_elapsed_days`对闰秒出生保持`null`，避免在TT恰与零点重合时捏造一个可用普通datetime相减的民用出生时刻。

完整核验仍逐条检查原生进程实际返回的TT显示、Delta T逆迭代及各子盘时标。对于具名“已确认闰秒出生”方法，另要求标签和选定TT与冻结日历、原输入严格对应；其他连续TT快照仍必须匹配原有显示见证。主盘的原始标签和浮点逆算显示可以不同，两者各有依据。重新计算业务哈希也不能把主盘替换为下一日零点、错误闰秒标记或错误日历零点。旧9微秒误通过回执须在禁止原生重算时被拒绝。

所有135项的星历TT、UT1、26个激活及人体图结构逐值保持不变；27个零偏移控制的完整业务结果保持类型、数组顺序及浮点位一致，只排除运行元数据。这里修复的是输入身份、标签与解释忠实性，不把保留9微秒的字符串说成星体达到9微秒物理精度。完整结果还覆盖9微秒与闰秒末端输入的生时区间见证。

原错误还影响周期输入排序：出生标签为`60.000009`时，旧实现接受评估时刻`60.000008`。现有准确输入排序使用源定义的有理TT，能在同一浮点TT上保留这1微秒的先后；`60.000009`仍为相等，`60.000010`为之后。三种接口均保留对应错误或完整解释，未裁定的第六线阶段继续为`null`。

维护时使用[独立生成器](../scripts/build_human_design_fractional_leap_reference.py)及固定官方SOFA源文件显式运行`--check`。普通测试只读取冻结事实，不联网、不编译；参考不能在修改生产代码后重写来迎合实现。已确认的UTC闰秒、恒定数值偏移的标签运算与真实地方钟是不同验证范围；本轮仍不证明历史或亚秒偏移地方钟的实际实现、实测UT1、连续历法穷尽、出版方原典母本、完整384线线义、任意模型解释或现实预测。
