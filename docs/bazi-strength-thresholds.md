# 旺衰阈值的精确算术

既有工程政策规定：扶身份额大于0.60为数值强，小于0.40为数值弱，等于两条边界时均为中和。此次修复了浮点累计与除法将边界推入相邻档位的问题，权重、阈值、原典标签和结构规则保持。

例如，虚构工程输入1988-07-05 08:00、上海民用时、关闭真太阳时，当前历法得到戊辰、戊午、辛酉、壬辰。既定工程算式的扶身量为331/32，减身量为331/48，份额精确为3/5；旧浮点值为 `0.6000000000000001`，原数值档和最终档均误入强。修复后为中和。1990-03-01 12:00同口径的庚午、戊寅、乙丑、壬午，份额精确为2/5，旧浮点值 `0.39999999999999997` 曾误入弱，现也为中和。这些是可调用的虚构回归输入，不是实测出生记录或新的独立历法参考。

二进制浮点不能精确表示多数十进制小数，显示舍入也不能恢复原先的比较语义。[Python官方浮点说明](https://docs.python.org/3.12/tutorial/floatingpoint.html)解释了这一限制。修复沿用已声明的十进制工程系数和几何藏干份额，以分数重建预算，只改变阈值比较；没有使用宽容差把邻近值一律归中和。分数由系数文字及整数份额构造，不将浮点结果直接转换成所谓精确十进制数。[Fraction官方说明](https://docs.python.org/3.12/library/fractions.html)明确区分了这两种输入。

公开 `thresholds` 字段卡覆盖综合、标准命盘和九专题。将字段卡的 `fields` 传入调用，视图名不是计算参数。原始命盘回执位于 `bazi_birth.day_master.assessment.threshold_arithmetic`；共享解释依据位于各入口的 `evidence_chain.strength_context.threshold_arithmetic`，综合与标准命盘外层路径分别含 `structure_profile`。

回执保留：

- `support_exact`、`weaken_exact`、`share_exact`：既定工程预算的分数字符串；
- `weak_threshold_exact`、`strong_threshold_exact`：实际使用的阈值；
- `numerical_label`：精确比较后的数值档；`strength_level`另含既有结构规则；
- `legacy_float_numerical_label`、`float_comparison_differs`：旧浮点判档及其是否不同；
- `support_above_half`：既有得令重根分支使用的严格二分之一比较。

原浮点能量、总量及份额继续交付，便于核对旧结果；不再用其边界误差决定上述比较。整体传统工程政策仍标v7，新的比较算术单独标 `exact_rational_strength_thresholds_v1`。历史私有实验模式未借此重新评分。

标准命盘快照在旧浮点数值档不同时补充同次分数依据。“数值档”与“结构最终档”必须分开：24个数值档纠正中有5例被既有结构规则覆盖，最终判级没有变化。字段投影缺失时不补算；类型合同拒绝份额、总量、档位与差异标记之间的矛盾。

精确分数仍取决于原先记录的离散关系、工程系数及其语义，不证明这些规则符合整部原典，也不提供物理精度或现实概率。身印承载、有效月内司令和通关效力仍待裁定。完整范围、首次失败及遗留门槛见本地验收（本地数据：`validation/bazi-strength-threshold-v1.md`）。
