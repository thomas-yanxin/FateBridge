## 分盘修复的根因

此前`varga_coordinates`先把有理数盘内度数转为float，`varga_longitude`再加目标星座起点，造成第二次舍入。给定二进制或有理数输入时，结果可能与对完整有理数坐标只舍入一次相差一个浮点步长。另一个边界是`math.isfinite(Fraction)`会先作浮点转换：类型本身有限的大有理数因此可能报溢出。

现由[同一分盘所有者](../src/fatebridge/core/jyotish/jyotish_vargas.py)保存精确的目标星座和盘内有理数，三个公开函数各在最终输出处转换。输入类型、八种分配、D30不提供经度以及既有半开目标区间的约定保持。已有限的`Fraction`不再要求可表示为有限float，普通浮点输入仍在所属边界拒绝非有限值。

这没有添加第二套生产分盘算法、模型补算或展示层推断。线性等分盘坐标是已声明的FateBridge显示约定，来源星座分配与显示算术分别核对。

`mean_longitudes`原来先把Earth的精确多项式转float，再加180并模360得到Sun；`nathonnatha`原来先把日组转float，再用60减显示值取得夜组。现分别保持太阳对点、日组与夜组的有理数算式，最终标量各自舍入一次。没有更换系数、作者、坐标／时间模型、准入范围或强度常数；水星仍为60。计算仍在原领域所有者中，不新增第二套生产公式。

可以直接核对这两处的数学不变量：在整数／有理数运算正确的前提下，Horner循环保存原文多项式的精确值，先按360归约再加180与最后统一归约等价；Nathonnatha最短弧在0–180度内，两组精确值之和为60。因此新增误差只应出现在各最终标量的浮点交付处，不能再从已舍入的另一个标量派生。独立逐幂和与IEEE编码的固定对照检查这一交付，没有把计算模型的正确算术写成物理时标或原典解释均已证明。
