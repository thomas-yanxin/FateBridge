# 法达版本兼容参考与验收约定

本文将 2026-10-19 用户提供的法达计算说明整理为可复现的工程参考。来稿未提供作者、版本或可核验的第三方实现；其中关于“测测端”的描述只代表来稿，不证明该产品的实际算法。

**公历周年版本已接入生产代码，现有法达默认组合保持原结果和返回结构。** 两个独立参数 `firdaria_night_order` 与 `firdaria_year_basis` 同时适用于独立 `firdaria` 和综合 `western_timing_analysis`，见第 8 节。下文 profile ID 仍是文档和测试标签，不是接口参数；它们只标识四种可选组合中的两种。

## 1. 两套口径

| 项目 | `fatebridge_firdaria_legacy_v1` | `user_reference_calendar_bonatti_v1` |
| --- | --- | --- |
| 状态 | 生产默认组合 | 生产可选组合；夜盘选 `nodes_after_mars`，年长选 `calendar_anniversary` |
| 日盘顺序 | 日、金、水、月、土、木、火、北交、南交 | 相同 |
| 夜盘顺序 | 月、土、木、火、日、金、水、北交、南交 | 月、土、木、火、北交、南交、日、金、水 |
| 年长 | 固定每年 365.2425 天 | 大运边界为原始出生钟时的公历周年 |
| 大运推进 | 从上一段结束继续加固定日数 | 从原始出生日期按累计名义年龄独立求周年 |
| 小运 | 大运年数 / 7，连续加固定日数 | 将大运两端对应的 UTC 历时七等分，独立计算各边界 |
| 序列重复 | 每 75 个固定年重复 | 每累计 75 个公历年重复 |
| 显示 | ISO 8601，保留实际计算出的秒／微秒及偏移 | `start/end` 保留微秒；`start_display/end_display` 截到分钟，不四舍五入 |

这里的 `legacy` 只表示既有行为标签，不表示它是弃用接口。365.2425 是当前常量的数值，不能因为变量名为 `TROPICAL_YEAR_DAYS` 就宣称它是逐年求解的真实回归年或太阳返照。

固定年长也可能采用 365.25 等其他约定，但本参考不将它们与这两套口径混用。

## 2. 来源与工程补充的边界

- 来稿提供：九段年限、日夜顺序、七等分小运、交点不分小运、两个分钟显示示例。
- [Öner Döşer《Astrological Prediction》节选，第 38–40 页](https://bendykes.com/wp-content/uploads/2016/08/ap-extract.pdf)：列出总计 75 年的九段及七等分规则，采用夜盘交点位于火星之后的版本。
- [Steven Birchfield《Firdar》，2020 修订，第 2–6 页及附表](https://birchfieldastrology.com/wp-content/uploads/2020/07/firdar_revision-02-2020-07-13.pdf)：引述 Abu Maʿshār 的夜盘水星后接交点规则，并讨论通常归于 Bonatti 的另一种理解。因此本文用 `bonatti` 作版本标签，不将历史归属争议写成已无争议的事实。
- 本项目新增的工程选择：时区处理、UTC 七等分、闰日回退、原始出生锚点、微秒量化、分钟截断及边界归属。这些不冒充来稿已说明或第三方产品已经实现的规则。

来源只支撑传统算法与版本沿革，不证明现实预测效力。

## 3. 年限、顺序与日夜盘

固定年限为太阳 10、金星 8、水星 13、月亮 9、土星 11、木星 12、火星 7、北交 3、南交 2，总和严格为 75。

| 大运 | 日盘名义年龄 | 当前夜盘名义年龄 | 来稿夜盘名义年龄 |
| --- | --- | --- | --- |
| 太阳 | 0–10 | 39–49 | 44–54 |
| 金星 | 10–18 | 49–57 | 54–62 |
| 水星 | 18–31 | 57–70 | 62–75 |
| 月亮 | 31–40 | 0–9 | 0–9 |
| 土星 | 40–51 | 9–20 | 9–20 |
| 木星 | 51–63 | 20–32 | 20–32 |
| 火星 | 63–70 | 32–39 | 32–39 |
| 北交点 | 70–73 | 70–73 | 39–42 |
| 南交点 | 73–75 | 73–75 | 42–44 |

七星小运按“日、金、水、月、土、木、火”的循环从本段主星开始；两交点不参与小运，也不再分七段。

核心数学验收显式给定日夜盘，不用示例年月日反推。三端验收另提供明确虚构的上海坐标并实际计算本命盘，不将测试地点当作来稿已给事实。来稿没有出生地点，无法核验其“太阳五宫／十宫”是否成立。当前引擎的 `determine_sect` 用太阳第 7–12 宫判日、其余判夜；太阳宫位缺失也会落入夜盘分支。它还不是独立地平线高度判定，不应将整宫制、日出日落临界或宫位缺失场景视为已验收。改进该判定需单独改动共享计算与三端回归。

## 4. 时区约定

### 当前引擎的可观测行为

出生钟时按 `birth_timezone` 解析，未传时区时沿用地点推断及共享构造器回退行为。分析钟时也按出生时区解释；验收始终显式提供时区和分析钟时，不依赖系统现在、出生小时的默认回填或未知地点。

时间线从带时区的 `birth_info.local_datetime` 出发，直接做本地 `timedelta` 加法并输出 `isoformat()`，没有先统一到 UTC。在 IANA 时区跨夏令时时，墙上钟时加法与真实 UTC 历时可能相差一小时；不能宣称当前算法对所有 IANA 时区均采用恒定 UTC 秒数。当前接口也没有法达专用的出生 `fold` 消歧参数。

### 参考版本的新增约定

1. 测试将两个原文例子明确实例化为 `Asia/Shanghai`，这只是时区测试条件，不代表已知出生地点。也接受显式固定 UTC 偏移；固定偏移不自动获得某城市的历史夏令时规则。
2. 公历模式的 IANA 钟时使用标准库 `ZoneInfo`，按运行环境时区数据库及其未来延续规则解释，也覆盖 2038 年后的夏令时；未来法律变化仍可能需要更新时区数据库。出生、分析钟时或所生成的周年边界若处于不存在的时间（春季跳时）或重复的时间（秋季回拨），生产公历周年模式返回 `validation_error`，不猜偏移。错误会指出钟时角色，周年边界还会指出名义年龄。接口尚无端点单独消歧入口；需要确认有效钟时或改用已确认的固定偏移，后者将对整个时间线采用固定偏移，并非仅消歧一个端点。该限制只在公历周年模式生效，固定年模式保留原有行为。
3. 先在出生时区建立大运周年端点，再转 UTC 求差与七等分，最后转换回显示时区。更换显示时区只改变显示，不改变边界瞬间或当前主星。
4. 内部判断用带时区的完整瞬间，公历周年模式统一转 UTC 比较，不能用去掉偏移的字符串或展示到分钟后的时间进行比较。公历周年模式不接受分析时刻早于出生时刻。

## 5. 公历周年、闰日与等分

参考版本采用延伸公历；本文用例均为现代日期，不宣称历史改历场景已经兼容。设出生时刻为 `B`，累计名义年龄为整数 `a`：

```text
anniversary(B, a):
  目标年 = B.year + a
  月、钟时仍取原始 B
  日 = min(B.day, 目标年月的最后一天)
```

出生在 2 月 29 日时，非闰年回退 2 月 28 日，后续闰年恢复 2 月 29 日。所有边界均以原始出生日期为锚点，不能从已经回退到 2 月 28 日的上一段继续加年。例如夜盘 `2000-02-29 12:00 UTC`，9 岁为 `2009-02-28 12:00`，20 岁恢复为 `2020-02-29 12:00`，75 岁为 `2075-02-28 12:00`；2100 年不是闰年。

大运 `[S, E)` 内的第 `k` 个小运边界：

```text
boundary(k) = S_UTC + round_half_even((E_UTC - S_UTC) × k / 7)
k = 0..7，量化单位为微秒
```

从同一个起点独立求各边界，不把截断后的分钟数逐段相加。最后一个边界严格等于大运结束，下一段开始复用该边界。微秒量化可能使各段相差 1 微秒，这是时间表示精度，不是额外的小运时长。

大运、小运均为左闭右开 `[start, end)`：恰在边界属于下一段；交点大运的当前小运为空；恰在 75 年边界进入下一周期。名义年龄不能由显示日期反算成 `75.1` 后再决定周期。

## 6. 显示与两个原文示例

参考版本的原始边界保留微秒；分钟展示只在时区转换之后将秒、微秒归零。展示值不回写计算，也不影响边界归属。名义年龄使用整数累计年限，第一周期结束固定标为 75，原文的 `75.1` 仅作为未核验的产品展示描述保留。

| 场景（时区补充为 Asia/Shanghai） | 参考精确小运结束 | 参考分钟展示 | 当前引擎小运结束 |
| --- | --- | --- | --- |
| 1997-12-28 18:25，夜盘月亮首段 | 1999-04-12T08:07:51.428571+08:00 | 1999-04-12 08:07 +08:00 | 1999-04-12T08:45:24+08:00 |
| 2001-10-12 11:40，日盘太阳首段 | 2003-03-18T04:48:34.285714+08:00 | 2003-03-18 04:48 +08:00 | 2003-03-18T06:16:00+08:00 |

原文的分钟总数 4,733,280 和 5,258,880 正确；除以七分别为 `676182 + 6/7`、`751268 + 4/7` 分钟，不能将省略小数后的整数写成精确等式。若四舍五入到分钟，会得到 08:08 和 04:49，与原文不一致。

## 8. 生产接口选择

| 参数 | 可选值 | 默认值 |
| --- | --- | --- |
| `firdaria_night_order` | `nodes_at_end`（夜盘水星后接交点）、`nodes_after_mars`（夜盘火星后接交点） | `nodes_at_end` |
| `firdaria_year_basis` | `fixed_365_2425`（原本地时间固定年加法）、`calendar_anniversary`（公历周年、UTC 七等分） | `fixed_365_2425` |

两项可独立选择，夜盘顺序选项不改变日盘顺序。它们在共用的 `WesternTimingRequest` 家族中公开，顺序和年长算法只用于综合时运中的法达层及独立法达工具；其他独立技法忽略这两项。公历模式还按 `ZoneInfo` 解释本次出生／分析民用钟时：若与旧解析的未来夏令时偏移不同，综合工具的其他技法也按同一修正后的瞬间计算，保持本次查询的钟时一致，技法自身算法不变。默认模式的时区路径不变。非法枚举在三端均被公开请求模型拒绝。

默认组合（包括显式传入两个默认值）不增加业务字段，以保留已有完整结果、快照和业务哈希。任一选项非默认时，法达对象增加 `calculation_options`，记录 `night_order/year_basis/subperiod_basis/timezone`。公历周年模式的每段大运还增加 `nominal_start_age/nominal_end_age`，大小运均增加 `start_display/end_display`；精确 `start/end` 始终参与计算。`analysis_context.age_years` 是其他西占技法共用的固定年年龄，不随法达口径改变；法达周年边界以 `nominal_*_age` 为准。

REST 请求体与 MCP `firdaria` 参数使用相同字段，例如（地点明确为测试假设）：

```json
{
  "birth_year": 2001, "birth_month": 10, "birth_day": 12,
  "birth_hour": 11, "birth_minute": 40,
  "birth_timezone": "Asia/Shanghai",
  "birth_longitude": 121.4737, "birth_latitude": 31.2304,
  "analysis_year": 2026, "analysis_month": 10, "analysis_day": 19,
  "analysis_hour": 12, "analysis_minute": 0,
  "firdaria_night_order": "nodes_after_mars",
  "firdaria_year_basis": "calendar_anniversary"
}
```

REST 地址为 `POST /api/astro/timing/firdaria`；综合接口为 `POST /api/astro/timing`，MCP 对应 `western_timing_analysis`。CLI 对应：

```bash
uv run --no-sync fatebridge firdaria \
  --birth-year 2001 --birth-month 10 --birth-day 12 \
  --birth-hour 11 --birth-minute 40 --birth-timezone Asia/Shanghai \
  --birth-longitude 121.4737 --birth-latitude 31.2304 \
  --analysis-year 2026 --analysis-month 10 --analysis-day 19 \
  --analysis-hour 12 --analysis-minute 0 \
  --firdaria-night-order nodes_after_mars \
  --firdaria-year-basis calendar_anniversary \
  --no-include-snapshot-text --strict-fields \
  --fields firdaria.calculation_options firdaria.current_major firdaria.current_sub
```

综合命令替换为 `western_timing_analysis`，字段路径相应为 `time_lords.firdaria.*`。`return_timezone` 仍属于返照／行运地点，不改变法达边界或法达展示时区；法达始终按出生时区输出，调用方可转换精确瞬间用于其他时区显示。运行中的 Desktop MCP 连接可能缓存旧 Schema，更新源代码后需重载连接再使用新参数。
