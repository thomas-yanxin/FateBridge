# 补回149条登记编辑说明

产品原典查询现采用v7数据索引，补回149条源记录已有、旧索引遗漏的编辑说明。全部367条记录、321个不同输入、123条明确标签、244条未知／未标注记录和3条禁止档位约束保持。生产旺衰、历法、四柱输入及计算结果没有更改。

源码与独立安装包的本地验证完成；当前连接的MCP仍按用户“暂不重连”的决定保留未更新状态，本轮不重复失败调用，也不把本地通过写成实际连接验收通过。

## 漏失原因与修复

初版生成器读取`reasoning`以及若干标注依据字段，没有读取`annotation`。因此149条原记录已有的说明，在产品的`annotation_basis`和`retained_context`中同时为`null`，其中52条有明确强弱标签。例如，原记录解释了如何把“日主弱中变旺”映射为工程强档，产品却只返回等级和短锚句。

新的生成器固定绑定事前协议、完整v6索引、原登记文件及149个完整记录修订。逐条解析原文件中的JSON位置，核对同一命例、原说明文本、记录散列和原标签，再原样填入两个字段；其他218条索引对象逐项保持。历史v6及全部旧索引、原始转录和原计算继续保留。

新增`editorial_annotation_provenance`标记说明来自登记文件的`annotation`，携带文件散列、记录编号、字段位置、原记录／原索引对象／说明文本散列及原标注类型。`is_verbatim_original_text=false`明确整段是登记编辑说明，不能冒称原典逐字引文；原典锚句另列。`strength_label_assigned_or_regraded=false`和独立验证信用0保留这次修复的性质。

查询摘要同步提示编辑说明与原典引文分开。运行时核对文本散列、来源、命例及原标签；输出Schema在完整／摘要投影之前拒绝伪称原文、重判标签或新增独立验证信用。

这是资料投影修复。字面匹配、禁止档位比较及强弱比较方法未变，因此继续使用`registered_literal_source_annotations_reviewed_inputs_v5`；另以`data_revision=source_annotations_v7_editorial_projection`和投影协议散列区分资料版本，没有降级为旧连接仅支持的v3方法来规避错误。

## 全量结果

先在修改前保存全部367条当前输入的真实服务输出。修改后逐条比较，完整计算、来源比较状态、已知相符／分歧、未知状态、禁止档位及未改写计算标记均相等。当前24个不同输入的分歧保持；原始26处分歧没有因此扣除或重评分。

新149条说明逐字对应原记录，其中52条有标签、97条未知。加上此前已保留的6条说明，当前155条存在`annotation`的源记录全部在两个产品字段中原样保留，没有剩余的同类遗漏。其他材料使用的`reasoning`或既有依据不被覆盖。

此前50条“旧有明确标签／全书未作三档映射”的待审记录中，45条的已有说明现在可从产品读取；待审状态不变。它们不能因说明恢复、计算相符或全书未知而自动改判。

- 真实隔离MCP在源码和安装包中各执行33次有效调用、1次错误调用，分别恢复305页同run结果。覆盖9个来源组、强／弱／未知、禁止档位、旧明确分歧、上次校读来源和最大的完整结果。4,096字符预算保持，核对原回执、分页身份、偏移、全文及冻结完整业务散列。

最终检查器在产品检查完成后，另有一项“34份生成合同字节全部不变”断言失败：正式生成器纳入了其他星盘输入模块的时区说明更新，6份合同、7个说明叶节点发生变化。原合同、原失败、差异及分类收据均保留；当前生成合同与冻结Schema一致，其余28份相等。本八字修复的输入合同保持，此处不宣称原字节不变检查通过，也不把其他星盘更新当成本轮成果。

验证结束时，工作树另有4份人类图文件和`.DS_Store`与冻结视图不同，均未回退或并入本修复结论。上述验证适用于明确冻结的视图及其安装包，不能据此认证整个当前工作区、其他体系、Linux黄金字节、托管CI或已连接服务。原首份分类收据中一处保留状态字段措辞有误，原件与澄清后的第二份均保存，原断言结果仍为失败。
