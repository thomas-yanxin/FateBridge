## TT 精度进入实际日历

此前正确的精确算术仍会接收到先相加、再取整的大儒略日浮点数。现在 DE440 默认根解算保留基日和日内偏量，并将两者交给 `datetime_from_tt_point`；只在最后交付 Python 微秒标签时取整。输出同时保留 `selected_crossing_tt_parts`、两段式根区间、数值表示声明和兼容的标量展示值。缓存版本区分新旧日历路径。

两段式表示的用途可参见 [ERFA 的 TT→TAI 实现](https://raw.githubusercontent.com/liberfa/erfa/master/src/tttai.c)。它解决数值表示损失，不把纳秒级数值区间升级为天文模型的物理准确度。此前全部 4,872 个根的独立比较继续见[两段式参考审计](bazi-tt-representation-and-acceptance.md)。

新日历转换器完整回执（本地数据：`validation/bazi-calendar-point-utc-first-v1.json.gz`）和旧默认入口复放（本地数据：`validation/bazi-legacy-float-utc-v34-retained-v1.json.gz`）使用完全相同的 6,391 个冻结输入、原预期值和拒绝条件。新路径明确传入 TT 瞬间；旧入口的 13 个值差异、14 个正常值拒绝和14个不可表示标签误接受全部继续出现。没有将浮点展示值与原本民用午夜的意图混为一类，也没有修改原41项记录（本地数据：`validation/bazi-tt-scalar-conflicts-retained-v1.json`）。

1960—1971 年使用同一套历史 UTC 仿射段，以有理数反解；更早日期继续声明 Swiss UT1／Delta-T 约定。[ERFA 的历史表及说明](https://raw.githubusercontent.com/liberfa/erfa/master/src/dat.c)也明确区分 UTC 历史适用范围。新增的独立 Decimal 参考保留全部506项：412项最初标为正常、90项不可表示、4项前UTC未知。其中7项首次预期标签在取到新段午夜后，不能满足原0.2毫秒前向保持条件。程序拒绝这些标签；原始预期和7项失败仍保留，未据此宣称历史原判据全通过。协议与首败见历史瞬间夹具（本地数据：`../tests/fixtures/bazi_historical_point_v1/protocol.json`）和首轮诊断（本地数据：`../tests/fixtures/bazi_historical_point_v1/first-diagnostic.json`）。

## 完整同类会局的结构判级

新增条件是：已有完整三合或三会以日主同元素为目标、目标透出、没有被判为冲突失效，并至少保留两个现有资格规则认定的重根。原有财官连续透出抑制规则仍先执行。条件满足时使用结构判级，原始能量账本、所有参数、强弱数值阈值和敏感性变体的数值保持不变。

来源定位到1947年李雨田校订任注《滴天髓阐微·众寡》PDF268。根数及存留条件是工程编码，完整会局不等于完全成化；这项有限规则不代表整书已经形式化。采用前协议（本地数据：`../tests/fixtures/bazi_complete_bureau_adoption_v1/protocol.json`）先于生产采用冻结，保留 v6 源码及预试候选。

当前完整语料回执（本地数据：`validation/bazi-complete-bureau-adopted-source-corpus-v1.json.gz`）仍使用25组、349条记录、303个不同输入和全部234条未知编释。改善的三组为：

- `XX-16`：己巳、辛未、丙午、丁酉。
- `FJ-08`：癸卯、丙辰、甲辰、丙寅。
- `DTCW1947-ZQ-03`：癸丑、壬戌、丙午、庚寅。

三组均由弱改强，与原先保留的强标注相符。另有两条未知记录的计算变化，仍保留未知，不增加匹配信用。20条记录的结构规则说明发生变化，实际判级仅5条变化。原26项逐项差量（本地数据：`validation/bazi-complete-bureau-adoption-delta-v1.json`）继续收录全部原柱、原预期和来源定位，区分3组改善与23组未解。

源索引只在计算之后比较字面四柱，没有以原典标签覆写结果。历史 v6 全349份旧计算可由保存源码准确复放；新v7另核所有数值账本及原有匹配记录。源材料全部已暴露，改善不计入独立盲测。

## 验收工具和仍保留的失败

旧根力实验曾混用归档主程序与当前辅助模块。本轮从保存的证据包恢复哈希完全相同的 `classical_roots` 和 `classical_stages`，在私有命名空间加载，不替换生产模块。旧首轮结果逐项相等；任一归档辅助模块被改动仍会拒绝复放。当前运行环境的变化继续明示，不借历史复放获得新的采用资格。

源码关键回归125项通过，另有2项成对验收检查，约束新日历通过不得覆盖旧41项失败、采用后23项不得删除旧26项记录。REST、原生MCP和CLI核对完整结果及投影，包括3组改善、未解控制、未知和未登记输入。独立源码及基础安装包stdio各完成7次有效调用、1次错误输入拒绝、631页同次结果及255个实际消费根的检查。

本轮首次测试选择包含一个不存在的测试路径；后续投影检查漏请求方法版本字段，产生6项检查失败。另一次构建写入首次快照的打包清单，测试期间排版也使原绑定失效。全部日志保留，修正后使用新的冻结快照，构建另用工作目录。没有恢复字节后把第一次运行声称为无漂移。扩大回归首次为3,745项通过、113项失败、27项跳过。用同一113个失败节点、相同测试字节在升级前冻结源码上复核，112项同样失败；新增1项仅为v7结构规则说明与旧诊断回执不同。该原始断言及其旧版本通过控制保留，新版本另要求所有数值、标签和630项压力试验不变，且规则说明确实满足采用条件。未来钟时六批已完成116,906条原编号、状态、顺序及唯一性核对，保留116,124条已知与782条未知；安全数值、已知状态、反演事件和已知单元门槛通过，严格包络失败54,818条。首次合并在把源收集器的扫描量诊断计数误当作已发出行的状态计数时拒绝；完整部分文件和首败保留，第二版合并分别验证这两类计数，没有改动源尾标、实际行、计算或原始判定器。原顺序进程继续保留。未改动的独立整数算子归因（本地数据：`validation/bazi-dayun-split-root-sensitivity-second-v1.json`）完成全部812,868个已知探针：同一实际节气根下812,868项整数历法计算相等，580,620项安全探针没有一项越出同根包络。原独立参考根下的54,818项失败仍保留，不能由同根通过替代。这把根／时标约定的差异与同根起运算术分别定位，未认证物理UTC或包络全局极值。

## 原典字面研究和立春边界输出修复

扩大回归还定位到两项既有功能问题。研究层新增藏干关系时，误把符号性的字面干支观察一律要求为六十甲子；现在严格的历法／时运单柱入口仍拒绝非周期组合，字面研究层只验证单字干支，并对非周期组合明示标记。真实349条登记记录逐项核过，其单柱全部属于六十甲子；不合五虎遁／五鼠遁与单柱不属六十甲子是不同问题。非周期组合仅为符号合同测试，不记为新增原典例证。

另有九个主题在立春日返回内部错误：`boundaries_on_date`误声明成字符串字典，而实际节气包含数值偏移、整数fold和模型对象。修订复用既有`SolarTerm`合同及其时钟一致性验证，不把数值强转成文字或丢弃模型信息。18个原本内部错误的三端用例已恢复；新增120种单字组合、原60组严格门槛、349条不改柱及边界合同的122项检查通过。首次独立藏干表并未规定巳中两个次级藏干的顺序，检查曾误当作顺序规范；首败及纠正依据分别归档，既有60组完整回执仍逐字相等。

最终冻结源码本轮选择的381项中380项通过，1项旧摘要预算断言仍失败：事业首视图的元数据延后字段增加了`run_metadata.provenance`。未将这一原断言改为通过。源码与基础安装包的新独立stdio进程，各验证九主题、男／未知两组共18次立春日调用，核对90页同次完整结果及实际两段式TT根。协议、首败与全部源码快照会同完整队列结果分别保存。
