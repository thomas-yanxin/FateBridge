# 备用节气根的 TT 点值消费语义复现

本轮在未修改的实际解析节气调用方中复现了与旧41项完全相同的失败编号。尚未修改生产，也未宣称41项旧默认标量门槛通过。默认两段式DE440分支已使用显式时间点；此次定位的是解析／SPK结果没有两段分量时的备用分支。

同一浮点JD可以被旧兼容接口视为已舍入的民用标签编码，也可以被明确声明为一个IEEE时间点。两者在原子偏移转换边界的别名处不能混用。`_solar_term_utc_via_analytic`的有分量分支已调用`datetime_from_tt_point(TTInstant.from_parts(...))`，无分量分支却调用默认兼容的`datetime_from_tt(result['jd_tt'])`。数值求根器输出本身并未携带“这是原UTC午夜标签”的意图。

事前协议（本地数据：`validation/bazi-scalar-solar-consumer-v1/protocol.json`）在测试前冻结，沿用原6,391个输入和全部原状态、预期及判据。仅将解析求根器替换为逐项返回冻结点值的控制，再调用未修改的真实后续转换路径。控制根不宣称处于该测试调用的实际节令搜索区间；这是一项合成消费层隔离检验，不是重新求出的真实节气、独立观测或天文模型精度验证。

首次完整结果（本地数据：`validation/bazi-scalar-solar-consumer-v1/baseline-first.json.gz`）保留全部输入：

| 原状态 | 数量 | 结果 |
| --- | ---: | --- |
| 正常瞬间 | 3,930 | 3,903相等，27项值差异或错误拒绝 |
| 不可表示UTC标签 | 243 | 229项正确拒绝，14项误接受 |
| 原典时制参考未决 | 2,218 | 全部保留未知，不计通过 |

41个失败编号与旧默认入口41项记录（本地数据：`validation/bazi-tt-scalar-conflicts-retained-v1.json`）精确相同。它说明已知点值与标签编码的歧义实际进入了调用方，不能用“精确转换函数已经存在”认定所有消费者已迁移。

调用清单第二版（本地数据：`validation/bazi-scalar-solar-consumer-v1/consumer-call-inventory-v2.json`）还确认原生Swiss求根后也使用默认标量入口；该分支本轮仅完成代码定位，没有用上述控制实际检验，不能将解析分支结果直接扩展为原生检验成绩。第一版清单误按扩展函数名`swisseph`筛选，遗漏实际名为`swe`的调用；首版保留，清单修正没有改动任何数值结果。

后续修复应只为数值求出的根声明显式时间点，保留旧民用标签兼容入口及其原断言；默认两段式根和来源也不能换成参考答案。采纳前仍须核对完整点值与历史未知、共享回归、实际节气结果、错误传递及REST/MCP/CLI。合成控制通过不能单独满足这些要求，亦不能关闭54,818条跨根包络失败。

冻结运行时1,135个文件和全部事前输入运行前后散列均相等。生产改动、模型执行和新增独立观测均为0；本轮只完成了故障发现收据（本地数据：`validation/bazi-scalar-solar-consumer-v1/discovery-report.json`），修复状态仍未完成。
