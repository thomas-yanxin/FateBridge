# 出生重复钟时与已知 UTC 偏移

八字11个入口与七个时运入口新增可选 `birth_utc_offset`。它验证已确认的民用偏移，并在同一当地钟面出现两次时选择实际出生瞬间。年、月柱的节气判定和出生至节令的经过时长使用这个瞬间；后续交运仍保留原 IANA 地区时区。

例如虚构工程样本 `1991-09-15 01:30:00 Asia/Shanghai`，`+09:00` 对应前一天 `16:30 UTC`，`+08:00` 对应 `17:30 UTC`。两者相差一小时，钟面字样相同。偏移未知时继续拒绝选择；不存在的钟时即使提供偏移也拒绝。

## 参数与证据

- `birth_utc_offset` 接受字符串 `±HH:MM` 或历史整秒偏移 `±HH:MM:SS`，数值、布尔值、非法偏移和与已解析时区不符的偏移不能生成完整报告。未知省略或传 null。
- 偏移不用于猜测地区时区。`timezone_source` 说明地区时区来自显式输入、出生地解析或软件假设。校验通过不证明这个地区时区就是实际出生记录采用的时制。
- 重复钟时可由非整小时或历史政治时制改变产生，不能把 `fold=0/1` 解释为必然“夏令／冬令”。`fold=0` 是较早出现的瞬间，`fold=1` 是较晚的瞬间。
- `calendar_context.birth_time_input` 在提供偏移时增加 `requested_utc_offset`、`civil_utc_offset`、`civil_instant_utc`、`civil_fold`、`civil_time_ambiguous`、`timezone_source`、`timezone_rules` 与 `offset_selection_scope`。标准命盘的完整路径为 `bazi_birth.calendar_context.birth_time_input`；专项、综合和时运路径遵循原有上下文位置。
- 回执和快照保留偏移选择与实际 UTC；出生分钟、秒数的省略事实仍按[出生输入分量](bazi-birth-seconds-audit.md)声明。确认偏移不认证出生记录精度，不自动生成时间误差区间。
- 直接领域调用若同时传入 `PersonInfo.birth_utc_offset` 和函数关键字，两者必须选择同一实际瞬间。`+09:00` 与 `+09:00:00` 等值；不同选择拒绝，不能静默替换已确认资料。
- 用户确认的正负分钟范围仍是逐分钟采样。跨回拨时，派生样本按各自实际瞬间更新偏移；不把名义出生偏移强行套到整个范围，也不宣称连续区间内全部秒数已验证。

## 修复前证据与独立参考

冻结协议（本地数据：`../tests/fixtures/bazi_birth_fold_v1/protocol.json`）先固定范围、源文件、负例和不能升级的全局结论，再生成参考和实现功能。参考采用 [IANA tzdata2026e](https://data.iana.org/time-zones/releases/tzdata2026e.tar.gz) 与同版 [tzcode](https://data.iana.org/time-zones/releases/tzcode2026e.tar.gz) 的官方 `zic` 编译，手工解析64位 TZif 过渡表，以源偏移算出 UTC。没有调用 FateBridge、ZoneInfo 或 dateutil 来生成钟时真值。公开时区名单来自锁定的 pytz，仅决定覆盖名单。

初次构建因本机 Xcode 许可未接受而失败，日志保留；改用已安装的 Command Line Tools 编译同一官方源码，没有替换成旧系统 `zic`，也没有代用户接受许可或修改全局工具配置。

参考覆盖597个公开时区中与本地出生年份1900–2100相交的31,623次回拨和31,960次跳时。每个区间检查起点、整秒中点、终点前一秒；重复点仅在同一事件内完全相同时去重。94,869个回拨点各有两个来源偏移与瞬间，95,880个跳时点没有有效瞬间；所有点再含未提供偏移、错误偏移或两侧偏移负例，共762,996次归一化尝试。

修复前完整私有关键字路径189,738次有效瞬间检查与573,258次拒绝检查均符合参考；公开八字模型的189,738次已知偏移请求均因额外字段被拒绝。这轮补齐公开契约及传递链，没有把既有私有解析能力计作新增天文算法。

IANA 来源支持时制规则核对。别名、重复年度和同一个数据版本之间的比对存在依赖，不能累计为独立观测；未来规则有条件于2026e，历史规则也不认证某个人的出生档案。

1972年前的UTC字样沿用冻结软件口径的前推标签，不能据此断言当时已经采用UTC，或把历史规则、UT1近似与真实记录误差认作已解决。

## 节气、四柱与交运

联动参考（本地数据：`../tests/fixtures/bazi_birth_fold_v1/coupled-reference.json`）从原先冻结的节气根与钟时换算口径中，选取全部252个“两次瞬间对应不同前后节气、八字年或月支状态”的回拨点，覆盖107时区、160个事件；另含每种回拨幅度的首个稳定排序中点，共111种幅度。选择发生在候选实现之前，没有按候选结果筛点。

每个点以两种缓存访问顺序计算两次瞬间；同一未校正钟面对应的日、时柱须一致，节气、年柱、月支须符合各自瞬间。男女两种顺逆分别检查参考节令、UTC经过秒数和未舍入起运岁数；预先固定经过时长绝对容差0.1秒。这个容差针对共享天文根与时间换算的实现一致性，不是独立认证的物理误差界。

哈瓦那2021年立冬的两个重复钟时另保留[香港天文台原刊](https://www.hko.gov.hk/en/gts/astron2021/files/2021cal11.pdf)的分钟依据：较早瞬间仍为戊戌月，较晚瞬间已为己亥月。上海、纽约、豪勋爵岛和哈瓦那还检查真太阳钟是否以所选 UTC 求均时差，并用同一瞬间的固定偏移作内部一致性对照；这不是新的独立均时差观测。

选定出生偏移后不能把地区时区永久替换成固定偏移。上海样本在 `+09:00` 出生，其后交运日期使用地区规则的 `+08:00`；固定 `+09:00` 会把未来交运实际瞬间挪动一小时，即使名义日期和起运经过时长相同。

随后发现，已确认第二次重复钟时的出生，在距参考节仅数秒、名义起运余量仍落于重复区间时，首运默认选第一次会早于出生。该问题与输入消歧、经过秒数分别核对；首运边界修复（本地数据：`validation/bazi-dayun-initial-fold-v1.md`）保留全部首次失败，修正首运的实际选择，原有钟时和起运经过时长参考不重新计分。
