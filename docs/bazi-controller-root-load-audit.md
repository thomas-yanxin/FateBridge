# 官杀根量、清浊与否定约束漏验

本轮修复了完整原典审计漏读命例内部否定约束的问题，没有采用新的旺衰判级规则。生产仍为v7，旧23项三档分歧保持。一个开发材料上修正7条、没有已知退化的候选，在预选完整新单元中没有新增修正，故未通过原采用门槛。

## 固定候选与完整旧例

此前容量v3允许有身根、有比劫且透出官杀至多一处的命式获得承载判级。这没有区分同一处官杀获得多少根气支持。新候选沿用原条件，仅在有透出且有根的官杀时，要求现有日主残余藏干预算不少于官杀残余藏干预算；无透出官杀的分支不增设此条件。全部五行用同一关系，系数、根表、原标签及数值账本不变。

事前协议（本地数据：`validation/bazi-controller-root-load-v1/protocol.json`）固定候选、完整361条旧例和接下来完整阅读〈清气〉、〈浊气〉两个单元。该预算条件是工程假设，原典没有给出这条充分条件定理；没有用命式字面或历史人物身份例外覆盖结果。

完整开发复放（本地数据：`validation/bazi-controller-root-load-v1/development-first.json.gz`）保持361份生产完整计算相等，保留121条明确标签、240条未知和315个不同输入。容量v3有9条开发改善、1条退化；新候选有7条开发改善、0条已知退化。它同时失去了旧候选的两条开发改善，未只保留有利差量。

这7条均是旧候选已经获得的开发改善，本轮没有在生产中修正这7条。旧候选的印重分支也原样保留，不能把整个候选的所有变化都归因于新增官杀根量条件。

己酉、丁卯、己卯、乙丑例可说明机制：只有一处乙木官杀透出，但其木根在月、日两处，现有残余预算合计5.4；日土残余预算约1.142857。新候选因此不再把原弱例改强。该例暴露于开发阶段，不能计作新的独立检验。

## 完整清气、浊气单元

使用1947年上海大东书局本原书扫描，整书散列为`d6a7d1daf6513ce9fb9940ff8331b96804c10cdafbeac00d4d3d0a37229e1803`。原书正文前是较长的初学材料，没有找到可用目录，故在读取所选命例前记录定位方法修订（本地数据：`validation/bazi-controller-root-load-v1/boundary-location-addendum.json`），只改变按标题定位的方法，未更换预选单元。

PDF235〈清气〉标题至PDF242〈真神〉标题前，两个完整单元各3造，共6造。235页伤官尾造、242页真神开头和定位时额外暴露的相邻页分别记录，不混入新单元。第三个清气例的年柱癸未在238页末，其余甲子、丙寅、丁酉续于239页；跨页四柱全部保留。

六造转录与语义边界（本地数据：`validation/bazi-controller-root-load-v1/reference.json`）及冻结收据（本地数据：`validation/bazi-controller-root-load-v1/reference-freeze.json`）在任何新造计算前保存。两造有明确最终旺衰，四造没有唯一三档标签。其中“日主之气不薄”另记为排除弱的有界编释，不补成强或中和；同一开发者校读，独立原典专家仍待复核。清气、浊气、清枯、得令及人物经历均未被用来自动生成强弱答案。

首次全单元结果（本地数据：`validation/bazi-controller-root-load-v1/prospective-first.json.gz`）中，生产、旧候选和新候选均只符合2条明确标签中的1条，新候选新增修正为0，4条未知保留。生产与候选均将癸酉、甲子、丙寅、乙未判弱，而原注在丙日语境明言“弱中之旺”；甲子、丙寅、己亥、辛未也仍判弱，违反保留的“不薄”有界编释。两项差异完整保存，未为了采用候选而放宽标签或另换章节。

这说明根量条件仍不足以表达有效生化和位置接引。原文区分官、印、财在天干与地支的贴近、远隔、接引；也区分“有印”与“能生身”、“清”与“有气”。这些是后续机制建模需要解决的问题，不能把原典文字直接换成未检验的距离权重。

## 修复真正的审计漏项

全量审计原来只读取文档层`body_constraints`，没有读取命例内嵌`negative_constraints`。已登记的順局SJ05保留“非身弱论也”，却未进入完整回归的否定约束列表；此前个别研究另行核过这条约束，不能冒充全量审计已覆盖。

现在验证模块明确提取并检查内嵌禁止档位，不为它生成唯一强弱标签。完整361条重跑后，所有旧完整计算与旧17项声明逐项相等，新增SJ05一项确定失败。确定失败由4项增加到5项，另有1项不可比仍保持未知；三档分歧仍为原23项，不能把不同类型的失败相加成一个准确率。完整配对收据（本地数据：`validation/bazi-controller-root-load-v1/corpus-gate-reconciliation.json`）保留前后差量。

候选首轮开发审计也只守卫了另行声明的否定约束文件，却未实际评判其中两项。现利用原保存的361份完整结果补齐这两项判定（本地数据：`validation/bazi-controller-root-load-v1/constraints-closed-assessment.json`），不重新生成有利样本或修改原成绩。候选满足两项禁止条件，完整新单元的新增修正门槛仍失败，继续不采用。

## 验证与交付范围

最终12项冻结检查通过，覆盖完整旧例与原声明保持、所有新单元、采用失败不可提升、否定约束的非法输入拒绝和原始材料散列。首轮11项通过、1项失败，是检查器误用了完整审计器散列文件的命名规则；按其实际`.json.gz.sha256`路径读取后重跑，原数据与散列未变。格式和类型检查通过，完整快照、源码增量、首败及原书材料另见本地收据（本地数据：`validation/bazi-controller-root-load-v1/local-report.json`）。

本轮只修改验证模块和维护审计器，没有改共享计算、REST/MCP/CLI合同或公开强弱结果，没有新模型、代理、安装包或部署验收。六份新原典材料及其反例目前在本研究中单列，尚未宣称已进入公开索引；后续登记须连同有界编释表达一起完成，保留现有361条原对象和所有失败。
