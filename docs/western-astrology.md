# 西方占星的计算、原典与验证

[文档中心](README.md) · [API 参考](api-reference.md) · [算法状态](algorithm-status.md)

本命盘现在分别处理民用 UTC、行星运动的 TT 和地球自转的 UT1。昼夜宗派使用太阳中心的真实地平高度，整宫、象限和 MC 等宫制不能替代地平线。古典混合规则与有明确版本的原典子集分别返回。

七曜日运动沿用前向一 TT 日的五点采样，地心试算不消耗范围外的 UT1；恒星黄道盘按同一 TT 计算 Lahiri 偏移，其速度差分跨越 360°／0° 时按圆周展开，避免制造虚假高速或把逆行翻成顺行。名义宫位和地平仍要求有效 UT1。有限天文对照、同库算术控制、三端回执与尚未通过的 Lilly 印刷例题分别记录。

## 输入与天文精度

西占可选的`use_true_solar_time=true`出生钟面重置按记录时刻解析出的UT1调用均时差，名义出生和生时区间逐点重算共用同一实现。`person_info.true_solar.time_reference`交付记录UTC／TT、实际均时差UT1及未来闰秒假设；德国盘在`base_chart.person_info`下读取。重置与默认民用时间、明确LMT／LAT输入分别声明，不能用它推定未知钟时或认证历史精度。数值控制包含96个固定模型时刻，并分别核对完整盘面和三端回执。

内部日期采用Python的前推格里高利历。卜卦可用 `question_calendar`、择日可用 `candidate_calendar` 显式选择 `julian`，默认仍为 `proleptic_gregorian`；其他出生／分析接口仍按已公布的格里历合同处理。日期先转换，再按指定时区校验和转换钟时；不按1582年或地区自动改历。夏令时跳过钟时拒绝计算，重复钟时要求明确UTC偏移，不能暗选其中一次。同一物理时刻的TT、UT1和盘面位置保持一致。

`calendar_conversion` 保留原历法、原日期、原钟时及换算后的本地日期；`analysis_context.input_calendar/input_date` 同样保留原标签，`question_datetime/candidate_datetime` 为内部格里历本地钟时。儒略历1700年2月29日合法，换算为格里历3月11日；格里历同名闰日仍拒绝。输入年采用公元1月至12月编号，不推断英国旧式3月25日换年或双年份。转换超出Python公元1–9999年范围时明确拒绝。`date_label_jdn` 是日期标签的整数日编号，不能当成实际UTC／UT1／TT历元。原典钟时、地方平太阳时／视太阳时及地区改历仍须另核；可用[历史历法审计](../scripts/western/audit_western_civil_calendar.py)复核已选例题。

卜卦 `question_second`、择日 `candidate_second` 接收已确认的整秒 `0..59`，省略沿用 `0`。原秒数随历法转换、正午进位与所选钟时解析传到同一星盘时轴；`calendar_conversion.input_clock` 和 `clock_conversion.hour_origin_conversion.input_clock` 保留该分量。`clock_conversion.input_granularity=second` 描述支持的钟面分辨率，`input_clock_accuracy_certified=false` 仍不认证来源记录精度。与[Python datetime的普通钟面范围](https://docs.python.org/3.12/library/datetime.html)一致，不接收小数秒或直接输入的秒60；下述太阳时反解返回UTC闰秒是另一种输出情形。日期标签与现代UTC→TAI→TT参考分别按[SOFA时间尺度](https://www.iausofa.org/current-software)核对，不将钟面传递能力称作星历或预测精度提高。

卜卦的 `question_clock_basis`、择日的 `candidate_clock_basis` 可显式选择 `civil`、`local_mean_solar`、`local_apparent_solar`。默认 `civil` 沿用民用时区；`timezone_name` 省略／null时采用API默认 `+08:00`，回执标明 `legacy_api_default`，不能把它当成已确认地点时区。太阳时必须省略／null时区，避免重复修正。按 [USNO钟时定义](https://aa.usno.navy.mil/faq/eqtime)和[Swiss接口9.4节](https://www.astro.com/swisseph/swephprg.htm)，平太阳时为UT1加东经时差，视太阳时再加均时差（LAT−LMT）；后者按地心视太阳反解，未复原具体日晷的站心、折射或读数误差。原始JPL请求与响应、接口定义（本地 `tests/data/astro/source_materials/source-files.json`）作为来源资料保留，不作为新增观测样本。

日期规范化完成后再解析声明的钟时。`clock_conversion` 与公开 `clock_input` 字段卡分别保留原钟面、钟时口径、有效民用时区、UTC命名载体及实际TT／UT1；`question_datetime/candidate_datetime` 仍是规范化后的输入钟面，须连同 `analysis_context.input_clock_basis` 解释，太阳时的 `analysis_context.timezone=null`，内部载体时区在 `chart_timezone`。1960年前的UTC命名载体承载模型UT1，不能据名称宣称当时已有原子UTC。太阳时反解复用共享引擎，未改变普通现代输入的物理时刻；钟时数值残差不认证原始分钟记录的准确度。原书未说明的钟时保持未知，不能按上升点或结局拟合。

卜卦 `question_hour_origin`、择日 `candidate_hour_origin` 独立声明小时日起点：`midnight`（默认）按午夜计0–23，`noon` 的0为同日12:00、12–23为次日00:00–11:00。[Lilly1647第30–31页](https://iiif.wellcomecollection.org/image/b30338724_0065.jp2/full/2400,/0/default.jpg)的星历表按正午起算，午后第14小时对应次日02:00。AM／PM已经换成现代24小时钟面时沿用 `midnight`。日起点与民用／LMT／LAT分开声明，依已确认原页选择，不从年代、地区或ASC拟合推断，也不把制宫表坐标当作提问钟时。

太阳时反解落入UTC闰秒时，卜卦／择日保留原生TT／UT1继续计算，`converted_utc`可返回含`23:59:60`的标签。`clock_conversion.utc_representation`明确区分UTC标签、闰秒与Python datetime可表示性；不要截断、平滑、移秒或把显示限制说成星盘不可算。仍不推断原资料精度、实测EOP、完整原典或现实预测有效性。

`clock_conversion.hour_origin_conversion` 保留原历法日期、原小时标签、整数日进位和最终格里历钟面；进位完成后才验证最终日期范围，再处理时区／夏令时或太阳时。该操作是标签规范化，未计算实际持续时长或时区偏移。例如儒略历公元1年1月2日午后第12小时最终为格里历1年1月1日00:00；中间日期无法表示时，`calendar_conversion.normalized_local_datetime=null`、`normalized_date_representable=false`，原标签与日编号仍保留，最终钟面可以有效。不能据中间null否定已返回的最终钟面。1978年元旦UT1映射至UTC闰秒的历史失败仍保留；当前以原生时间尺度和扩展标签交付，不要求Python datetime表示该标签。

1972 年起，`TT = UTC + (TAI−UTC) + 32.184 秒`。偏移表固定自 [IERS Bulletin C 72](https://hpiers.obspm.fr/iers/bul/bulc/Leap_Second.dat)，包含来源指纹及有效期。到期以后的日期沿用最后已知闰秒，并返回 `chart_profile.future_leap_seconds_assumed_unchanged=true`。这是一项假设；未来闰秒并未被预测。1961–1971年使用[IERS历史UTC关系表](https://hpiers.obspm.fr/eoppc/bul/bulc/UTC-TAI.history)的分段偏移和日漂移，1960年使用已声明的SOFA关系；更早输入沿用Swiss Ephemeris的历史UT1／ΔT约定，仍非实测地球自转或原典钟时重建。

历史偏移的浮点值与精确TT点共用原表十进制计算；普通UTC有效域同时遵守负调整删除的日尾，不能把被删除标签继续送入星盘。反解先选择源内区间，再把微秒舍入限制在合法段内。正调整的分数插入秒不能用Python datetime表示；负调整处不超过3纳秒的源方程缝隙也保持未知。精确TT点、精确IEEE值和标量名义午夜是分别声明的输入语义，当前共用反解所有者。原54项浮点失败与原506点参考保留，修正后的源域参考另列，详见[分项验收](precision-acceptance.md)。

已加载历史UTC系数更新后，前向TT及反解使用同一组分段关系；缓存按实际生效日期、偏移、参考MJD、日漂移、终止日期与1972首偏移建立。更新范围以实际已加载资料为准。默认186标签与72交点逐字段保持，有限第三方复核及保留错误见[分项验收](precision-acceptance.md)。

已知UTC到TT的偏移不依赖UT1提供者。缺少原生星历库时，1960年起仍可得到TT，默认UT1明确沿用UTC近似，方法标为`frozen_UTC_offsets_to_TT_UTC_as_UT1_approximation`；更早时刻没有原子UTC偏移则继续未知TT。所选C04可独立按原表提供UT1，超出覆盖仍拒绝。盘面还须满足自身星历依赖，TT可算不代表所有工具都能离线运行。

节气的UTC标签、民用钟政策和TT搜索锚点复用共享原子钟转换，不因同年其他节气超出C04而拒绝显示。原子UTC可用时，`civil_time_policy`／`civil_time_method`只说明实际UTC到TT方法；更早输入仍按具名UT1／ΔT约定处理。日界、宫位和地平计算继续要求所选UT1覆盖，不缩短搜索窗或切换默认模型。相关源内插值与模型对照见[选定时标参考](../tests/data/guolao/selected_day_models_v1/README.md)。

行星使用 `swe.calc(TT)`，宫位和地平坐标默认使用 Swiss ΔT 模型反解的 UT1。卜卦／择日可显式选择下述 IERS20 C04 UT1；其他入口及未指定选项的默认路径仍使用模型。`chart_profile` 返回 `calendar/time_scale/julian_day_tt/julian_day_ut1/horizon_method/sect_convention`。实际星历文件模型仍看 `ephemeris_model`，不能只看是否安装了包。[Swiss Ephemeris 官方接口文档](https://www.astro.com/swisseph/swephprg.htm)区分这些时间尺度与 `azalt` 的真实／折射高度。

跨年代位置还依赖对应的`sepl`／`semo`分段。可用现有下载器按固定清单补齐公元1–9999年的34份日月／行星分段，再用`SE_EPHE_PATH`显式选择；这不包括小行星、EOP或未来钟时认证。覆盖与位置专项在同一133个TT时刻、266组日月参考中保留补全前的49项超线和184项不可计算；补全后主机与ARM Linux均符合原0.02角秒线，最大差异约0.00217角秒。参考与数据共享DE441谱系，不是独立动力学或全历元绝对精度证明。当前参考在日月覆盖向量（本地 `tests/data/astro/ephemeris_coverage/`）、TT事件（本地 `tests/data/astro/tt_events/`）及共同框架（本地 `tests/data/astro/tt_common_frame/`）；普通本命统一来源看`chart_profile.ephemeris_model`；`planetary_models`仅在混合／近似分支出现，详细物理来源也按入口条件交付，不能请求不存在于本次结果的条件字段。共享输入中的非默认`ephemeris_policy`目前只对印占开放。

独立安装版须核对实际发现的数据目录，不能用仓库中的历表替代安装验收。2026-10-25 的安装版对照中，补齐固定清单的34份分段后，相同266组参考由6组符合原判定线、76组超线、184组不可计算，变为266组符合。这是该次数据配置的结果，不代表其他安装已具备这些文件，也不增加独立天文样本或现实预测证据。

uv run --locked --extra dev python -m fatebridge.fetch_ephe --year-range 1 9999 --dest /tmp/fatebridge-western-ephe
uv run --locked --extra dev python -m scripts.western.audit_western_ephemeris_coverage --ephe-dir /tmp/fatebridge-western-ephe --output /tmp/western-coverage-audit.json

昼夜约定为地心太阳中心、无折射、真实高度 ≥0 为昼。行星的 `above_horizon` 也取实际地平高度，缺少高度时返回未知。行星时采用日出日落分段，有自己的视圆／折射口径；两者在地平附近不能当作同一定义。极区没有适用的象限宫位时仍报错，不悄悄替换宫制。

卜卦／择日的 `ut1_source=iers_c04` 使用固定版本的 IERS20 C04 最终每日合成值，覆盖 **1962-01-01 00:00 至 2026-09-19 00:00 UTC（含端点）**，共23,638日。来源经 Astropy 官方数据镜像固定提交获取，原始文件与派生包均有SHA-256；没有宣称本次从IERS服务器成功直取。`swiss_delta_t` 保持默认。日间查询先移除真实TAI−UTC（含1972年前漂移／调整），在TT上对连续UT1−TAI线性插值，闰秒不会当普通UTC秒插值。太阳时反解、恒星时与Lahiri选项沿用同一来源；没有外推、预测值或静默模型回退。覆盖外起盘返回错误；地心TT黄经事件搜索直接使用TT星历，不再因无关的试算UT1超范围而返回未知。宫位、地平与日出等仍要求对应UT1来源覆盖。这项可用性修复不提高外部位置核验成绩。

`clock_conversion.ut1_reference` 和 `calculation_basis.earth_rotation.ut1_reference` 返回名义历元的源日、日值、形式标准差和插值权重；公开 `ut1_input` 字段卡可整组读取。模型路径该引用为null。只应用UT1，**未应用极移、天极偏移和日内潮汐**；[IERS C04指南](https://hpiers.obspm.fr/eoppc/eop/eopc04_05/C04.guide.pdf)说明日值与完整地球定向的差别，指南版本为2009年的05C04，不能冒称本实现复现20C04的生产算法。形式标准差不是插值或瞬时物理误差界，数值守卫也不是外部精度认证。数据与参考转换可由[IERS几何参考生成器](../scripts/western/gen_western_iers_geometry_reference.py)复核，残留差异不因改用实测日值而自动消失。

## 离线轨道近似的来源与差距

旧36140项外部日速的实际生成器对Swiss位置作0.02日五点差分，**不是API直接返回速度**；此前将它写作“第三方返回速度”的说明在此更正，原数值、输入及门槛不变。事先固定的1280个新现代日速则确实来自`FLG_SWIEPH|FLG_SPEED`，二者分别记录。

当前完整TT导数阶段实际重跑全部原40380位置、36140现代日速，以及事先固定的2560个新位置留出、1280个新现代日速，均符合原外部门槛。原月球208项位置失败全部修复；十体最大位置分量差约0.008255角秒（金星），月球约0.002907角秒。原完整月球扩展队列4806位置、4126现代日速也全过原线，旧332位置失败修复；分母分别保留，不能合并成一个准确率。

另以实际`FLG_SWIEPH|FLG_SPEED`返回值补查全部原40380项及既有2560项留出，均符合事先沿用的1角秒／参数日线；原现代36140项、原广域4240项及留出分别记录，最大差约0.274409、0.263964、0.260905角秒／日。该补查在改造后进行，不称为新盲测。原土星点与API速度差约0.000373角秒／日，不能与旧0.02日模板的0.407150混写。对原生月球最大差点，完整参数曲线与冻结发射延迟的独立隔离相差约0.274837角秒／日；冻结延迟结果与API相差约0.000428。原生细模板及冷／热调用探针全部保留；此证据定位时刻敏感度，不认证整个原生二进制函数或其物理精度。

## 太阳圆面内的位置模型

`chart_profile.apparent_position_policy`、原生推运盘的 `calculation_basis.apparent_position_policy` 和事件历史同名字段，说明标称历元的太阳偏折模型。公开 `solar_position_model` 字段卡可读取这一层。它按未偏折有限视线区分太阳后方、太阳前方、圆面外及边界疑义；未核对版本或不支持的后端保留 `not_evaluated`。月亮、太阳自身和虚点不在此几何覆盖范围内。

[Swiss 官方文档附录 A](https://www.astro.com/swisseph/swisseph.htm)说明：太阳后方不可见天体的位置，采用透明太阳质量分布作连续延拓。`virtual_continuous_solar_disc_extension` 表示这种约定；前景凌日不能据投影重合误报成位于太阳后方。这不是光学遮掩、太阳边缘接触或实际可见性求解，`maximum_physical_error_arcseconds=null` 也不是零误差。

固定291个天体／历元的新增 JPL 开发对照中，65组背景延拓与 JPL 视位置存在明显差异；关闭偏折可诊断这层差异，却会破坏圆面外的对照。因此默认坐标保持原样，原0.02角秒比较仍记失败，不能靠切换约定过线。来源与固定队列见[太阳圆面参考生成器](../scripts/western/gen_western_solar_disc_reference.py)。

### 朔望与行星时

出生前朔望现在在 TT 上对日月视黄经差的0°／180°交点括界求解，选取严格早于出生 TT 的最近一次。事件以跨越后首个可表示 JD 记录；出生 TT 恰好等于该事件 JD 时，选前一次朔望。`classical.syzygy` 保留 `julian_day_tt/julian_day_ut1/event_datetime_utc/solver`，旧 `julian_day` 明确为 UT1。新月取太阳经度，满月取月亮经度；恒星黄道使用朔望事件历元的原生 Lahiri 坐标，不能将回归黄经直接写入恒星盘。事件小数位数是数值表达，不是外部观测精度。

`classical.syzygy.ephemeris_source`另行记录整个朔望搜索和恒星黄道显示实际使用的模型、样本上下文与文件身份。`models_stable=false`表示其中发生模型切换；不能把出生历元的Swiss来源概括为整个搜索的来源。支持的降级结果保留并披露，不通过删除它们伪造一致；回执不认证跨来源函数的连续性或事件绝对精度。原生坐标框架、视位置约定、有限值、请求日速及文件完整性出现矛盾时返回来源错误，不能把错误吞成“未提供朔望”后继续评分。

`classical.syzygy.utc_representation`把日期显示与朔望计算分开。公元1年初的出生前朔望可落在天文年0（纪元前1年）；现在保留原有TT／UT1、经度、来源及其参与总主星的计算，`event_datetime_utc`可使用扩展纪年标签，并返回`datetime_representable=false`，不因Python日期范围而删除整项朔望。该字符串是标签，不能无条件交给`datetime.fromisoformat`。闰秒和历史非唯一UTC表示也复用共享标签机制；1960年前的UTC命名载体仍是模型UT1，不能声称当时已有原子UTC。公开出生输入范围仍为公元1–9999年，数值格式不认证历史钟时或天文绝对精度。

行星时从实际相邻日出／日落建立昼夜弧，各等分12段，以左闭右开区间分配小时。原先固定向前减24小时，会在日出逐日提前时选到更早一天的日出；2026年4月15日格林尼治日出后1秒曾因此被标为火星日昼第8时，修复后为水星日昼第1时。日主读取开启该行星日的日出在用户时区中的民用星期；UT1先转TT，再按冻结UTC政策转民用时间，不能把UT1日历字段直接当UTC。

保留的行星时日出口径为海平面、1013.25 hPa、0°C、含折射的太阳中心。它与[通常年历采用的太阳上边缘日出](https://aa.usno.navy.mil/faq/RST_defs)有差别，也不能代替本命宗派的地心真高度判据。`planetary_hours.sunrise_convention`、弧与小时的UTC起止时间、UT1弧端点均返回。极区缺少相邻适用事件或转换失败时返回未知，不夹限到第1／12时，也不伪造日出。

小时主星顺序与24时跨日递推的限定原典依据为[Cassius Dio《Roman History》37.19，Loeb 1914](https://penelope.uchicago.edu/Thayer/E/Roman/Texts/Cassius_Dio/37%2A.html#19)。该段并未指定现代折射或不等时几何；`source_scope` 明确分开这些实施政策，手工标注仍待独立校勘。

朔望与行星时审计使用[美国海军天文台2026年月相表](https://aa.usno.navy.mil/calculated/moon/phases?year=2026)的全部25次新月／满月作独立分钟级对照，固定容差60秒；按其[UT定义](https://aa.usno.navy.mil/faq/UT)比较UT1。日出前后检查属于声明口径的行为回归，尚未获得独立日出几何或现场天气验证。

## 推运、返照与主限坐标

界推运沿既定埃及界表推进时，现在保留原始黄经的精确有理弧及半开区间，再转换显示年龄；参加星体也用同一弧区间归属。旧累计浮点与 `1e-9` 跳步会把普通盘的界段漏掉：2001-05-22 02:08 UTC、0°E／40°N的上升约3.038038°，约16.962—26.962岁的火星、土星两段曾被重复标成水星。修复不改界表、时间钥或来源选择；独立100位Decimal全局区间交集与两种时间钥的三端回归见 `tests/western/test_western_distribution_partition.py`。精确算术保留输入已有区别，不增加观测或原典精度。


推运底座现在直接使用 `fatebridge_swisseph_native`，与本命盘共用 TT／UT1 政策，保留内部完整黄经、小数秒及用户输入的纬度。`natal_reference.calculation_basis`、行运／次限／返照的 `calculation_basis` 返回星历模型、时间尺度、TT／UT1、未来闰秒假设和黄道偏移。恒星黄道采用明确的 Lahiri 偏移，整宫宫头按该黄道的星座边界确定；不沿用第三方库的默认偏移或极区纬度夹限。

太阳和月亮返照求解 TT 黄经的有括界零点，取TT标量上不晚于分析TT点的最近一次。未找到括界就报错，不能补一个未来TT交点。`solver` 返回目标与求解黄经、残差及 `event_not_after_analysis`；`return_datetime_utc` 与带原时区偏移的 `return_datetime` 都保留秒以下数值。这些位数表示求解器的数值精度，实际误差仍受星历、输入和未来时间尺度假设限制。

返照角差先相减再直接求余，避免先加180°把非零小角差舍为零；精确对分仍沿用原 `[-180,180)` 约定。`event_not_after_analysis` 按求解器的双精度TT标量比较。TT标量与民用钟标签不是无损往返：现在最终盘直接使用求得TT；若它恰等于分析TT，则沿用该点已知的分析民用输入作为显示见证，避免反解标签晚于原输入。该见证不证明双精度TT能区分同一舍入格内的精确UTC先后，秒以下格式也不证明物理钟时准确度。

### 返照根与行运分档

返照搜索、本命目标和最终盘复用同一原生位置所有者、原生标志及热带／Lahiri黄道。旧搜索直接调用另一组Swiss标志，1990-04-06 01:33 UTC和2024-03-20 06:30 UTC的同出生时刻控制曾因一个浮点末位差退到前一年。修复统一坐标路径，不加“接近即命中”的误差容限。求得TT通过共享物理历元载体进入最终盘，UTC标签不再作为位置重算操作数；插入秒的有效`:60`标签和无法表示的本地标签分别保留。

行运使用目标地点的地心原生盘，展示十个物理天体及ASC／MC与本命参照的五种相位。`house_emphasis`统计行运盘自身十个非轴天体的已定义宫位，不是行运星落入本命宫的叠盘。普通命中在实际`orb_limit`内排序后取前24项；`exact_hits`是`min(orb_limit,0.3)`度内的紧密相位展示档，取前12项，不等同数学零度精确或成功概率。两个档位都由原始角度判定，不能先把角差交付成浮点再重新分类；`exact_orb_limit`声明实际采用的紧密阈值。

独立FLINT3.6.0／python-flint0.9.0固定210组二进制角度输入及原阈值语义，保留旧交付浮点过滤的一处边界差异。出生时刻控制、已解TT载体及原有解析源测试见[返照检查](../tests/western/test_western_return_residual.py)，角度资格见[固定参考](../tests/fixtures/transit-exact-orb-reference.json)。这些控制验证数值、时刻和坐标传递，不建立符号推运的现实有效性；独立NASA物理事件对照和完整原典资格另行验收。

[Horizons说明](https://ssd.jpl.nasa.gov/horizons/manual.html)将第31项定义为地心视黄经／黄纬的IAU76/80日期黄道，并区分TT及UT标签。新增本地封存的18个TT返照控制覆盖1800—2400年，沿用太阳120秒、月亮15秒门槛；Moshier和文件模式均通过，所选太阳最大时刻差分别约7.65秒、7.78秒，月亮约2.62秒、0.66秒。不能由这批结果宣称所有年代、不同黄道／EOP口径或某一后端的误差单调更小。

地点盘还须核对`calculation_basis.earth_rotation`。当前声明在所选J2000前后两世纪窗口采用[IERS 2010表5.2e](https://iers-conventions.obspm.fr/content/chapter5/additional_info/tab5.2e.txt)标准旋转及Swiss章动，外侧保留原生长期变化并在窗口边界作常数相位衔接。原生Astrolog比较保留324次调用中的24处原2角秒门槛超限，不能抹成同口径通过。补充的独立ERFA旋转加同库投影参考中，288组窗口内轴点对满足事先另定的0.001角秒门槛，36组外侧仅核对声明的相位政策；这不是独立完整宫头、远期物理地球自转或导数连续性认证。相关比较不改变现行旋转模型或原门槛，也不授予预测SOTA结论。

通用太阳弧的太阳差及各因素旋转保留给定坐标的精确有理数，直至分座与相位门槛判断；交付浮点坐标时沿用共享的同侧分区表示。原推进时间钥、正负弧的模360方向、1.5°相位线、四位弧显示和八条命中显示上限保留。这修复边界分类与假命中，不增加星历物理精度。

推运与返照的星体交付直接读取原生底盘的坐标、落宫和逆行事实；缺失坐标不能填成0°。昼夜盘复用同次底盘的太阳地平判定。宫制无定义按输入错误报告，星历来源错误保留其来源代码。埃及界按星座内给定角度的半开区间归属，越界或非有限角度直接拒绝。

多重回归只消费本命黄经与物理试算时刻，不预先构造宫位；高纬度地点的Placidus宫位无定义不会阻断黄经求根。

土星、木星和平均月交点的多重回归，从参考时刻向两侧连续扫描，以不超过1个TT日的步长括界细化，分别找到所需的最近过去／未来根即停止；各侧保护界为1.5个平均周期加5个TT日。不能只在平均周期种子附近取一个根：木星逆行可使同一黄经在数月内三次经过，旧路径曾把2002年4月的下一次回归跳到2013年。现在不会按整日去重而合并不同根；扫描末端不足整步时也核对最后小段。观察到原生日速变号的日格会局部分成两段，分别用实际黄经验证括根，避免同格中的两次经过相互抵消；细化期间的实际模型与原生文件上下文必须保持一致。原生日速只是转折候选的定位依据，未认证为完整视位置导数。

例如2001-01-25 03:00 UTC的木星本命黄经，在当日14:15:48附近再次经过；旧日格扫描将两根一起漏掉并返回2000年7月的旧根。隔离的Skyfield1.54／DE421以独立实际视黄经作1001点扫描，再二分得第二根14:15:53.098888，两者相差约4.963秒，符合事先固定的30秒线。这是已暴露开发个案，不是盲测或全部年代的独立物理认证。回归见 `tests/western/test_western_return_station.py`；未观察到的多重转折、停滞擦触和数值分辨率以下结构仍未证明穷尽。

多重回归的 `zodiac_type=Sidereal` 现在从本命到试算根都使用原生 Lahiri 黄经，遵循 [Swiss 接口5.8／12.1节](https://www.astro.com/swisseph/swephprg.htm)的 `SEFLG_SIDEREAL` 和 `SE_SIDM_LAHIRI`；默认 `Tropic` 保持回归黄道。原生同库残差检查和2001／2002木星三次过境回归见 `tests/western/test_western_extra_return_order.py`，不是独立动力学精度或现实预测证据。

恒星次限 `astro_vedicprog` 的本命参照与推运位置现在都直接取共享原生Lahiri底盘，不再把热带本命参照配上恒星推运位置，也不在原生偏移失败时使用线性近似后返回成功。赤纬次限 `astro_jaynesprog` 在原UTC瞬间经共享时间策略取得TT后计算赤纬，不把UTC钟面JD误作UT1调用。1972／1990／2024三个时刻的同库坐标控制与两工具三端核对见 `tests/western/test_western_progression_frames.py`；这验证时间与坐标传递，不提高外部星历物理精度或符号推运的现实效度。

主限的赤道投影现在使用 TT 星体坐标和 UT1 恒星时，MC 保留真实赤纬；半弧方法的 ASC／MC 使用实际赤纬和半弧。两种投影都测试零推进量还原原盘，恒星黄道在投影前后显式转换。半弧方法遇到恒显／恒隐点时拒绝无定义投影，不用任意极小分母制造坐标。现有 `axis_static_key` 与 `mundane_semiarc_static_key` 仍是带明确近似标签的方法；数值修复不等于完整复现某部原典的主限体系。

主限后续几何、容许度、时点分类和法盘共用未舍入的推进弧与坐标；`0.01`年窗口比较原始相对岁数。此前先取四位小数再运算，固定14个Ptolemy热带黄道场景中有4个过去／未来时点被错标当前、45个容许度超过半个末位单位、154个法盘经度未满足原算术线。以实际Swiss坐标及独立有理数操作数对照，修复后同一队列均通过，最大法盘经度算术差约`5.7e-14°`。这只核对已声明静态模型的算术，不是物理精度、完整主限原典或事件预测认证；原始失败和门槛保留。事件日期文字仍显示到秒，未舍入岁数与推进弧继续供计算使用。

### 法达年长、时间基准与来源分歧

`firdaria` 与综合时运中的法达共用领域计算，并始终声明实际 `calculation_options`。固定年采用UTC名义经过时长，公历周年采用原始出生生日边界，主运内子限均按UTC等分；两种夜盘交点顺序独立选择。

## 数值边界与显示

南交点保留北交点加180°的精确派生关系，再判断分座与宫位。普通宫头仍用半开区间；折返宫头的R／T投影把同一精确关系传入已有高精度几何，不改投影方法、相位偏移或精度上限。公开经度仍为浮点显示值，精确派生比值另记在投影检查中；C只扩展内部精确输入兼容，极点原有限制保留。回归见[对点分区](../tests/western/test_western_antipodes.py)和[对点归宫](../tests/western/test_western_antipode_houses.py)。这些检查不提高原星历坐标的物理精度。

旧27等分宿辅助函数用浮点近似的13⅓°作整除，40°、80°等精确边界曾落入前一宿，导致印度盘通用顶层与 `india` 专业层不一致。现在27等分及旧28等分示意层均按原黄经的精确有理值分类；`legacy_equal28` 的宿名和 `su28_degree` 也从同一未舍入黄经计算，再保留原有4位 `lon` 显示。90°整点的斗宿内度为0；两侧坐标即使同显90°，归宿仍可不同。全部宿界与相邻float、两个印度入口及旧宿占分支的三端控制回归见[等分宿界测试](../tests/astronomy/test_equal_lunar_sectors.py)。所修的是既有等分算法，果老研究盘具名不等距赤经宿界保持独立；现代不等宽宿度仍可超过30°，不把等分示意覆盖到未分配的现代点。

本命、关系盘和推运的数值坐标保留计算精度，星座、宫位、相位及古典条件均使用未舍入值。四位小数舍入曾让白羊末度同时显示为黄经30°、星座内30°，并让刚超过8°容许度的相位进入结果。现在坐标满足黄经 `[0,360)`、星座内度数 `[0,30)`；`chart_profile.aspect_policy` 集中交代现代容许度政策；`aspect_evidence` 保留逐项的 `separation/exact_angle/orb/orb_limit/rule_id`，可直接核算。常规 `aspects` 仍给出完整命中列表与未舍入的偏离度，首轮摘要无需重复每条的政策元数据。公开模型拒绝不可能的坐标。

导出中的“星座＋度数”统一为星座内度数。例如绝对黄经75.123°显示为“双子15.12°”；末度接近边界时显示29.99…°，保留所在星座。JSON保留数值精度，文本位数不表示观测精度。

边界、原典配对和解释反事实的可复现审计与测试见 `tests/western/test_western_semantic_fidelity.py`。这是限定条件的自动检查，不给自由文本或整个专业系统自评满分。

当前数值检查分别核对独立天文资料、给定坐标的精确算术和公开端口的字段一致性。完整输出相等不能替代 NASA／香港天文台等独立资料的误差检验；各主题下列出当前可运行的审计命令及其范围。

## 关系盘的时间、空间与方法

`relationship_focus` 选择婚姻、恋爱或通用侧重，保留 `marry/结婚`、`romantic/dating/love/戀愛` 等已有别名、大小写和首尾空白兼容；省略或空白为通用。未知的非空值返回输入错误，不能把拼写错误说成“未指定关系取向”并省去对应过滤。嵌套 REST 和扁平 MCP／CLI 共用该归一化。

关系盘的双方基础盘及 Davison／Marks 实盘，直接复用相同宫制、黄道和时刻的本命盘结果，保留原生 Lahiri 坐标、含纬度的宫位计算及 TT／UT1 依据。影响图盘另声明为将源星体黄经放入对方宫头扇区的符号叠盘，不冒充同一时刻的地平重算。

`davison_variant` 在嵌套 REST 与扁平 MCP／CLI 输入中使用同名参数；只对 `TimeSpace` 和 `Marks` 有效，其他模式不会静默接受非默认变体。方法依据为[Astrodienst 的 Davison 变体说明](https://www.astro.com/cgi/h.cgi?f=gch&h=gch64&lang=e)：

| 参数值 | 时间 | 地点 |
| --- | --- | --- |
| `uncorrected`，默认 | 两出生时刻的模型 UT1 JD 算术平均 | 纬度平均、经度先按短弧展开再平均 |
| `corrected` | 从未校正中点附近括界求解，使回归黄道 MC 对齐双方 MC 的中点子午轴 | 同未校正地点 |
| `spherical` | 同未校正时间 | 球面最短大圆距离中点，非 WGS84 椭球中点 |

例如179°E与179°W的经度中点在日期线，不能算成0°。经度展开、模型UT1平均和小数秒政策是明确的实施约定；来源只描述平均出生时间，未规定原子时间细节，本实现不宣称与 Davison 原书逐字校勘。MC校正按[Astrodienst FAQ 的“子午轴”口径](https://www.astro.com/faq/fq_fh_round_f.htm?lang=e&nho2=2&nhor=2)选择接近原中点的方向，保留目标、实际MC、校正秒数与残差；未直接改写MC坐标。参考地点重定位变体尚未接入。

组合盘采用[Astrodienst 的对应中点法](https://www.astro.com/faq/fq_fh_compo_e.htm)，星体、ASC、MC及适用宫头分别取短弧中点，不自动把水星／金星移到相反方向。它没有真实出生时刻或出生地点，`positions_from_single_instant=false`；符号纬度平均亦明确标记。精确相隔180°的两点没有唯一短弧中点：组合盘报告歧义；比较盘的中点目录保留两个未决候选，交换输入不会随意选另一端。相位和中点命中使用未舍入数值，`relative_midpoint_policy` 与逐项 `aspect_evidence` 可核查。

`Marks` 分别计算“甲与双方Davison资料的Davison”和“乙与双方Davison资料的Davison”，以 `marks_charts.inner/outer` 返回；`chart` 为内方个人盘，`primary_chart_role=inner`。计算配方来自[Bob Marks 作者课文镜像](https://astroer.com/htmls/bob/bobmar/markschart28.0.htm)；原站返回404、镜像尚未与原始存档校勘。作者的个案成功陈述未被采纳为有效性证据。公开 `marks` 字段卡保留双方的 `marks_charts`，安全联合视图亦保留此根；非Marks模式为空对象。`chart` 不能被当成共同盘或复制给外方；字段卡主层为 `marks_chart_pair`。

各模式共用两张本命盘的七曜与跨盘相位计分，`compatibility_evidence.source_paths` 指向同次返回的本命资料与相位表。关系分数的 `compatibility_policy` 交代七曜元素／模式重叠、相位加减及三项平均，是 FateBridge 自定义启发式，未作经验校准。v2 按未舍入容许度选择最紧密24条，并保留第24条处的全部精确并列项，因此入选数可能超过24；名称或甲乙顺序不再决定舍弃哪条。只差一个浮点步长也不是并列，不设人为 epsilon。元素／模式分先舍入，再与截断到0–100的相位分取平均；均为最近整数、半数取偶。`compatibility_evidence` 保留人数分布、重叠计数、分母、入选相位在同次 `synastry_aspects` 中的索引、逐项±4、截断前后分数及平均过程；空相位的50是规则基线，不是观察到的关系质量。投影入选明细时选择整个 `selected_contacts` 数组。

合成角度控制中，交换甲乙双方的分数均为63；独立边界、并列和顺序检查见[关系计分审计](../scripts/western/audit_western_relationship_scoring.py)。计算对称性不校准评分的专业解释。24条名额、所有合相一律加分及等权平均仍是粗略产品约定，尚无原典或经验依据认证。文本导出列出“自定义评分依据”；其中长数组沿用通用摘要上限并显示省略提示，逐项复算应读取同次完整JSON。

原典关系判断的缺口也需单独保留：[Ptolemy《Tetrabiblos》IV.7，Robbins 1940](https://penelope.uchicago.edu/Thayer/E/Roman/Texts/Ptolemy/Tetrabiblos/4B%2A.html#7)优先考察双方日、月、上升和福点的星座关系，并继续考察位置高低与其他行星的见证；它没有给出此处的七曜百分制。当前自定义评分尚未实现该章完整判断链，不能称为该章的实现，也不能将其综合分解释成关系成败概率。

## 宫位与四轴的独立核验

2026-11-09复查发现：[官方接口](https://www.astro.com/swisseph/swephprg.htm)的A/E同义等宫入口没有同时进入高纬宫头修正。公开Western选择规范化为A，但共享精度层原来只处理E，造成已修正的ASC与原宫头相反。在既有独立100位向量参考的216个public输入中，A有67组宫头超过原1角秒线，最大相差180°，E没有超差。修复在共享宫位层补齐A，沿用同一个东方交点和等宫旋转公式，没有改参考或门槛。修复后216输入×A/E×热带/恒星两框架共864组零超差；原失败另存仓库外。扩展的完整高纬回归3219项通过，A/E/equal三种公开选择在两框架下的REST、原生MCP、CLI六组检查通过，当前连接MCP另以原失败输入验证了宫头和太阳落宫。此处验证的是给定binary64角度模型的几何及交付，不独立认证时标、实测EOP、绝对天文精度或预测效力。

`equal_mc`（Swiss `D`）的标准名称是“天顶为第10宫宫头的等宫制”；[官方接口定义](https://www.astro.com/swisseph/swephprg.htm)明确规定第10宫宫头为MC，误称为第10宫中点的名称不予接受。等宫头从原始锚点一次旋转，避免先算MC+90°、再旋转回第10宫造成二次舍入；落在浮点边界时保留精确输入和整周旋转所确定的星座分区。这不增加出生资料的精度或天文信息。

独立采集协议（本地数据：`../tests/fixtures/western-houses-protocol.json`）先固定1角秒容差，再用 PyERFA 2.0.1.5／NumPy 2.5.4 的 IAU 2006/2000A 恒星时、真黄赤交角及向量平面交线求ASC和上子午线MC；另外编译 Astrolog 8.00 固定提交的独立宫位算法，禁用其 Swiss／Placalc 后端。保留1900–2099年、七种纬度、三种经度的126个天球几何输入以及每个输入的13种宫制输出。TT／模型UT1由 FateBridge 作为共同输入提供，故本研究独立检查几何与旋转，不独立验证历法、时间尺度或实测EOP。

修复前审计保留原始失败证据：ASC／上子午线交点84/126组满足固定容差；13宫制共1638组中1068组满足容差、72组方法无定义、498组存在差异。旋转基准修复后的完整审计为126/126组轴满足同一容差，宫头1488组满足、72组无定义、78组仍有差异。全部样本及预先固定的阈值均保留；完整审计仍返回非零。无定义和 Astrolog 的替代宫制不计为数值通过，剩余差异涉及其十次固定迭代的 Placidus、极区宫头和MC分支，尚不能全部归因于某一实现。

修复前最大ASC差约74.50角秒，上子午线MC约1.98角秒。[Swiss 2.10.03源码](https://github.com/aloistr/swisseph/blob/v2.10.03/swephlib.c)及[官方说明6.1节](https://www.astro.com/swisseph/swisseph.htm)表明原生恒星时在1850／2050年转换长期表达式。原显式 [IERS Table 5.2e](https://iers-conventions.obspm.fr/content/chapter5/additional_info/tab5.2e.txt)内核仍保留作独立共同输入算术控制。当前自转适配使用实际Swiss默认章动、Vondrak岁差和原生偏置组成的同一NPB矩阵，按[IERS第5章](https://iers-conventions.obspm.fr/content/chapter5/icc5.pdf)和[ERFA gst06](https://github.com/liberfa/erfa/blob/v2.0.1/src/gst06.c)的S06与原点差取得GAST，保留精确有理ERA和最终角度归一。在J2000前后两个儒略世纪统一采用这一组合，不再跳过1850–2050；外侧保留Swiss长期变化并在相应边界作常量相位对齐。窗口位置及对齐常量为FateBridge策略，不能说成IERS规定的精度保证；远古／远未来绝对精度和导数连续性尚未认证。

## 年小限与月段边界

`profection`、`givenyear` 与综合推运共用年小限计算。周年在出生时区内从原始出生月日重建：2 月 29 日在平年按 2 月 28 日，在下一闰年恢复 2 月 29 日。生成周年采用[Temporal的compatible规则](https://tc39.es/proposal-temporal/docs/timezone.html)：回拨取较早时刻，跳时向前移过缺口。归属在UTC上比较，并保留名义周年年序；例如Kiritimati被跳过的1994-12-31周年移至1995-01-01，下一周年仍从原生日构建为1995-12-31。出生和分析输入的钟时仍须明确有效，生成规则不推定未知记录。法达公历周年继续执行其已声明的严格拒绝政策。

月段采用 FateBridge 声明的周年区间十二等分约定：先按 UTC 经过时长分段，再转换为本地时区展示。每个边界直接从完整年区间计算，活动月段采用左闭右开区间，年小限的月序使用同一组可表示边界。`profection`返回整岁、年界与实际选项；`givenyear.year_start/year_end`及首尾月段采用同一区间，`return_timezone`只转换这些瞬间的展示。这里的指定年盘是在分析时刻起盘，并附年小限、月段和本命相位，不是太阳返照零点。此约定不认证全部古典月小限方法、出生记录精度或现实事件应期。[固定独立参考](../tests/fixtures/predictive-time-reference.json)与[实际消费测试](../tests/western/test_western_timing.py)保留回拨、跳时、闰日、历史秒偏移和跨日期线案例。

## 周年与次限的具名时间模型

年小限的整岁模12、从本命上升座推进及取传统守护星与[Skyscript术语条目](https://www.skyscript.co.uk/glossary/profections/)所述基础方法对应。Valens另有多起点、传递与不同月／日分法；当前UTC周年十二等分是明确的软件约定，不能将一张周期表当成全部原典程序。

二次推运采用[Astrolog 8.00文档](https://www.astrolog.org/ftp/astrolog.htm)的365.24219日固定年键：从出生UTC起，每个该名义年推进一天；它不是逐年实测的太阳回归长度。时间换算使用精确十进制有理数，最终一次取最近微秒，半格取偶数。旧365.2425日键与其浮点舍入反例分别保留；默认键修订和算术修复是两项变化。`calculation_options`给出精确年键分子／分母、时间基准、舍入及quotidian轴宫口径。按推运瞬间在本命地点重算的轴宫与Naibod轴、MC太阳弧等方法不同。

## 相位边界与瞬时入出相

本命、关系相位、映点、关系中点和共享推运相位，现按输入浮点数的精确值完成圆周差、派生中点、容许度比较与排序，再转换成公开小数。所有既有容许度保持不变，也不加模糊的数值宽限。这里保存输入已有的区别，并未增加出生资料或天文观测精度；[Python数值说明](https://docs.python.org/3/library/fractions.html)也明确区分浮点数的精确值与使用者原本想输入的十进制数。

例如水星 `0.5000000000000001°`、土星 `352.5°` 的最短黄经差略大于8°，旧算法在相减／跨周界时舍入为8°，误收为合相；修复后排除。原始失败保持原样，由独立十进制审计另记解决情况。关系中点与映点的后续比较保留精确中间量，避免先显示再归类；线性黄经算式转回浮点时保持在原来的半开星座区间内。该例是合成边界输入，不是已观测的天象或预测命中。

旧入出相算法推进0.05天（72分钟）再比较，可能跨过精确成相点而反向分类。例如黄经0°、速度13°／天的天体正接近位于0.1°的静止目标，当前仍在入相，旧算法却判为出相。现在依据当前黄经差与有符号相对速度判定，`classical_patterns.aspect_motion` 分列 `applying`、`separating`、`exact`、`stationary`（相对黄经同速）及 `unavailable`；精确、同速与未知速度不再当作出相。距离与速度依据、方法及边界保存在 `application_policy`，正文与导出同时列出状态。独立卜卦引擎也已同步采用该判定，并取消黄经／速度先舍入的路径。

[Robbins 1940 I.24](https://penelope.uchicago.edu/Thayer/E/Roman/Texts/Ptolemy/Tetrabiblos/1B%2A.html#24)的接近／离开概念是此处明确限定的参考；该章还区分合相的黄纬条件、相位射线及其他效力条件。`ptolemy_latitude_condition` 现单列合相黄纬同侧／异侧／缺项；相位射线标为无需该项。使用共享闭半球约定，位于黄道上的天体可与任一侧共享半球，此零点约定明确保留。判定直接比较符号，避免极小异号纬度相乘下溢成零；未知纬度不补零。此条件不改变现代黄经相位列表，也不独自建立完整的托勒密入相；未来成相、停滞反转及全部效力条件仍待验收。结构化状态经过本地 REST、原生 MCP、CLI 的完整输出与严格投影核对；实际模型的自由解释仍需单独检验。

## 卜卦月亮事件与Lilly条件

卜卦从明确提问时刻起盘。`horary.moon.motion_basis` 使用与起盘相同的TT、地心视黄经、黄道与星历配置，搜索月亮下一星座界前严格未来的主相位。每30分钟扫描后，按黄经差给根定界并二分到相邻可表示JD；保留实际事件黄经、TT、UTC、根区间和物理星历来源。该步长不是事件时刻精度，原生模型也不是观测精度认证。月亮与各目标的相对运动必须满足所声明的顺行／单调条件；7天只是搜索保护界，失败返回未知。事件根区间与入宫根区间重叠时，也保留边界未决，不强行判为没有相位。

旧算法只查看当前容许度内的入相，并用相位距离代替月亮将行经的度数。因此会漏掉当前容许度外、出宫前能成的相位，也会把移动目标导致出宫后才能成的相位收进去，还可能按距离错排时间。生产调用现用实际星历逐次求根；仅供直接几何研究的恒速投影另有方法名，不用来冒充原生搜索。

原生Lahiri起盘、日月返照搜索与月亮事件共用严格的原生岁差偏移：运行失败、非有限值或失败标志均不能改成线性近似后宣称成功。返照在同一 TT 直接计算偏移，不先反解 UT1 再调用可降级的旧入口。起盘或返照失败返回错误；只有事件搜索失败时返回未知，也不把它当成空亡。已选择星历的数据一致性错误仍按原错误类型传递。遗留近似调用的显式回退另保留，不能给原生路径背书。

预先固定的协议（本地数据：`../tests/fixtures/western-horary-motion-protocol.json`）选择三个TT窗口、四天长度与10分钟JPL网格。独立采集器不导入生产代码，先由[JPL observer表的TT与视黄经](https://ssd-api.jpl.nasa.gov/doc/horizons.html)建立事件参考，再比较原生二分解。核验保留12,117组位置、全部事件顺序与时刻残差；原定位置容差2角秒、时刻容差30秒均未修改。该有限窗口不能认证其他历元、全部空亡流派或完整卜卦判断。

所选 [Lilly 1647原书](https://wellcomecollection.org/works/s7z7c46y)第112页以离开前星、在本星座内是否继续应用来谈空亡。此处工程查询为“严格未来黄经成相是否早于下一星座界”，`apply`、`forthwith`、历史容许度及此前分离背景的文本条件尚未全部验收，不能把两者视为唯一等价定义。无出宫前相位，也不直接证明现实事情不成。

原书图像及人工标注（本地数据：`../tests/fixtures/western-lilly-motion-1647.json`）分别记录第111页的传光定义、第125–126页的成事判断。第111页例子为白羊土星20°、火星15°、水星16°：水星把火星的光传给土星，两端本来就有合相，故不能加上“两端必须无相位”的限制。传统轻重次序也不等于某一瞬间速度排名；停滞的月亮不会因此变成比土星更重的聚光星。共享格局现核对这两点，并通过 `light_configuration_policy` 标明仍是结构候选。

第126页另外涉及接纳、遇到其他星之前的真实顺序及其他成事条件；不能拿当前入出相替代。`horary.perfection.candidate` 保留已算的结构，`perfects=null` 表示成事路径尚未核完，两造同主星也不自动构成独立成事证明。当前完整判词为 `uncertain` 并列缺项；旧代理规则的 `heuristic_verdict` 仅留作明确标注的研究对比，严格 `motion_conditions` 视图不读取它。这是保留待完成的实际方法缺口，不是将“所有条件均未知”认作原典验收通过。

## 黄道释放的起期、角宫参照与经过日

`zr.calculation_basis` 标明当前采用 Chris Brennan／Leisa Schaim 的[2019年第192期公开讲解](https://theastrologypodcast.com/2019/02/11/zodiacal-releasing-an-ancient-timing-technique/)，规则版本为 `brennan_schaim_zodiacal_releasing_2019_v1`。该页的计算、峰期与角宫三联段落分别说明360日年、30日月、下层除12；精神点与福点同座时，从下一星座开始精神点释放；所有释放轨的角宫参照均为本命福点。精神点与福点不同座时仍从精神点本星座起期。起期顺移不改动本命点的位置。`release_start_sign`、`start_sign_adjusted` 与 `angular_reference_sign` 分别交付这些事实。

此前把精神点自身当作峰期参照，导致144个福点／精神点星座组合中的96组峰期星座集合错误；同座不顺移还违反所选重建的12组起期规则。修复后144组起期、四角集合及1728个L1宫序／相位格通过，生成的L1／L2／L3共5856个峰期布尔值与实际运行的 Kerykeion6.0.5 一致。这是已给定星座的条件计算网格，不是144张独立天文出生盘，也不检验预测结果。全部原失败、原始第三方输出、版本与哈希保存在本轮仓库外证据中。

第三方程序并非逐条真值。[Kerykeion冻结源码](https://github.com/g-battaglia/kerykeion/blob/b81527d689991f806f8ea991364b7c3fed4c4c41/kerykeion/zodiacal_releasing/factory.py)使用365.2422日年，公开工厂也未实现同座顺移。FateBridge保留所选360日年及顺移规则，不为取得软件一致率改掉来源规则。[Delphic Oracle5作者帮助](https://www.astrology-x-files.com/help-do5/do0920.html)同样以顺移为默认，并明确另提供不顺移选项；本轮只读了该帮助，没有把它记作实际运行 Delphic Oracle。所引规则属于具名现代重建；原希腊校勘本及完整Valens程序尚未验收。

360日及子期按经过日计算，内部区间与活动期比较使用UTC，输出标签再按出生时区的历史偏移转换。原先在带IANA时区的当地钟时上累加天数，会使跨夏令时的区间多出或少掉一小时。六个合成实际日期输入中，两条释放轨合计75个L1、175个L2、171个L3区间，原29处一小时差现为零；父期截断保留，完整周期与截断周期分开比较。子期单位另以[Brennan2019周期讲义](https://theastrologypodcast.com/wp-content/uploads/2019/02/zodiacal-releasing-periods.pdf)核对。上海1990年夏令时出生和悉尼1984年夏令时出生的20×360日边界，以及切换前一微秒与恰好切换时刻，保留为回归控制。这里的UTC日历经过日不等于逐闰秒的SI秒时长认证。

另实际执行Kerykeion6.0.5的出生盘与公开释放工厂，六个日期输入的12个本命点星座一致；点经度仍有差异，未据此接受绝对天文精度。年长与同座政策造成的时间线差异完整保留。本地REST、原生MCP、CLI覆盖不同座、同座顺移及两个历史夏令时样本；当前聊天缓存进程与真实模型解释须另验。公开装配仅返回L1至L3，内部L4常量及可选输出字段不证明提供了L4计算。全部解绊情形、时域极限、完整历史方法与现实预测仍未通过整体验收。

`duration_value` 是父期截断前、以 `duration_unit` 表示的完整星座名义周期。L1为360日年数，L2为30日月数，L3为实际日数；真实生效区间读 `start`／`end`。此前L3把小年数直接标成天数，例如双子20“天”实际名义周期为50天，巨蟹25“天”应为62.5天，现已补齐2.5倍换算。父期截断不修改名义值；不能用它替代实际区间长度。此字段与日期区间分别核验，未把间隔通过追认为旧字段也正确。

八个完整函数体另拆成33项计算、选择与交付职责；两个清理函数属于交付辅助。实际执行[公开计算器](https://zodiacalreleasing.net/)当前JavaScript中原样提取的计算类及日期依赖，在显式UTC、共同360日年操作数下核对438组完整或实际截断父期、5404个L2／L3区间、37828个字段及17526次边界前一微秒／恰好／后一微秒的活动查询，均一致；12组L1初始预览也一致。这里执行的是原程序算法代码，没有宣称其网页UI验收，重复福点参照也不是新增独立出生盘。原始完整脚本、提取范围、哈希、Node版本和输出在仓库外保存。

独立新环境再次实际执行Kerykeion6.0.5，工厂文件与上述固定提交逐字节相同。288组给定父座／层级／福点参照的3600区间，10800个座序、解绊与角宫字段一致；其365.2422日年与本引擎360日年使6672个按日期交付的起止字段不同，最大157日，原差异保留，不改第三方常量或将它称为同模型时间误差。[作者讲解的解绊段落](https://theastrologypodcast.com/transcripts/ep-192-transcript-zodiacal-releasing-an-ancient-timing-technique/)说明子层一轮十二座后跳对宫，并在同一父期内继续顺行；[Delphic Oracle的解绊设置](https://www.astrology-x-files.com/help-do5/do0910.html)另指出最高层跨完整轮回的规则未明，并提供选择。公开计算器在L1也解绊，本引擎L1则一直顺行；211个360日年以后出现的政策差异未裁成一个无分歧的权威答案。

当前L1预览默认最多24段，返回已生成的过去区间、当前区间及其后四段；L2／L3只展开当前父期。分析时刻超出该预览时，current_level可为空，不能把它解释为数学上不存在活动期；450个360日年的工程输入已记录这一限制，不是寿命或事件判断。公开仍只提供L1至L3，内部L4单位辅助的检查不扩大发布范围。48项层级单位、144组给定点星座起期以及真实三端调用属于有限软件验收，完整古典文本、全部时间范围与现实预测仍未验收。本轮核对未发现需要修改该模块算术的新反例，已有算法与业务测试原样保留。

## 恒星位置、黄道与原典标签

`fixed_stars` 使用20颗已明确识别恒星的 [CDS SIMBAD 天体测量记录](https://simbad.cds.unistra.fr/Pages/guide/sim-url.htx)，每颗的ICRS J2000坐标、自行、视差、径向速度、文献及采集回执存于[随包来源表](../src/fatebridge/data/western_stars/sources.json)。这是现代观测资料，不重建古代观测星表。Swiss原生视位置按本次TT传播；[官方固定恒星接口](https://www.astro.com/swisseph/swephprg.htm)说明该计算包含自行、岁差、章动、光行差和视差。回归盘使用日期真黄道，恒星盘使用原生Lahiri位置，恒星与盘内因素必须处于同一坐标基准。

恒星位置采用当前SIMBAD输入及原生视位置。预声明的协议（本地 `tests/fixtures/western-fixed-star-protocol.json`）采用1角秒线，20颗星乘6个1900–2099年TT历元，共120个位置；独立ERFA参考（本地 `tests/fixtures/western-fixed-stars-erfa.json`）共享星表输入，但不共享数值算法或地球状态。该队列检验坐标与来源关系，不认证观测绝对精度或全部年代。朴素线性岁差近似及其比较已退役，不能代替当前误差线。

`chart_profile.fixed_stars` 返回星表来源、TT、黄道、模型版本及状态。星表单独随包分发，调用不依赖可选完整 `sefstars.txt`；缓存和操作员路径在共享锁下隔离。恒星函数可返回SWIEPH请求标志，而地球状态实际回退Moshier，故保留恒星标志并另测、另列 `earth_ephemeris_model`，不由请求标志认证精度。状态为 `unavailable` 时文本明确显示“未计算”，空列表不能被解释成没有合相。

传统性质与天体测量分别给出来源。按 [Robbins 1940《Tetrabiblos》I.9](https://penelope.uchicago.edu/Thayer/E/Roman/Texts/Ptolemy/Tetrabiblos/1B%2A.html#9)，昴星团属月亮／木星；此前昴宿六的月亮／火星标签已更正，后者是巨蟹座积尸气一类的归属。行星性质标签仅表达该处传统对应，不凭合相单独补出事件判断。审计记录同时保留旧模型残差和一对合成边界反例，不能将反例称为实盘命中。

## 参考点、模型与日速来源

`calculation_basis.ephemeris_reference_points` 明确区分原生本体中心、行星系统质心、解析交点和派生轴。Swiss 默认的火星、木星、土星等位置是相应系统质心；不是已经做过本体中心修正的坐标，依据[官方文档2.4及附录C第6例](https://www.astro.com/swisseph/swisseph.htm)。`center_body_correction_applied=false` 如实保留。太阳、月亮、水星、金星与上述点分别列出；这项说明也进入月亮与七曜事件的回执，不通过改名把其他点认作本体中心。

坐标原点与目标参考点分开核对：`BARYCTR` 改变原点，`CENTER_BODY` 则改变行星目标点；同为地心日期黄经，也不能据此认作同一点。[官方接口3.2.2及3.3.1](https://www.astro.com/swisseph/swephprg.2.10.pdf)分别说明这些选项。当前标准消费者未请求本体中心覆盖，原生返回若带此标志，会报 `coordinate_contract_changed`，不继续按默认系统质心发布；守卫验收区分了受控故障与正常星位保留检查。未启用新的本体中心模式，也未由此改变既有精度失败的判据。

精密比较还须匹配时间尺度、地心／站心、视位置约定及坐标框架。原生2.10.03源码默认采用Vondrák2011岁差、IAU2000B章动与IAU2006框架偏置；它与Horizons第31量的IAU76/80日期黄道不能直接认作同一框架。这是指定源码版本的默认定义，不是对任意安装版本或运行时底层配置的认证。共同框架检查用JPL ICRF方向及独立ERFA旋转核对相同参考点，不通过替换原生坐标或放宽容差来配平。

主本命盘、希腊盘和十三等分盘也在 `chart_profile.ephemeris_reference_points` 返回同一参考点合同，并将实际分组说明带入摘要与文本快照；归组依据每颗因素的实际模型，单颗回退时按实际来源归类：连续DE441冥王星明确为系统质心，其余未确认中心身份的近似源继续单列。交点与派生轴／阿拉伯点分别标记。本命盘来源交付验收核对共享映射、完整结果与严格字段投影；这些说明不改变星位或证明物理观测、原典全文及现实预测有效。

推运／事件底座的 `ephemeris_model` 现在只汇总物理天体的实际后端，解析交点单列。此前单一Moshier或Swiss数据模式会因加入解析月交点而误报 `mixed`；现在只有实际物理后端混合才用该标签。底座还返回物理数据来源和计算期间配置一致性检查，文件身份不等于观测精度认证。

## Balbillus比例削减与异法

当前选择《Catalogus Codicum Astrologorum Graecorum》VIII.4（Petrus Boudreaux编目，Franciscus Cumont编辑及增补，Brussels: Mauritius Lamertin，1921）所刊Balbillus／Palchus摘录的有限读法。[原书第237–238页](https://archive.org/download/ccagtome-08-part-3/CCAGTome08Part4.pdf#page=251)列出七曜小年：日19、月25、土30、木12、火15、金8、水20，并述每个父期将自身年数分为129份，先分给自己，再分给其后各星。第237页注24明示将手稿119份校为129、太阳119份校为19；此处采用校订正文，保留异读及编者按七曜小年合计129的理由，不称手稿无歧义。

主周期采用声明的连续黄经读法`N × (1 − d/360)`，d为`nearest`最近角距或`forward`自擢升点顺黄道到本命黄经的距离。子期为`父期时长 × 子星原小年 / 129`，不再用子星另行削减后的周期除12，也不把余额全部塞给末星。自身先取份额，其余按本命黄经序；该顺序、连续／序数度、距离方向以及360日比例与实际历年的对应仍为条件读法，尚未裁定完整历史程序。

2026-11-09先移除太阳、月亮和火星专属的经验线性拟合。原拟合使太阳恰在所选擢升点时仅得17.9724167年，与所声明的19小年不符。按事先固定的七曜、两种距离读法及每0.25度网格，共20,160条主周期有理数参考，原实现4,320条超既定`1e-10`年线，修复后零超差。参考是对公布规则的独立算术实现，不是真实第三方软件逐盘观测。随后读取上述校订本，发现原子限在七个擢升锚点的49个父子配对中48个不符、1个缺项。对同一20,160组输入的扩展检查，原子限121,532个不符、19,588个缺项；改为129份后，141,120个子期时长及141,120个起点均满足原四位小数的半末位单位`1/20000`年线。全部原输入、缺项和门槛保留；扩展检查是在修复后进行的鲁棒性研究，不能冒充盲测或新增独立原典观测。

结果`reduction_model`记录`balbillus_continuous_proportional_v3`、主子周期公式、原书作者／编者、1921版页码及校勘信息，同步进入快照。七曜擢升／落陷及每个子星份额进入自包含回归；此前只检Venus和只检子限总和的抽查已由这些来源控制替代。已有[Delphic Oracle方法说明](https://t.astrology-x-files.com/help-do4/balbillus-method.html)及[Project Hindsight比例规则](https://www.projecthindsight.com/products/delphicoracle.html)仍作为软件读法参照，不代替原书校勘。

另实际执行了 [Horosa固定提交的标量及主子期源码](https://github.com/Horace-Maxwell/Horosa-Web-App-comprehensively-improved-MacOS/blob/10fb75de980bb0a6e0d1f50c7ee93cc97a88d7de/Horosa-Web/astrostudyui/src/utils/balbillus.js)。它采用序数度`floor(黄经)+1`，太阳／月亮／火星基数为18／24／14；同一20,160点的标量定义差异继续保留。其`once/cycle/fill`三种子限读法，在七曜21组条件执行中，自年份额均不同于所选校订本的`小年/129`。该执行核对未运行GUI或日期转换，不将一种软件输出充作所有流派的唯一真值。原典全程序、所有取度及历年读法、实际事件预测和SOTA仍未获验收。

## 近太阳导数的假收敛与分段

`fatebridge_complete_position_derivative_v8`对固定发展的42个历元在两种框架下共84组对照采用原0.002角秒／日门槛。70位用于独立数学归算，输入星历仍为双精度原生物理数据，不能称作70位天文精度或盲测；实际结果应读取本次审计，不能由方法版本名推断全部样本通过。

所有数值阶段都核对多层中心差分及两种密度的单边拟合，内部0.0002角秒／日线保持。太阳内部质量表按半径分段插值；普通对称模板跨越近处节点时，只有严格位于已知分段内部、全部采样节点同段的方向才可参与局部单边导数。所有适用方向都要共同通过三层检查，不能挑有利的一边；未知分段或精确节点不补成有效计算。`complete_position_derivatives`中的`directional_checks`、`source_branch_motion`与`sampling_stabilization`保留方法、被排除的方向、原失败阶段和量化尺度，显示位置不由该算法改写。

在常规路径全部未收敛、且已确认位于原生有限太阳模型分段内部时，当前方法可对水星／金星／火星的辅助几何状态作50位数学化简。它按原质量表处理光偏折和光行差，恢复原生迟延历元的小数余量，并用经核对的原生基向量转换显示框架；仍须满足全部适用方向、三层及原0.0002角秒／日线。实际采用时在`source_branch_motion.decimal_reduction`记录运算位数、质量表散列、框架检查和适用限制，该次先前尝试的失败保留在`decimal_reduction_previous_attempt`。50位运算不等于50位天文精度，显示星位不改写；共享星历上的独立数学参考不能替代绝对天文验收。

## 十年星限比例重建与精确时轴

`decennials`和聚合推运使用昼生太阳／夜生月亮起期、七曜本命黄经排序、每主期129个30日月，以及按小年数／129递分的第三、第四层。它是具名的比例重建。[Valens的Riley初译本](https://www.skyscript.co.uk/pdf/pubs/texts/valens/riley/docs/Vettius_Valens_Riley.pdf)第VI卷5–7节及第IX卷第五世纪增补同时传有比例表和重复129日周期，表数及例算也有不一致；初译本纸页119–120、168–169不能合成一个无分歧的算法。现行起星也没有实现原文完整的aphetic资格筛选。

计算保留精确有理数，从出生UTC锚一次舍入到最近微秒，再转换出生区显示；半微秒取偶数。旧版第三层五分钟、第四层一分钟提前取整已移除，地方钟的夏令时变化不改变名义经过日。`start_offset_exact_minutes`／`end_offset_exact_minutes`给出名义分钟的分子、分母；原整数偏移和`nominal`仅为显示。`calculation_options`声明模型与舍入口径。预览仍为七个主期，当前三层各带七个直接子期；超过预览仍能定位当前期。

独立FLINT 3.6.0／python-flint 0.9.0对40,320个父期与循环顺序状态的282,240个子段核对精确偏移及微秒端点，零差。在相同UTC比例模型下实际执行[shin10567/Morinus-Source-Codes固定提交](https://github.com/shin10567/Morinus-Source-Codes/blob/bbe3ebe1bb5b9a7d62cb6662ff413e61522cc6c6/decennials.py)，FateBridge边界误差均不大于参照，最大约0.49973微秒，参照最大约2.09411微秒；这只是所定比例公式与微秒表示的比较；具名实现参照不构成领域权威或完整软件SOTA认证。另核对全部47,293种七曜同经／异经排序关系，以及Temporal 0.5.1的24个合成出生钟、216个时轴场景和240个边界查询。它们没有独立重算本命天文，也不是盲测或现实预测证据。

公开Schema仍只提供默认模型。内部手选起星、Chaldean顺序和365.25日名义年缩放不作为新增公开能力，后者也不是实测太阳年。原称Hephaistio的未发布候选表缺少可核实出处，七行中六行与父期总长不符，故停止执行，未将其归一化或记为通过；原表、六行差额和原典差异保留在[固定参考](../tests/fixtures/decennials-reference.json)。原典校勘、完整起星资格、其他日主方法和预测有效性仍待验证。

### IERS公式的精确转数与模型差异

自转v4保留原表十进制ERA初相和日速，在所给UT1浮点的精确有理点上组合转数；小角修正在角秒内补偿求和，直到最终周天归一后才转度数浮点。它保留内部算术低位，不恢复输入时刻已舍去的精度，不改变章动、黄赤交角或TT／UT1来源。旧v3输出及冻结参考保持，版本回执区分实际实现。

[独立参考](../tests/data/rotation_iers2010_v1/README.md)按实际TT正负两世纪时窗逐日加确定二进制相位取146101点，分别采用IAU与原生角度输入，共292202次实际表达式计算；原0.001角秒线均通过。IERS原表34项及8个基本角的来源逐项核对，原12点ERFA参考完整复算逐值相同。90位原表十进制表达式的257个预先均匀点、两类输入共514项，当前全部不劣于同输入ERFA，最大约1.023e-10角秒；旧271／514项不劣于ERFA及其余243项差距保留。

共同输入的表达式算术通过不等于完整IAU2000A_R06参考系通过。当前Swiss章动／平均黄赤交角输入对完整IAU模型的146101点仍有7116项超过毫角秒诊断，最大约0.002590角秒；该模型差异保持未通过。IERS截断表达式在完整IAU输入下与完整SOFA旋转也有微角秒量级差异。远期原生变化及固定相位政策、极移／CIP／次日潮汐、实测钟时和物理观测继续分别验收。

### 原生太阳质量单元的来源核对

太阳质量分支完整审读外层及状态采样边界。独立编译固定Swiss源码的原101点质量表与未改的meff函数，以原几何运算接收公共矢量。2420个预先固定受控输入覆盖全部101折点、中点、五种二进制偏移尺度和外部区域的两种正交方向；另用原42个实际水／金星历元及9个均匀火星控制，共51个实际原生几何。所有获准单元均与原作者C相同；202个折点保持未知，208个中点／外部控制均可用。

冲击参数的浮点诊断不宣称与作者C逐位相同：Python与C的浮点归约可不同，算术余量及两种几何必须一致才可给出单元。实际控制的最大比例差约3.34e-11，全部受控向量最大约1.54e-9，单元无误判。这里复核的是已声明来源的局部分支，不是独立星历、连续区间完整性或真实日盘内观测认证；原日速折点失败及各步长结果继续保留。

本轮[同矩阵控制](../tests/data/rotation_frame_v1/README.md)以完整原作者C及ERFA2.0.1核对146101个预定TT／UT1。旧显式公式搭配原生NPB有4885点超过原0.001角秒一致性线，最大约0.001165角秒；修正后同矩阵GAST最大差约5.270e-8角秒，矩阵轴方向重现最大约7.033e-11角秒。257个实际共享默认钟时控制由9项超线降为0，且在空星历目录下可重复；原钟时与新钟时逐点一致。原始一律SWIEPH参考的97个历史钟差保留，按已声明历史-1／现代SWIEPH政策重建共同输入，不将参考政策差异说成引擎物理错误。
