# 出生范围的派生秒数与漏采事件

`birth_time_uncertainty_minutes` 声明的是以名义出生参考为中心的正负UTC经过分钟。原始秒数未知时，名义参考沿用00秒；这不意味着每个派生地点钟时的秒数都等于00，也不意味着出生记录精确。

历史时区偏移可能带秒数。阿比让1912年从 `-00:16:08` 改为 `+00:00`，跨过变更的逐分钟UTC网格会产生本地秒数08或52。旧采样器在原始秒数未知时把派生秒数再次设为未知，归一化遂重用00：部分有效瞬间被误当成不存在的钟时，另一些被移动到错误的实际瞬间。现在派生样本保留自身实际钟时的秒数，原始 `PersonInfo.birth_second` 仍为未知。

## 核对范围

来源采用上一轮已由官方 `zic` 编译并冻结的 [IANA 2026e](https://data.iana.org/time-zones/releases/tzdata2026e.tar.gz)。按固定条件选出全部399次非整分钟偏移变更，覆盖354个公开时区名；每次变更前后各构造一个整分名义参考，核对正负两分钟网格，并分别测试原始秒数未知与显式00，共1,596个输入变体、修复后7,980个网格瞬间。

修复前798个未知秒数变体失败，其中434个移动了实际瞬间，364个发生误拒；显式00对照保持原有正确行为。修复后所有网格瞬间与来源规则一致，原始记录未被修改。此项核对隔离并替代了排盘层，只证明时钟构造与归一化传递；不能把它当成7,980个独立排盘、天文观测或预测案例。扩展队列在初步修复后生成，属于问题发现后的回归，不能宣称是盲测。

完整领域计算另有两个虚构软件控制例：一例检查原先误拒的有效范围，另一例检查被多报的时柱候选。它们用直接 Swiss `time_equ` 与已冻结IANA偏移构造固定输入，不由 FateBridge 输出生成预期值；均时差口径仍与程序共享，地理位置也不作为真实出生观测。校正钟面绝对容差预先固定为0.1秒，不能把这个容差或相符结果说成独立认证的物理精度。

首版测试误把跨午夜当作换日柱；当前八字规则在23点翻日。错误假设、原失败日志和第一份测试均保留，历法规则没有为通过测试而改写。原控制的UTC瞬间与午夜校正钟面预期保持不变；新增1点界线控制用于核对真正的时柱候选差异。

原始资料的省略事实继续由 `calendar_context.birth_time_input` 返回。未知秒数与显式00可以拥有相同的名义数值网格，同时保留不同的输入身份与精度回执；范围计算不得反过来把派生秒数写入出生档案。

时钟修复验收（本地数据：`validation/bazi-derived-seconds-local-v1.json`）对应明确冻结的997个源码／构建文件。源码219项回归（含两个范围入口的完整／投影REST、MCP、CLI核对）、带星历文件的10项控制与基础依赖构建包15项检查通过。源码和构建包各自的全新stdio进程均完成9次工具调用及45页同次结果散列校验，另运行了安装包的两个独立CLI命令。没有把工具调用算作模型运行。

保存的构建包与差异文件可逐字节重建修复前990个、验收后997个文件；原始失败、错误测试假设、修正后的对照与成功结果分开保留，见证据索引（本地数据：`validation/bazi-derived-seconds-v1-logs/artifact-index.json`）。这些结论限定于指定源码和构建包；合同检查通过时，场景清单仍因并行源资料变化报陈旧，未据此宣称整个共享工作区已验收。

## 尚未补齐的连续范围

冻结协议（本地数据：`../tests/fixtures/bazi_uncertainty_events_v1/protocol.json`）还登记了另一类问题：两次变化可能发生在同一分钟采样间隙，留下一个网格未读到的中间命盘。独立于候选程序的来源算术遍历了1,439,964个节令与时区组合，固定9,929个邻近换时事件；9,922个有足够参考排序间隔，另7个保持未裁定。

本篇时钟修复验收时，完整修复前排盘核对仍在运行，尚未据部分结果作出全队列结论。该快照如实标记了逐分钟范围，但尚无事件候选扩展。后续已另行实现[本命事件探针](bazi-birth-events-audit.md)，其冻结源码、局部验收和仍在运行的完整队列独立记账，不追溯改写本篇时钟回执。真太阳时边界、民用跳时／回拨、当前大运的连续状态变化与交运极值继续逐层核对，不以原始钟面样本代替。

后续范围保持在待核对队列（本地数据：`validation/bazi-next-calculation-gaps-v15.json`），没有把时钟传递局部通过替换为连续范围通过。

新增的内部 `rebase_birth_clock` 可在已确认的时区、经度和校正策略下计算带微秒的派生瞬间，不修改原始记录，也不新增声称已知出生微秒的请求参数。它为后续事件核对保留必要分量；函数存在和单元测试通过不证明连续候选已穷尽。[根求解文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.brentq.html)要求连续函数与异号括区间，单次求根收敛同样不能证明找齐全部变化。

[Python datetime](https://docs.python.org/3.12/library/datetime.html)使用理想化公历和不含闰秒的每日时长；本核对沿用程序既定口径。历史UTC字样为前推计算标签，不断言当时已经采用UTC或真实记录误差已知。

原典25组349条记录仍保留26种已知旺衰分歧；本轮不改强弱政策或原典标签，没有新模型、独立专家或现实预测观测。整体验收继续为 `unproven`，不赋总分。本地源码与构建包验收、共享部署和真实模型行为分别处理。
