# 八字综合与九项专题：证据深化审查

本页记录首轮深化及当时结果。后续取格规则、解释模板和四维验收的更新见
[八字四项验证](bazi-four-axis-validation.md)；下文8/10等数字保留为首轮历史记录。

本轮从生产代码、公开合同、冻结原典命例和反例出发补强。目标是让每项判断能回答
“哪颗星、什么位置、哪一种根、哪个条件、哪个时间层”，并保留反证。
版本 `bazi_position_prerequisites_v1` 不替换既有旺衰权重，也不认证所有子平流派。

## 共性认知盲区与本轮落地

| 盲区 | 容易产生的误判 | 本轮处理 | 保留的限制 |
| --- | --- | --- | --- |
| 把出现次数当有效力量 | 财多即富、印多即学历高 | 逐星列透藏、柱位、同字根／同五行根；另传旺衰模型版本与敏感状态 | 不把根存在等同根深或有效 |
| 把十二长生与藏干根合并 | 阴长生凭空增加藏干；没藏干就无任何根 | `roots` 与 `growth_phase_roots` 分立；仅有长生参照时保留流派复核 | 不把阴长生作为新权重叠入旧旺衰模型 |
| 十神共现就成格 | 伤官、印同现就断伤官佩印 | 五类 `structure_checks` 逐项返回 matched／not_matched／unknown | 身强食旺、印根深、制化力度及救应仍待裁定 |
| 无月令起点和禄刃资格 | 戊生未月因己劫财就称月刃 | `month_command` 并列本气、各藏干透位、会支、建禄与阳刃资格，并标旧标签冲突 | 不静默改写旧取格算法或冒称取格分歧已解决 |
| 同组合不同位置被抹平 | 财印一出现就财破印，或丁壬一见便合去 | `financial_seal_positions` 列柱间距离、中隔字、五行克制及天干五合 | 存在配对不等于作用成立、合去或破格 |
| 专题只收到孤立时间标签 | 只知道流年某十神，不知触动何宫何星 | 九专题均返回流年／大运天干、藏干、对本命逐柱关系、相关宫触点、运年间关系及联合完整合会刑组 | 不扫描全年、不机械判合化吉凶 |
| 局部资料缺项使整题失败 | 未知性别使所有专题失去本命和流年 | 未知顺逆时仅缺大运；保留本命、独立流年及明确覆盖柱 | 大运不猜顺逆；独立大运专用接口仍可要求性别 |
| 现代应用覆盖原典条件 | 用岗位类比、关系分数倒推古法成立 | 同时返回规则版本、原典定位、形式化范围及未裁定条件 | 旧有各专题的现代类比与固定指数未获得效果认证 |

五类条件审查为食神生财、伤官佩印、食神制杀、杀印相生、正官财印相辅。
`not_applicable` 表示相关星未齐；`prerequisite_not_met` 表示本限定规则有明确条件未满足；
`pending_adjudication` 表示只有部分条件已核对。三者的 `formation_status` 均为
`not_adjudicated`，不能读成“不成格”或“已成格”的全局裁决。
财印同现也不强行归入“正官财印相辅”；财、印分别有自己的存在条件。

## 九项专题的实际增量与剩余缺口

| 专题 | 新证据的组织方式 | 仍不能由单盘或当前规则完成的判断 |
| --- | --- | --- |
| 事业 | 官杀、印、食伤、财的透藏与根；月柱关系；格局前提与运年触点 | 真实技能、职业高度、行业收益；完整成败救应 |
| 财运 | 财与食伤、比劫分列；财印位置；运年藏干财及完整合会触点 | 财库逢冲就发财、资产数量、信用、投资成功概率 |
| 婚姻 | 配偶星含日支藏干；星与日宫分列；未知性别保留分支 | 另一方心意、实际相处、婚姻成败与双方互动 |
| 正缘桃花 | 财／官传统选星分支与日宫引动；不把接触点当身份认证 | 正缘身份、忠诚、第三者、必然出现的婚恋事件 |
| 学业 | 印、食伤、官杀分别定位；月柱及运年触点 | 智力、学历、录取率；需成绩、资源与目标等现实资料 |
| 性格 | 十神外显与暗藏分别记录，保留根气与时间层 | 心理量表意义上的人格特质与精神诊断 |
| 六亲 | 偏财、正印、比劫与年／月宫；新增可追溯运年触点 | 从没见某星推亲人不存在、人数、信用或实际亲疏 |
| 子女 | 按已知性别选择官杀／食伤；时宫与时间触点 | 孩子本人画像、生育能力、数量、性别与生育时间 |
| 健康文化 | 继承盘内五行文化分类与版本；时间关系保留为盘内事实，不指定临床“健康星” | 身体强弱、疾病风险、诊断、治疗和医疗择时 |

上述选星和宫位属于 `fatebridge_position_topic_v1` 的专题取证约定，不能归为
《子平真诠》统一认证的九主题解释。性别相关口径只是所声明传统映射，不能用于
推断性别认同、性取向或真实伴侣情况。

## 已修复的婚姻计算错误

1. 未知性别原先由布尔否定落入女命，现保留男／女传统配偶星分支，不生成混合质量分。
2. 配偶星原先漏掉整个日柱，现只排除日干自身，保留日支藏干。
3. 红鸾、天喜、咸池、孤辰、寡宿原先查出目标支便输出命中，现须原局实际出现该支。
4. 男命配偶星入墓原先误查克日主的元素，现查日主所克的财元素；墓库对应不推断配偶健康。

这四项是确定性的选星或集合判断错误。它们的修复不使墓库简表、神煞或婚姻指数
自动成为现实预测方法。旧字段 `spouse_star_strength` 的次数分类保留兼容，
新增 `counting_scope` 明确其不是有效旺衰；专业读取使用新的逐星证据。
婚姻指数另给出 `score_kind/score_basis/counting_scope`，移除仅凭分数建议晚婚、
仅凭比劫计数推第三者的措辞；固定指数仍未完成现实效度验证。

## 读取与复算

- 综合：`structure_profile.evidence_chain`；标准命盘：`bazi_birth.structure_profile.evidence_chain`。
- 九专题：`<topic>_analysis.evidence_chain`；公开 `evidence_views.depth` 给出字段路径。
- 普通主题首轮保留 `method_id/strength_context/topic.first_view` 与原有主题主证；`first_view` 按专题声明顺序摘录两种已见星并列出生效时间柱，不表示主导或排名。规则原文定位和完整审查由 `depth` 读取，避免完整对象挤掉默认预算中的业务主证。
- `topic.timing.layers` 使用 `timing_context` 实际生效的自动／覆盖柱；不另造日期。
- 文本快照只摘要条件状态；完整位置和条件对象从 JSON 读取。完整导出应首次 `fields=null`，同run交付规则不变。
