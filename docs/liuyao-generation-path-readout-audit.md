# 生源、受方与特定生向的逐路径说明

第三十三轮修复了一个解释遗漏：生源条件和受方当前门槛都已匹配，并不一定使这一路生扶成立。已有计算还检查受方特定的寅木生扶资格，摘要此前没有在对应路径句中交代它及最终路径结果。

例如冻结的开发输入为 2000-03-27 12:00、Asia/Shanghai，`010101 → 111101`，明确焦点为第六爻。当前历法返回卯月甲申日。第一爻寅木具有来源资格，第六爻巳火的受生门槛也通过，但巳寅申限定条款排除这一路寅木生扶，最终 `benefit_now=false`。旧路径句只有“生源条件匹配；受生爻未见所列承受障碍”，读者必须另找其他位置的三支说明才能知道路径未匹配。

现在每条受限路径返回可选文字字段 `qualification_explanation`，补充实际计算的特定资格与最终结果：“巳寅申限定条款排除这一路寅木生扶；本条生扶路径条件未匹配；刑的总作用仍未裁定”。快照直接消费这一返回文字。源资格、受方门槛、特定生向与最终路径分别保留；不将其中任一项改成另一项，也不由路径条件推断现实结果或刑害。

实际首读合同默认 `include_snapshot_text=false`，所以说明也必须通过结构化生扶路径交付。最初仅补快照的 R1 候选因此被取代；其未完成的重复复验明确记为已取消（本地数据：`validation/liuyao-v33/r1-cancellation.json`），已完成部分（本地数据：`validation/liuyao-v33/r1-partial-verification.json`）及全部日志保留，没有把取消当作通过。最终实现不需要客户端开启快照才能读取这项说明。

依据仍是既有选定版本：同版NLC 1925 书影（本地数据：`../tests/fixtures/liuyao_scan_v3/sources/nlc-1925-zengshan.pdf`）第 98 页的巳、寅、申条款及先前冻结的限定规则（本地数据：`../tests/fixtures/liuyao_penalty_v20/profile.json`）。本轮复读书影并核对来源散列（本地数据：`validation/liuyao-v33/source-reading.json`），没有增加原典裁决或扩大排除范围。摘要共享函数直接读取 `target_yin_generation_allowed` 和 `benefit_now`，不重新判断三支、活动资格或生克。

四个输入及完整计算前结果在冻结开发资料（本地数据：`../tests/fixtures/liuyao_generation_readout_v33/cases.json`）和原始输出（本地数据：`../tests/fixtures/liuyao_generation_readout_v33/before-payloads.json`）中保留。它们不是四个原书事件、盲测或四份真实模型回答。另两个未决许可测试是说明函数的显式 DTO 状态，不冒充新增合法卦盘或准确率样本。

不适用该限定的路径保持原说明；原本在当前静爻生扶范围外、未显示的路径继续保持原有显示范围。首轮错误地要求后者也必须出现路径句，造成一项审阅断言失败，已单独勘误（本地数据：`validation/liuyao-v33/baseline-expectation-erratum.json`）。另外两项首轮失败确实对应解释遗漏。原日志、错误断言及冻结源码均保留，未更改原始计算预期。

计算规则补丁版本为 `2.18.2`。四处运行时改动限于共享说明、可选输出字段、快照消费和版本元数据；源码结构核对（本地数据：`validation/liuyao-v33/r2/calculation-ast-proof.json`）确认原数值及判断表达式未变。原生成函数只新增一条文字赋值分支，移除这一明确分支后 AST 与上一候选相同。四个完整结果另逐字段比较，只单列经过语义核对的新文字、快照及补丁版本差异。两个旧完整结果测试只更新版本预期，原断言、原 JSON 和原案例身份不改。

新加的两项投影检查最初错误地把数组写成可以点入条目的字段路径。现有[投影实现](../src/fatebridge/application/projection.py)及[开发指南](development-guide.md#新增或修改一个领域能力)要求数组整组选取；原失败和勘误（本地数据：`validation/liuyao-v33/r2/projection-test-erratum.json`）保留。修订验收检查完整生扶数组中的新字段，并分别验证非法数组子路径和未知对象字段继续被拒绝，没有修改投影规则。R3 只改测试，804 个运行时文件与 R2 逐字节相同。

另以原 8192 字符预算、已发布首读字段和关闭快照的组合进行补充实测（本地数据：`validation/liuyao-v33/r3/budgeted-first-reading/result.json`）。REST、原生 MCP、CLI 各自从原 run 恢复完整 payload 并核验 SHA，恢复数据含实际排除说明与假值路径；没有为补全文本重新计算。这是工程读取验收，没有增加独立案例或真实模型回答。

本轮没有重新运行太阳交点精度队列。天文、时标与历法依赖沿用冻结的第 31 轮；第 32 轮原生 Moshier 的 501 项失败和月球单项替换新增的 86 项退化继续有效。作者展开式镜像返回 404，作者直接下载返回 403，均保留访问记录，没有取得新系数或形成新的数值候选。作者索引还明确 `emb.zip` 拟合 DE102，`plan404.zip` 使用与 AA56 相同的展开式，不能把发现下载名称记作发现更高精度候选。

另外按[公开 `ear404` 系数](https://raw.githubusercontent.com/aloistr/swisseph/master/swemptab.h)独立重建了135 项地月质心级数（本地数据：`validation/liuyao-v33/emb-source-reconstruction/result.json`），使用直接组合角求值，与二进制的递推倍角实现分别计算。原 4,872 交点输入加既有 256 个一般时点全部低于预先固定的 `1e-12 AU` 分量差线，最大约 `7.40e-14 AU`。这支持该批输入上的系数求值一致，不能证明物理准确，也不证明上游 master 是编译源。既有输入的太阳视运动为每秒约 0.0397—0.0425 角秒，而[Moshier 作者资料](https://moshier.net/)给出的地球位置精度量级约为 0.1 角秒；量纲核对（本地数据：`validation/liuyao-v33/angular-scale-reading.json`）说明角位置介绍不能充当原 1 秒 TT 的保证。原 501 项失败继续保留。

同版第 74、104—106 页的补充复读（本地数据：`validation/liuyao-v33/followup-classical-reading.json`）继续区分静爻合起、动爻合绊、未来逢合与出空应期。没有把未来逢合普遍改作当前静爻月破已解除，也没有把书中应期叙述当作本工程收集的现实事件。第 26 轮误归版本的记录与勘误仍保留。

本轮也没有新增模型对话；内置路径说明与三接口检查不能替代当前版本自由回答的真实模型复验。没有发布或部署。最终验收和失败链见本轮机器回执（本地数据：`validation/liuyao-depth-v33-verification.json`）。
