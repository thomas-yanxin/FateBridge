# 大运边界包络的分析上下文漏扫修复

本轮修复了一个独立于太阳求根的范围计算缺口：相同出生范围的交运边界，因分析日不同或改用显式年龄而漏包已知探针。原40,219条失败证据、后来原队列完整复放的54,818条严格失败、原41项TT边界冲突、原26处原典分歧及5例解释验收记录全部保留。本轮没有重新执行原116,906条完整队列，不能从54,818中扣除新增队列的修复数。

## 原因与修复

原实现只在分析日附近扫描未来跳时。交运时间线本身不依赖分析日，但其范围包络因此可能遗漏其他日期的跳时结束逆像；显式年龄路径则不扫描这类未来事件。既有不存在钟时向前平移政策在跳时结束处产生向后的离散跳变，分钟端点不能替代这段局部极值。[dateutil说明](https://dateutil.readthedocs.io/en/stable/tz.html#dateutil.tz.resolve_imaginary)描述了不存在钟时的前移语义；该政策本轮没有更改。

新增扫描根据每个仿射出生单元和全部13个配置十年边界的实际墙钟投影范围选取窗口，适用于有分析时刻和显式年龄的路径。公历闰日裁剪的两侧参与投影范围计算，避免只取两个端点而漏掉中间墙钟值。[Python的UTC偏移约束](https://docs.python.org/3.12/library/datetime.html#datetime.tzinfo.utcoffset)要求偏移绝对值严格小于24小时，因此墙钟投影范围向两侧各扩24小时可以覆盖对应转换瞬间；这只是扫描窗口的推导，不是给交运包络添加24小时容差。

扫描仍逐个整数UTC秒检查实际加载的时区对象，保留区间中偏移多次变化而端点偏移相同的情况。缓存按实际时区对象和UTC日期绑定，保留UTC零时的变更，不按时区名称复用不同数据对象。原分钟网格、分析日附近的跳时与回拨探针全部保留，新增事件只补充探针。范围结果继续明确未认证连续极值、出生记录精度及物理精度。

生产增量只有三个文件：新增边界扫描领域服务、在既有出生事件服务中并入结果，以及公开输出类型。单点时间线、公历加法、TT换算、太阳模型、强弱规则和原典判级均未修改。方法标识升级为 `dayun_all_boundary_gap_and_analysis_probes_v4`，旧v3验收源在修改版本预期前已归档，其他断言保留。

## 冻结参考和全部配对结果

事前协议（本地数据：`validation/bazi-dayun-boundary-clock-window-v1/protocol.json`）固定了抽取方法：遍历完整116,906条来源记录，按时区、方向和50年分组取第一条已知控制，再加入既有两条内部／末端边界控制。得到34个控制，每个分别使用原分析时刻、后移180天、显式年龄30三个上下文，共102种情况。这些均为已暴露的工程材料，不获得盲测或独立观测信用。

参考生成器只使用冻结节气标签、标准库整数公历和已冻结的独立TZif解释器；原782条未知的编号和原因全部保留。另有924个较晚的探针投影超出独立TZif覆盖，逐个保留为空值及原因，没有从生产结果补成已知。安全探针仍用原正负100毫秒位置，跨根数值检查仍为0.1秒，严格包络仍为零容差，逆像floor／ceil仍单独作为诊断。

例如纽约工程控制的出生参考为1908-04-04 17:29:47、正负1分钟。把分析日后移180天或改用显式年龄后，旧包络最晚首运边界为1918-03-31 03:57:14.092040−04:00，却遗漏同根安全探针给出的03:59:47.905197−04:00。修复后三种上下文均保留03:59:59.999994−04:00的已计算事件探针。派生微秒不代表该出生记录或历史太阳模型具有微秒准确度。
