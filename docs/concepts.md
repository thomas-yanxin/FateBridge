# 核心概念与结果阅读

AI 咨询中的计算、解读与对话各有职责。理解这些分工，可以帮助开发者与 Agent 维护者判断结果来自哪里、哪些信息需要核对，以及哪些条件会影响解释范围。接入时最常用的概念包括工具与场景、输入时间、结果回执和完整导出。

需要先运行一次计算时，从[快速入门](getting-started.md)开始；需要具体参数时查 [API 参考](api-reference.md)。

## 计算、解读与对话的分工

| 组成 | 负责什么 | 使用方式 |
| --- | --- | --- |
| FateBridge 计算引擎 | 按输入执行排盘、历法和规则计算，返回结构化结果及相应运行说明 | 本地运行，通过 MCP、REST 或 CLI 调用 |
| Onda 咨询技能 | 指导 Agent 判断本轮主题、选择计算依据、解释传统含义并组织回答 | 技能文件随源码仓库提供，由支持技能的客户端加载 |
| 接入应用、Agent 客户端与模型 | 提供界面与对话，理解问题、调用计算并表达结果 | 由使用者或应用开发者选择和配置 |

例如，用户询问工作方向时，Onda 指导 Agent 选取相关结构与时间依据，FateBridge 执行所选计算，模型结合实际结果组织解读。计算服务本身无需 LLM API Key；对话模型的配置取决于所选客户端。技能与场景清单的发现方式见[Onda 索引](../skills/README.md)。

## 工具与入口

一个工具负责一项计算或查询，例如 `bazi_birth` 生成八字命盘。REST、MCP 和 CLI 是调用它的不同入口，共用领域服务，但名称、请求形态与公开范围可能不同。不能仅凭工具同名就将某一端的请求原样发到另一端。

| 名称 | 含义 | 何时使用 |
| --- | --- | --- |
| 工具 | 具体计算或查询的输入与输出合同 | 已知道要算什么，读取其 Schema 后调用 |
| family | 工具目录的能力分类 | 从较大的目录缩小发现范围 |
| 场景 scenario | 按用户任务组织候选工具的发现入口 | 从事业、关系、时运等问题选择相关依据 |
| Onda 技能 skill | 主题取证、范围判断、解读与交付规则 | 让 Agent 围绕当前问题使用计算结果 |

一个场景可能涉及多个 family；一个工具也可能用于多个场景。场景列表和技能清单是选择指引，不会自动执行其中所有工具。`FATEBRIDGE_MCP_FAMILIES` 与 `FATEBRIDGE_MCP_SCENARIOS` 会限制连接公开的工具，两者同时设置时取交集；配置后需要重启连接。

选工具看[场景路由](scenario-routing.md)，了解技能发现与维护看[技能索引](../skills/README.md)，核对名称映射看[三端能力边界](api-reference.md#24-三端能力边界)。

## 输入与时间口径

出生时间、分析时间与取当前时间的依据有不同职责。

- `birth_*` 描述出生事实。接口使用公历，农历须先转换；不以默认小时补出未知出生时刻。
- `analysis_*`、`target_*` 或提问时间字段指定本次计算目标，具体名称取决于工具。
- `as_of` 冻结未显式指定的当前时钟，帮助复现；它不能替代出生时刻，也不能覆盖工具要求显式提供的目标钟时。

出生时区取决于地点和历史日期。中式工具与西占的真太阳时默认策略不同，核对实际工具合同和返回的时间校正，不把一个体系的默认值复制给另一个体系。西占推运若指定精确目标时刻，应同时提供 `analysis_hour` 和 `analysis_minute`，并核对 `analysis_context.analysis_datetime`。

传统周期也有各自边界：节气年／月、公历范围、生日年、返照周期和法达分期不能只用“今年”合并。时间层的选择与比较见[共享时间选择](../skills/_shared/timing-selection.md)。

## 一次结果包含什么

| 内容 | 用途 | 阅读时注意 |
| --- | --- | --- |
| 业务字段 | 本次实际计算值、规则命中及解释依据 | 字段根随工具变化，以实际输出合同为准 |
| `snapshot_text` | 算法生成的中文摘要 | 不能代替完整业务结果；并非所有工具都有 |
| `snapshot_export` | 部分工具提供的导出文本及章节信息 | `selected_sections` 只筛选导出文本，不裁剪全部业务数据 |
| `run_metadata` | 工具、版本、有效时间、输入和结果摘要等回执 | 通常默认附带；复现仍需保存原输入与对应环境 |
| `result_delivery` | 超出响应预算时读取同一次结果的交付信息 | 有保留期限与容量限制，应及时保存所需结果 |

`fields` 从输出根选择字段，`strict_fields=true` 拒绝无效路径。当前投影沿对象路径读取，数组应选择其所属字段后在客户端处理；交付资源支持的数组索引不能直接照搬到 `fields`。

REST 的投影等公共输出选项使用查询参数；MCP 使用工具参数；CLI 的多个 `--fields` 路径以空格分隔。输入字段相似，不代表输出字段根相同，例如独立八字命盘位于 `bazi_birth`，综合命理的相关字段在根层。

## 摘要与完整导出

摘要咨询可以投影问题所需字段，减少返回体积。需要完整 JSON、全部时间线或完整文件时，首次调用就使用 `fields=null`，CLI 省略 `--fields`，保留默认响应预算；需要的快照也应在首次调用保留。

交付存储保存的是投影和快照选项处理后的结果。分页能够完整读取这份结果，不能恢复首次调用已经排除的字段。收到 `result_delivery` 后，读取同一 run 的资源或文件，按实际业务 `payload` 核对 SHA-256。不要为了补交全文重新计算，也不要把 `run_id` 当成永久保存所有历史输入和结果的数据库主键。

完整步骤、分页与本地保存示例见[完整结果交付与同次导出](agent-guide.md#完整结果交付与同次导出)。

## 状态与覆盖分开阅读

成功响应说明请求完成了相应处理，不能单凭 HTTP 200 或某个 `complete` 判断所有方法均已审查。以风水分层结果为例：

| 需要确认什么 | 阅读依据 | 不能据此推出什么 |
| --- | --- | --- |
| 哪些计算已完成 | 各层 `status`、`coverage` 和缺失输入 | 已选层完成不等于所有优先方法完成 |
| 现在能解释什么 | `analysis_progress.interpretation_status` 与实际事实、规则 | 仅有条件依据不能升级为已确认现场事实 |
| 候选动作能否落实 | 许可、物理可行性及相应行动状态 | `ready` 不认证现实效力，也不表示各方法全部有利 |
| 哪些内容没有支持 | `unsupported_queries`、限制和未覆盖项目 | 未读取、未计算、未覆盖与已确认否定是不同情况 |

`partial` 只限制对应层，其他已有依据仍可解释；未知事实也不能按否定事实处理。风水各字段的作用域与状态细则见[家居风水](fengshui.md)。其他工具按自己的输出合同解读，不强套风水状态名。

## 计算事实与解释

计算事实回答“按这些输入和这套实现算出了什么”。传统解释说明所选来源如何理解这些事实。现实建议则结合已知职责、预算、双方回应或现场条件讨论可以核对的安排。三者应能区分，不能把建议冒充引擎原结论。

规则分数不是现实成功概率，多体系描述相近也不是独立统计验证。数值可复现、规则有来源、测试通过与预测有效性分别说明。星历精度还需核对实际 `chart_profile.ephemeris_model` 与 `run_metadata.engine_is_approximate`，详见[算法覆盖矩阵](algorithm-coverage.md)。咨询的允许范围见[硬边界](../skills/_shared/safety-boundaries.md)。
