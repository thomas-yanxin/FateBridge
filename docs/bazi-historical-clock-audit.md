# 历史钟时、计算包络与固定秒偏移

同一时区名称、同一IANA版本，并不足以证明历史出生钟时已经确定。本轮比较了同版时区源码的两种官方编译策略，并修复固定秒偏移标签的输入往返缺口。来源标签、原失败和未决项均保留；这些工作不改变原典强弱公式，也不认证真实出生记录或现实预测。

## 显式转换表中的事件枚举

已加载的 TZif 显式转换表覆盖窗口时，钟时事件按转换时刻枚举，再由同一 `ZoneInfo` 对象核对前后偏移。表外窗口、无显式表或对象身份不符时保留原逐秒扫描，不改为粗采样，不自行展开 POSIX 尾部规则。文件身份变化仍返回来源错误，相同名称的另一对象不能借用索引。

冻结参考包含597个声明时区、40,556个显式转换时刻及10组单日／九日窗口。与原读取器及逐秒扫描的比较没有新增事件差异；这是同一时区政策下的完整性和性能检查，不认证历史钟表或未来法律。完整协议、首次失败与32项最终检查见本地材料 `validation/bazi-tzif-explicit-scan-v1/`；既有严格包络失败和浮点冲突未因此关闭。

## 历史数据的编译策略会改变结果

[IANA理论说明](https://data.iana.org/time-zones/tzdb/theory.html)以1970年后的时钟一致性划分地区名称，明确不保证完整复原各地的更早钟时。[2026e的backzone原文件](https://raw.githubusercontent.com/eggert/tz/2026e/backzone)也说明其资料范围和可靠性限制。因此，补入更多历史条目并不自动等于更准确，不能按某个已知命例的吻合程度挑选数据策略。

冻结协议（本地数据：`../tests/fixtures/bazi_historical_clock_profiles_v1/protocol.json`）使用同一份官方2026e源码、同一zic编译器及相同1898至2103年边界，分别编译标准数据与完整backzone数据。源码压缩包已按原散列核对；没有修改系统时区、全局编译器选择或共享服务。第一次未指定工具目录的make调用被本机Xcode许可状态拒绝，原日志保留；随后仅为该命令指定已安装CommandLineTools，完成官方生成规则。

完整差异参考（本地数据：`../tests/fixtures/bazi_historical_clock_profiles_v1/reference.json`）遍历冻结提供者清单的597个名称，在1900至2101年UTC支持区间逐一比较联合偏移分段：475个名称相同，122个名称存在差异。1,055个差异分段位于1970年前，701个位于其后；涉及后者的名称有15个。这些是模型差异分段，不能当成1,756次独立错误或新准确度样本。参考生成未导入FateBridge、dateutil或ZoneInfo。

此前预先选择阿姆斯特丹用于历史秒级偏移核对，但实际标准编译文件仅有0、3600、7200秒偏移，未包含预期类别。该分类失败被保留；另行登记蒙罗维亚1972年的2,670秒跳时，不能据此填掉阿姆斯特丹的历史资料缺口。标准与backzone模型在阿姆斯特丹1900年相差1,172秒，表明历史数据策略足以影响出生UTC与节令相对位置；本轮没有把任一模型自动宣布为历史事实。

## 保留计算失败，补齐验收关卡

四地区、顺逆两个方向的扩展参考（本地数据：`../tests/fixtures/bazi_dayun_future_clocks_v2/reference-summary.json`）已冻结116,906个事件，其中116,124个可判定、782个未决。新的固定几何下，所有已裁定分钟网格已含已知状态；因此该队列不计新增状态修复数量，完整应用回放仍在原进程运行。

补充蒙罗维亚的231例原执行回执（本地数据：`validation/bazi-dayun-monrovia-future-clocks-before-v1.json`）均保留已知状态及声明的跳时逆像，但14例安全距离来源参照超出了返回的有限包络。逐例根敏感性分类（本地数据：`validation/bazi-dayun-monrovia-root-sensitivity-v1.json`）核对全部1,617份原时间线：使用各探针实际消费的节令根时，独立整数公历算式全部一致；14例源包络失败随80或81微秒的根差而出现，同根安全探针均在实际包络内。这一诊断没有替换原来源标签或免除原门槛。

原执行器记录包络失败，却未将其纳入退出码条件。独立验收结果（本地数据：`validation/bazi-dayun-monrovia-future-clocks-acceptance-v1.json`）现按全部原门槛判为未通过，并返回退出码1；真实回执回归测试要求保留这14例。没有扩张用户输入范围、给包络加任意余量、放宽0.1秒数值门槛或修改节令根来消除失败。

## 固定偏移标签现在可精确往返

原解析器已可用十进制小时表达整秒固定偏移，却拒绝展示器生成的 `+00:19:32` 等标准标签。新增支持 `HH:MM:SS` 及 `UTC`／`GMT` 前缀，保留原15小时边界与分秒范围检查。例如 `UTC+00:19:32` 和 `GMT-00:44:30` 可作为明确的固定钟时输入，不再需要循环小数小时。

这项功能只处理调用者明确确认的固定偏移。它不会推定出生记录中的秒、推定历史时区政策，或将固定偏移当成某地完整时区历史；固定钟时在未来也维持该偏移，与IANA地区未来换时规则不同。

修改前的定向测试为10失败、7通过，修改后17项通过；覆盖正负秒偏移、往返、与原十进制固定钟时的出生UTC／本命／交运一致性，以及未知秒保留。三工具完整与严格出生钟时字段投影的REST、MCP、CLI一致性12项通过。首次测试误将八字命盘的嵌套字段写成顶层字段，4项测试失败原记录保留，随后改用实际合同路径 `bazi_birth.calendar_context.birth_time_input`。

冻结源码290项、基础依赖安装包51项、带Swiss星历文件38项通过。原典回归首次被新增日历参考触发全目录覆盖门槛；新版本登记表明确以散列登记这一无本命四柱标签的日历资料，保留旧登记表。25组349条、303个不同四柱和原26个不符结果均保持不变，没有通过改文件名绕开发现规则。

本地验收回执（本地数据：`validation/bazi-fixed-second-offset-local-v1.json`）绑定1,018个冻结运行源码／构建文件；归档索引（本地数据：`validation/bazi-historical-clock-v1-logs/artifact-index.json`）保存安装包、6份差异字节、首次失败与来源执行器，已实际重建全部文件并核对散列。旧时钟语义对照（本地数据：`validation/bazi-fixed-second-offset-legacy-v1.json`）核对11,427个标签，其中11,419个保持原时钟结果、8个保持拒绝；包括全部597个原命名时区及普通／紧凑／十进制偏移，每个有效标签比较四个UTC时刻。它证明此次输入扩展的旧语义兼容，不是新增历史准确度样本。

源码与安装包的全新stdio进程各完成13次有效调用、1次无效格式检查及182页同次结果散列核对；覆盖三工具、正负固定秒偏移、已知／未知出生秒与重复调用。另有三个独立安装包CLI命令通过。第一次stdio执行误只启用时运场景，未公开八字命盘工具，原错误保留；依据实际场景声明补充星盘场景后核对通过，没有重启共享MCP。当前成果是本地候选快照，不代表已部署共享MCP或发布包已更新；先前5次真实模型结果及判据绑定问题仍保留，没有新增模型运行。整体原典、解释及独立物理／历史验收继续保持未证明，不赋总分。
