# 太阳视黄经模型组成与严格包络差异

本轮进一步查明节气模型之间微小差异的具体来源，并让本地计算回执明确说明实际采用、尚未采用的模型项。没有为了匹配已暴露参考而删除计算项、调整偏移、放宽容差或改变原失败标签。最近一次完整原队列的54,818条严格包络失败、原40,219条证据及41项旧浮点边界冲突继续保留。

## 固定同一瞬间，逐因素核对

事前协议（本地数据：`validation/bazi-solar-model-layers-v1/protocol.json`）固定1899—2101年全部4,872个已有独立双段Skyfield节气点，以及TDB模型、太阳势光行差项、黄道框架、有限距离引力偏折四个因素。每个因素两个选择，完整计算16种组合，共77,952个角度值。参考点、DE440内核、原数值源码、组合与原判据均未更换。

生产使用完整ERFA Fairhead地心TDB模型，Skyfield 1.53的[时间实现](https://raw.githubusercontent.com/skyfielders/python-skyfield/1.53/skyfield/timelib.py)使用USNO Circular 179的短级数。两个模型在本批瞬间的TDB差异最大约9.036微秒。这只是数值模型比较，不是未来UTC或历史钟表误差界。

生产光行差实现保留[ERFA `ab` 的太阳势项](https://raw.githubusercontent.com/liberfa/erfa/master/src/ab.c)。该原始说明将其归于Klioner相对论模型，并给出约0.4微角秒量级。Skyfield 1.53的[光行差与偏折实现](https://raw.githubusercontent.com/skyfielders/python-skyfield/1.53/skyfield/relativity.py)采用不同组成；[太阳节气路径](https://raw.githubusercontent.com/skyfielders/python-skyfield/1.53/skyfield/almanac_east_asia.py)同时固定IAU2000B章动。两条路线的默认计算不能被假定为逐微秒相同。

下面每个因素均覆盖其他三个因素的全部组合，每行有38,976组成对比较，不把它们当作独立观测或预测样本。

| 因素切换 | 本批角度变化范围，微角秒 |
| --- | ---: |
| 完整Fairhead改为Skyfield短级数 | −0.222440至+0.380010 |
| 去掉太阳势光行差项，仅作诊断 | +0.390907至+0.418891 |
| 生产黄道框架改为Skyfield框架 | −0.140687至+0.031719 |
| 加入Skyfield默认三个天体的有限距离偏折 | −0.087994至+0.091779 |

当前生产组合与Skyfield的角度残差最大约0.698424微角秒。将四项全部换成Skyfield的组成后，残差最大约0.000205微角秒，接近本次浮点计算的表示量级；完整几何位置比较的最大差异约0.101毫米。它们支持模型组成的归因，不认证任何模型达到这些物理精度。单独替换某一项也未必更接近参考，全部正负方向和组合均保存。

角度残差另按局部角速度换算过线性化时间诊断，全部4,872点最大约16.835微秒；它不是重新求根结果。此前[根与钟时归因](bazi-root-clock-factorization-audit.md)的约16.069微秒是2,357个实际被消费根的求根差异，范围和量不同，不能混用。

## 独立数值复核和完整依赖

在全部4,872个原始上下文中，另调用原生ERFA复核光行差和地心TDB。事前固定的向量分量门槛为`1e-15`，TDB门槛为`1e-12`秒；两项均无失败，实测最大差异分别为`2.220446049250313e-16`及约`1.91645e-16`秒。原生比较回执（本地数据：`validation/bazi-solar-model-layers-v1/native-erfa-comparison-guarded.json.gz`）保留全部逐项记录。这证明对应实现的数值一致性，没有把超出模型作者1950—2050比较区间的数学相符升级为物理认证。

首次因素比较只守卫了529个第三方Python及扩展模块文件，未覆盖包内数据。补齐数据、动态库及元数据后的完整依赖协议（本地数据：`validation/bazi-solar-model-layers-v1/protocol-dependency-closed.json`）守卫1,055个文件，重新完成全量比较；全部4,872份原始上下文和角度结果精确相等。原生ERFA另用943个文件的运行前后守卫复放，全部记录同样相等。首次数据和不完整依赖收据继续保留。

完整因素结果（本地数据：`validation/bazi-solar-model-layers-v1/full-factorial-dependency-closed.json.gz`）包含两个TDB分支的原始向量、速度、距离、全部角度与有符号差量。首次运行曾只在进程内保留原始上下文，后来补写JSON并全量复放；数值结果保持相等。原生比较首次因NumPy标量不能直接序列化而未交付JSON，改为Python浮点后再运行，原程序和异常分别保存，容差未变。

## 本地回执增加的说明

`solar_model_details.apparent_direction_model`现在明确列出完整地心TDB、零观测者坐标、ERFA光行差、已包含太阳势项、IAU2006/P03岁差及IAU2000B章动，并将有限距离引力偏折标为`not_applied`。物理精度认证仍为`false`。命盘工具的路径位于`bazi_birth.calendar_context`，大运工具位于顶层`calendar_context`，二者遵守各自现有合同。

这是回执透明度的修改。删除新增回执成员后，修改前后的全部顶层抽象语法节点精确相同；所有数值函数、系数、求根、时间换算和默认选择保持。本地验证收据（本地数据：`validation/bazi-solar-model-layers-v1/local-report.json`）分别记录三端完整输出、严格投影、冻结验证及首败。没有将不含太阳势项的参考组合采用为生产算法，没有发布或重启共享MCP，也没有把上一轮安装包验证冒充本轮新包验收。

最终冻结检查31项通过，1,134个运行时文件及全部验证输入运行后散列保持，格式、导入顺序、类型及当前生成合同检查通过。首轮28项通过、3项失败：验证副本缺少原始节气参考，以及两项误用了命盘日历的顶层路径。补齐材料并按实际嵌套合同修正后重跑，生产数值和原断言目标没有改变。完整依赖文件、两版验证输入、原始异常与源码增量均归档；本轮不代表全仓回归或安装包验收。

原116,906条队列在另一套已冻结的状态修复内核上继续复放，未受本轮回执修改影响。现行23项原典分歧、原5例模型机械验收0/5和现实预测效度未验证的状态保持；新增数值比较没有产生盲测、整书符合度、现实预测准确率或综合满分。
