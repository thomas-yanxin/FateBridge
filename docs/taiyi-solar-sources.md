# 太乙节气来源、实际模型与冻结数据

月、日、时计的`solar_anchors`直接保存本次采用的节气对象。`boundary`负责换节或换遁；金钥匙日计及显式金钥匙时计另列`winter_origin`，负责冬至前甲子起元。默认至点时计没有独立冬至起元；年计也不补造未使用的太阳锚点。

`resolution_provider`表示接口来源，`ephemeris_model`表示实际轨道模型。原生Swiss接口在文件缺失时可使用Moshier，两者的provider都可能是`swisseph`。摘要增加实际换节／换遁模型及存在时的冬至起元模型；完整证据、已有TT点和钟面信息保存在`solar_anchors`，快照和导出使用同次值。两工具的`solar_anchors`视图仅用于已选择月／日／时计的请求。

| 实际返回 | 含义 |
| --- | --- |
| provider=`swisseph`，model=`swieph` | 原生接口使用Swiss压缩文件；仅此名称不证明具体数据版次或实测精度 |
| provider=`swisseph`，model=`moshier` | 原生接口使用内置Moshier解析模型 |
| provider=`jpl_de440`，model=`fatebridge_de440_solar_v1` | 使用声明的DE440太阳实现；其软件覆盖与精度仍按对应协议判断 |

其他配置按本次实际值读取；`solar_model_details.model_id`中的实现名称不能替代轨道模型字段。

节气对象日名按对象所标时区读取，不能代替`day_origin`或`hour_origin`中本盘所选钟面的日名。

## 一次实际的验证环境差异

V42临时快照缺少项目`ephe/`，503／504年实际采用Moshier。该年的两条至点比项目Swiss数据的结果约早1.23秒，而旧接口标签只记`swisseph`。V43在新计算前冻结实际项目37份Swiss数据，再通过独立调用原生C的`solcross`、`solcross_ut`核对，并对V42快照分别带数据／不带数据重放，确认差异来自模型选择。原V42失败和旧报告保持，不改预期凑合。

补齐数据后，503年冬至回到旧值附近；504年夏至仍有约10微秒的标签表示差异。这个微小差异和原1.2秒漂移分别保留，不能将旧整份相等断言冒作通过。

## 时间尺度与精度范围

Swiss官方[接口文档](https://www.astro.com/swisseph/swephprg.htm)区分TT与UT输入，并说明其1972年前民用时间接口使用UT1。FateBridge对1960—1971年另有声明的SOFA／IERS漂移UTC适配，不能将这段输出直接与Swiss旧式UT1标签作同口径比较。原生C两个接口还可有不同的ΔT选择；不能混用UT根、TT根和民用标签。官方[ΔT说明](https://www.astro.com/swisseph/swisseph.htm)也区分模型估计和历史／现代观测资料。

14个选定太阳点、两模型共28项控制比较TT根、反算TT及角度残差，既定数值容差分别为0.05秒、0.0002秒及0.000001度。它们与生产共享Swiss轨道模型，只认证所声明的计算一致性，不是28条独立观测、完整古历、古代亚秒精度或现实预测准确率。既有官方分钟历表验收和古历失败另列。
