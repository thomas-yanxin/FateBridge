# 宿曜现实预测：从草案到前瞻验收

当前真实样本为0，当前CLI生成的草案（本地数据：`validation/sukuyo-prospective-draft-v109.json`）未注册；历史草案（本地数据：`validation/sukuyo-prospective-draft.json`）原字节保留，其Schema未含后来已有的完整上下文绑定及逐例基线字段，不宜复制为当前模板。以下说明如何使用已有[配对工作流](../src/fatebridge/validation/sukuyo_study.py)，不新增现实成绩，也不改变历法、原典、解释忠实和现实预测四轴的原验收标准。单项研究需要明确事件定义；其结果只能检验该项假设，不能替换四轴完整目标。

[COS预注册说明](https://www.cos.io/initiatives/prereg)要求区分事前计划与看过数据后形成的假设；[OSF官方指南](https://help.osf.io/article/330-welcome-to-registrations)建议预先写清变量、排除规则、分析、判断条件及偏离计划的处理。本流程据此把待决事项放在登记之前，原始失败和偏离记录始终保留。

## 1. 先确定可观测事件及完整队列

在`target_definition`写明能由独立记录判断的事件、起止窗口、阳性条件及阴性所需的完整随访。不能用“很有缘”“感到准确”或宿名相性标签作为它自己的现实验证结果。事件未发生与没有取得结果记录分别处理。

`pairs`必须恰好覆盖`plan.cohort`，每人只出现一次；全部训练主体须在两层`training_subject_ids`一致声明。训练成员与测试成员不得重叠。招募来源、登记前排除及原因、失访处理写入`recruitment_and_exclusions`和`analysis_plan`；不能在看过预测或结局后删掉困难、弃权或不利配对。原完整队列保留在报告分母中，另交代它与预定招募人群的差别，不能把容易子集的结果推广到原目标。

另将知情同意、去标识化对应表保管方式、裁定人员职责及预测接触情况写入具名材料。`blind-sheet`不输出专门的出生资料、宿名、标签和概率字段，但会原样附上事件定义及裁定指导；交付前也须检查这些自由文本是否泄露预测。它不证明人员实际上没有获知预测。须事前规定参与者是否看到预测、如何记录意外揭盲或外部咨询；如这些信息影响行为，不能把观察到的关联直接认作独立预测能力或因果效应。

## 2. 在看到结局前冻结计算不确定性的处理

`calendar_rules`记录实际代码／依赖及历法政策，`classical_sources`记录具名版本、字页、校记和未决异文；`interpretation_policy`与`forecast_policy`分别冻结解释和概率产生方法。文件内容与指纹都要保留。

古代日界、桧尾半日、闰月复用与小月补配先后尚未定时，登记政策必须说明如何保留实际候选。不能以现代12点自动选原典半日，不能在见到结局后选中有利重建，也不能把候选数或传统相性分直接换成概率。若政策不能产生有依据的概率，原配对仍登记为显式弃权，保留原因及完整计算材料，不从队列中删掉。预先制定的候选汇总政策也须另有依据；把所有候选等权平均仍是一项需要声明和验证的假设。

概率映射、基线推导、样本量理由及分析方案分别写入现有`probability_mapping`、`baseline_derivation`、`sample_size_justification`、`analysis_plan`字段。当前没有已验证的宿曜概率映射；文档和软件不能替它填值。基线应预测同一事件和完整窗口，可用常数或逐例冻结记录，不能在测试结局上选择较弱参照。原最低样本、技能、覆盖及置信条件不因试运行失败而调低。

## 3. 完整方案先承诺，再签发预测

使用[命令行脚本](../scripts/sukuyo_blind_study.py)的`draft`取得当前Schema；该命令只产生未注册草案。Schema描述字段，完整配对覆盖、基线二选一等跨字段约束还须经过`SukuyoProtocol.model_validate`，不能只凭JSON Schema校验通过认作方案完备。每个输出路径必须尚不存在，失败文件及失败原因另存，不覆盖已有承诺。

顺序如下：

1. 在观察窗口开始前完成匿名队列、四类实际制品、模型、基线与全部指导文本。基线冻结不晚于计划登记时刻；`plan.interpretation_policy_sha256`须与实际同名制品一致，外部登记引用也须在最终计划指纹形成前确定。
2. 用`context --protocol … --output …`取得完整外层方案的`protocol_context_sha256`，在签发任何原始记录前写入`plan`并重新校验。它绑定配对、来源、假设及指导；不是整个计划的最终指纹。
3. 以`digest(StudyPlan.model_validate(plan).model_dump(mode="json"))`计算最终`study_plan_sha256`。原始预测和原始结局记录在各自签发时绑定这一值；原始JSON文件字节散列不能替代它。改变任何已承诺方案内容，都须保留旧方案及偏离记录，不为旧记录事后补签。
4. `register`核对模型和全部`--artifact NAME=PATH`实际字节。`registration_reference`及独立可信存证必须覆盖最终方案和承诺；本地`registered_at`与哈希不认证时间或预注册。若采用先分配登记地址、后补存制品的服务，须保留最终字节确已在观察窗口前冻结的回执，单有预留地址不够。
5. 在注册之后、窗口之前签发完整队列的预测。每条绑定模型、解释政策、完整计划和实际计算／解释证据。用`seal`及每案`--evidence CASE=PATH`封存，弃权也要材料。把最终注册和预测承诺交独立时间戳存证；软件不会代为执行这一外部动作。

命令均通过`uv run --locked --extra dev python scripts/sukuyo_blind_study.py <action> …`调用；`--help`列出`draft`、`context`、`register`、`seal`、`blind-sheet`、`evaluate`的实际参数。四类制品齐备和本地注册成功不代表真实研究已在外部登记。

## 4. 到期收齐结局，保留缺失与揭盲记录

从冻结注册生成`blind-sheet`，裁定者依据其事件定义、窗口和事前裁定指导记录结局。配对身份对应表、完整预测和概率分别保管。到完整窗口结束后再确认阴性；不能把失访填为未发生。每条实际结局来源保留原字节、引用、散列和记录时刻；未取得结局的case仍留在注册队列中。

运行`evaluate --registration … --sealed … --outcomes … --outcome-source CASE=PATH … --output …`。当前固定样本设计只允许事前声明的一次到期评价；不能反复查看后择机停止，或对同一测试结果调映射再称独立验证。偏离、撤回、记录更正与真实执行次数另行保留，不能删除首轮报告。

## 5. 分开报告数值、协议和现实证据

报告完整配对数、预测／弃权／缺失、覆盖率、模型与基线Brier、技能、区间、`protocol_blockers`以及各项门槛。保留负技能、空值和未通过；本地记录散列相符不证明结局真实、人员独立或盲法有效。

当前工作流还单独报告`confidence_bound_gate_met`及其具名配对有界方法。它依赖独立配对及原登记条件，不能单凭点准确率或一次通过宣布100%预测。人工记录为`synthetic`时，输出继续是`not_established_by_synthetic_data`；真实样本与后续独立复现尚未取得时，`authority_certified=false`。

本流程不回写旧计算门、完整180题、旧失败或原典争议；未来新研究结果与这些验收分别登记。当前没有填写真实预测、结局、登记引用或已校准概率。
