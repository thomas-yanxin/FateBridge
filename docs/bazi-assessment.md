# 八字旺衰与喜用的计算范围

[文档中心](README.md) · [API 参考](api-reference.md) · [算法状态](algorithm-status.md)

八字本命、九专题及双人分析共用领域计算。工程旺衰索引、原典力量裁定、根的存在、格局适用条件分别交付。规则索引没有成功概率含义。

离散十神、纳音、藏干、长生和原始关系层的有限第三方对照，见[八字离散规则与关系层核对](bazi-relations-audit.md)。相邻五合现在交付候选化神与“相合”，不再由字面配对直接断成“合化”；这项修复不代表完整成化、旺衰或喜忌已经验收。

来源条件层现含21项原页校读。新增1947年本PDF393页的“从儿不论身强弱，非身弱论也”完整语境，以及238页“日主之气不薄”前的独印、财官与连续生化条件；原页录文与旧编释分列。前者涉及从儿论法与身力的区别，后者没有给出工程支持占比阈值。本次没有据此改数值、补三档标签或撤销约束：原367条记录、321组输入、17组工程标签差异和2项禁止弱约束违规均保留，原典力量仍未验收。

## 当前旺衰算法

`day_master.engineering_index` 标明 `quantity_kind=uncalibrated_strength_policy_index`：`strength_level` 是既有预算和结构覆盖政策的工程档，`numerical_strength_level` 是纯数值阈值档。原有 `day_master.strength`／内部 `strength_level` 也表示该工程政策档；不是原典身强身弱的已定结论。工程参数、原始预算和既有评分没有因本次拆分重新校准。

`day_master.classical_adjudication` 由独立的[原典力量职责](../src/fatebridge/core/classical_force.py)提供，同次结果的 `force_components.classical_adjudication` 复用它。身、印、身印关系及普通扶抑适用性分别记录；未知为 `null`，`status=not_adjudicated`，并列待核前提。物理根位不等于有效根力，工程档不回填原典结果，登记命例标签也不参与这一计算。

`season_root_revelation_relations_v12` 按每个原柱的藏干预算、月支季相、透干、根损与关系状态计算。日干不为自己增加非日干预算；合局的合成预算不成为物理藏根。同一根参与多个关系时，保留最严格的剩余预算，不累加重复扣减。

季相按木火土金水的旺相休囚死区分；藏干分配、显干激活、合绊及冲刑系数属于明确的软件参数。当前算法使用同次关系前提重建精确有理账本，阈值比较采用原始精确数，显示舍入不改变判级。天干只实施唯一相邻且不涉及日干的合绊，保留物理干字与五行；不实施未裁定的局部成化算法。

工程政策档还会受到具名结构规则的覆盖。`threshold_arithmetic`、`structural_decision`、`root_qualifications` 与原始账本应一起读取，不能把数值档当作工程政策标签的全部理由。这些结构覆盖仍采用工程根保留门槛，不能仅因附有原典出处便升级为充分的原典力量裁定。十二长生是阶段查表；实际藏干、根位、根量和有效根力分别记录。

`structural_decision.method_id=source_root_capacity_priority_v3` 保留得令、合格根、同类会局、顺生路径和冬水无木根等既有工程覆盖；其数值与原有来源对照结果继续保留。这不构成通用充分判别法：1947年本另有寅月寅时甲木“木嫩气虚”的明确反例。身印承接、食财官负载、寒暖生长阶段及特定路径须另外核验，不能继续由根数或工程身印合量推出原典三档。

实现位于 [`strength.py`](../src/fatebridge/core/strength.py)、[`strength_thresholds.py`](../src/fatebridge/core/strength_thresholds.py) 和 [`elements.py`](../src/fatebridge/core/elements.py)。独立 Fraction 参考使用字面藏干、季相及预算等式；其关系成立条件仍是待核前提，不因此认证古典有效力量。

## 喜用分层与冲突

`structure_profile.resolution_policy=source_force_before_preference_v4` 保留月令参考、从儿等条件结构、扶抑、调候与通关观察。全局来源喜忌须先有原典力量和普通扶抑路径的适用结论。当前仍为 `assessment_status=not_adjudicated`，`useful_elements`／`avoid_elements` 为空、五行列在待定项；空数组不表示“没有有利元素”或已经排除互助。对外 `favorable_elements_status` 一并交付。部分投影缺少状态时不能从空数组补造结论。

`engineering_favorable_elements` 保留既有工程扶抑参考；`structure_profile.engineering_reference` 保留原有候选冲突消解后的工程方向。事业、财富与双人评分显式消费工程对象，维持原计算政策并标明未经现实校准；它们不能借工程方向宣称原典喜忌已经成立。来源层与工程层不互相回填，也不重算第二个原局。

读取 `formation_status`、`pending_conditions`、`conditional_elements` 和每层来源，区分已观察事实与尚未成立的方向。物理有根不证明根有足够作用，印多不证明日主承受能力，出现通关路径不证明实际流通。事业、财务、学习等专题保留当前计数和具名规则索引；不再输出退役评分分档。

## 专题中的计数与结构候选

事业结构与创业规则的 `score_kind=uncalibrated_rule_index` 表示未经现实校准的规则索引。`scope` 和 `score_basis` 列出范围、基准、加减与限制；`weighted_counts` 包含日支全部藏干。这些数值不测量实际能力、收入或创业成功率。

事业方向的 `dominant_ten_gods` 保留最高及第三位的全部并列，`primary_career_type` 同时列出最高权重对应的标签。`formation_status=heuristic_candidate_only`、`rule_signals` 和 `unverified_conditions` 区分共现线索与尚未验证的成格条件，不因计数靠前就宣称成格。

综合与九专题可用 `evidence_views.classical_routes` 的字段清单核对月令、星位节点及原典生克合路径。日期级专题的 `timing_context` 采用本地零点锚点；立春或其他交节当日的具体钟时须查相应时运结果，不能以零点代表全天。时间规则见[八字时运](bazi-timing.md)。

## 专题模块职责清查

`analysis` 包的12个实质模块及一行 `__init__.py` 已完整逐体审读，原有13个类、90个模块／类方法及6个嵌套判定函数。另完整审读初始根预算与工程旺衰两个模块，并核对两个共享元素计数定义；未宣称已审完整个 `utils/data.py`。删除健康计数转发及无生产调用的旧综合时运后，当前对应119个具名位置，其中解释包107个、共享职责12个。原范围内13组34项粗职责改为119组398项审查内容，补映85个此前未直接具名的定义。这里包含声明、参数、计数、条件规则、文化词典、工程指数、编排和展示，不能当作119种算法或398项精度通过。逐项位置和验收状态见[细粒度清单](algorithm-inventory.md)。

本轮独立读取 [6tail/lunar-python 固定提交的原始表](https://github.com/6tail/lunar-python/blob/1645ad3b3653635e5cb31b0c6df22b5e4298f8ce/lunar_python/util/LunarUtil.py)，使用其100项有向十神及12支有序藏干，另用精确有理数实现声明的“非日干1、每个藏干0.5”计数。60种日柱、60种变动柱与年／月／时三个位置构成10,800条形式输入，其中10,680种不同柱图；重复记录保留。这些是软件符号输入，不宣称每张都是历法上成立的出生盘。

原十神计数、前三位含同分及全部并列首位均与该参考一致；原派生 `strengths` 却有4,345条只保留第一项。现在从实际并列首位逐项传播说明，同一输入集和原门槛下无丢失，较低排名不混为首位。原始失败及输入完整保留；固定回归覆盖唯一首位、两项并列、七项并列和十项人工同分。比较核对十神身份、计数与信息传播，未认证项目性情词典、人格测量或预测效果。

婚姻专题复用已有红鸾、天喜、咸池、六合与六冲所有者，删除本模块的重复表；红鸾天喜仍按年支、咸池仍按日支，孤辰寡宿口径保持。1,728组形式输入的神煞、男口径时间柱、女口径时间柱共5,184份完整子输出与修复前一致。这个对照只验证重构保持行为，不是独立原典或婚期验收。

另行冻结12支的四位置完整组合20,736条，各位置按固定甲子序选取同性柱。仍使用第三方干支五行、藏干事实和精确有理数，仅核对声明的明干1、本气0.5、每个藏干0.3及原阈值。原实现有15,090条计数未正确舍入到其精确十进制量，51条寒暖文化标签和1条相对均量标签在边界分错档；这些是重叠的比较，不能相加为样本总数。原失败全部保留。

共享计数现在用整数十分单位累计，浮点消费者只在交付处除10。健康文化分类用整数差及交叉相乘保留原来的差3、均量1.8倍和0.4倍含等号门槛，不以容差补救比较。同一20,736条输入的计数和两种文化分类与原参考均无差异。这是工程公式算术验收，不认证寒暖、脏腑文化对应为临床体质或器官结论。

完整响应的源码／Python 3.10安装包比较还发现同一预算在14个复用字段中的末位差异。[Python 3.12更改了浮点 `sum`](https://docs.python.org/3.12/library/functions.html#sum)，而旧冲力代理先分配浮点藏干再求和。现在复用既有 `initial_hidden_budgets` 精确分配器，按有理预算求和后转换一次，删除重复份额表；原1e-9同量门槛、其余权重和原典未裁定状态保持。

独立有理参考仍保留全部20,736条形式输入，其中4,456条实际返回初始冲力事件，共11,152个单侧预算比较；16,280条无此类事件的输入不获数值通过信用。原源码有1,560条、原Python 3.10安装包有1,789条输入出现预算末位偏差；修复后源码无差异，原失败保留。全部20,736条的工程档、精确份额和结构优先分支未变。该对照以实际返回事件为条件，只验初始预算，不认证冲的解除条件、原典有效力量或预测。

支持量、抑制量、份额和扶抑比的摘要也改为复用原精确账本，在有理运算完成后转换一次。冻结的原408条算术输入与既有独立字面有理参考中，修复前源码329条、Python 3.10包336条的至少一个摘要量未正确舍入；修复后源码无差异。原参考、输入与失败保留，原典力量、关系前提和分档权重没有因此通过验收。

固定公开请求另核对了生产调用图。旧 `comprehensive_timing_analysis` 没有生产调用，当前综合时运使用共享出生上下文的 `build_current_timing_state`；已删除重复编排并修正旧来源引用。原立春前流年、未知性别保留独立时间层的断言迁至实际共享入口，原代码和输入保留在审查记录中；不为提高调用观察覆盖率而丢弃边界。

原26组完整请求在源码和新Python 3.10安装包中各执行77次实际协议调用；每环境及跨环境均只排除 `run_metadata` 后比较全部事实，全部一致。`analyze_destiny` 没有登记REST，按实际MCP／CLI两端核对；其他所选入口核对REST／新CLI进程／新stdio MCP进程。后补来源对照入口一组、两环境共6次调用，也保持完整一致；原26组输入和门槛未替换。

本轮已读职责包含102个可执行函数和17个声明类。固定公开请求观察到101个函数，原有墓库输入另观察到嵌套更新函数；这不证明全部分支已覆盖。相关1,123项回归、全源码类型与格式、文档及生成合同检查通过。四种固定算术比较在实际安装包中通过，元素与初始根预算共用的20,736条输入不能相加为独立样本。当前聊天的既有MCP进程和部署验收另列，未由这些本地新进程检查替代。

事业、财务、学习、子女、婚姻、双人和五维中的固定权重、基准与阈值已逐公式登记，仍属未经现实校准的工程政策。健康文化分档、人物外观／性情／行业／学科词典，以及年支／日支选锚的逐条原典核对继续未完成。服务内部说明同步当前实际计算范围；公开目录原本已有独立说明，本次没有改变公开工具或请求范围。

## 原典资料与未决范围

当前随包的 [`bazi-source-annotations.json`](../src/fatebridge/data/reference/bazi-source-annotations.json) 保留367条来源记录、321个字面输入；244条未提供明确日主三档，不能作为相符项。来源条件、书名、发行者、页码、原文锚点和编辑编释分别记录；古代四柱不认证现代公历、时区或人物身份。

当前来源审计原24组不同输入先修复GS12，再由v12修复六组，仍有17组与保留三档编释不符，另有2项集合约束违规及4项局部冲向分歧。两项集合违规分别为SJ05从儿不以身强弱论的适用域，以及QQ02官印承受能力未定；不据“非弱”任意选强或中和。3个原集合约束均纳入回执；`--require-full`在完整原典验收未成立时退出1。冲突和未知不改成通过，不以新字段数量增加独立命例信用。

这一分母继续比较原工程政策档与原标签，不因新增未知裁定而消失。审计另列 `classical_grade_comparison`：123条有三档来源的记录目前全部尚未由通用规则裁定，未决不计通过。17组已重新核对原页；“气馁”“弱中之旺”等语义疑点另行保留，不改冻结标签来降低分歧数。

本次单元8的[冻结清单](../tests/data/bazi_disagreement_review_v1/review.json)从公开随包来源选取17组差异与全部3项集合约束，逐条区分登记原文锚点、旧编释、版次页码和适用域。9组保留原登记锚点，11组另附既有公共条件校读的原文摘录（两者重叠）；合计16组有至少一种已登记原文，CX-04仅有旧编释与页码，逐字原句仍缺。未单独登记原句的字段保留 `null`，不把编释升级为逐字书证；旧记录缺少版次身份的项也保留缺项。本轮仅复用既有校读，没有新增独立原页校读或人工双读，未完成项不计通过。

三项集合约束单列：GH-07仅排除强，不补弱或中和；SJ05的“从儿不论身强弱，非身弱论也”首先涉及从儿论法适用域，保留原禁止弱失败但不据此赋强；QQ-02的“日主之气不薄”须连同独印逢生、财官与连续生化理解，不能由官印出现或身印合量推定承受能力。QQ-01“弱中之旺”、SP-02“气馁”及身重印轻／身轻印重的语义映射均保留旧标签和待裁定范围，不调整数值权重使其贴合标签。
