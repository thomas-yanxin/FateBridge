# 太乙与三式太阳模型的输入年及邻年节气

月、日、时计按已确认的民用输入年选择太阳模型，再以实际UTC瞬间比较节气。真太阳钟用于既定计数规则，不能用校正后跨年的钟面重新选择星历。跨时区时，本地1800年1月1日可以对应UTC1799年12月31日；本地2200年末也可以对应UTC2201年初。

在声明的1800—2200软件范围内，计算前一次大雪、冬至等边界需要邻年的节气。太乙现沿用共享历法的私有邻年机制：范围内输入可求紧邻一年的边界，来源仍由该输入年决定。邻年节气的`solar_model_details.adjacent_boundary_context_year`保留实际上下文。独立调用1799／2201全年节气，在显式DE440模式下仍按原范围拒绝；输入年在范围外也不因其UTC日期跨入范围而获得许可。

此前太乙分别把每个候选年当成独立全年请求。显式DE440在候选1799／2201处报范围错误，自动模式则可能将这些邻年切到原生Swiss。V44以固定18个端点钟面、5种月／日／时配置、两种钟面、两工具及auto／de440共720条软件控制重放；改前306条满足来源与根要求，414条不满足。修复保留全部分母和原1秒TT参考容差，积数及换遁公式未改。

首轮只修太乙后为605／720；合参余下失败来自奇门置闰年表。三式默认置闰年表使用原输入年的前大雪至次年立春窗口，覆盖太阳钟或晚子时跨年。取邻年节气沿用相同来源机制；派生历表只按本次实际取得的节气日期、日名缓存，在复用前仍经过共享历法的来源校验。置闰九日条件、十五日分段与定局表均保持。

来源观察同时保留实际校正钟面年、晚子时有效日年。民用年末跨入次年时，次年的来源／精度观察仍在，不能因年表已覆盖该日而删除；校正标签退入前一年时，也不再额外查询该标签的再前一年。所观察年份均按原民用输入年选模型；独立全年接口的原范围限制不变。首次固定两年观察窗遗漏既有跨年要求的失败及订正另留于验证记录，未改原测试。

参考为已经冻结的Skyfield／完整DE440独立方法输出，完整复用1799、1800、1801、2199、2200、2201六年144个节气根。两种选择策略共288项根控制与720条服务控制分开报告。它们共享DE440资料谱系，新增独立观测、有日期完整古例和实际模型解释评测均为0。

JPL官方[DE440／DE441论文摘要](https://ssd.jpl.nasa.gov/doc/de440_de441.html)列出原DE440的1550—2650覆盖；其[数据格式说明](https://ssd.jpl.nasa.gov/planets/eph_export.html)说明轨道以Chebyshev多项式保存、时间单位采用TDB。原始星历覆盖并不直接认证本项目打包实现、民用时标或完整古历。本轮维持已有软件范围，未增加历史时间精度或原典验收声明。

实际模型与时标字段见[来源说明](taiyi-solar-sources.md)，改前失败及最终验证见V44记录（本地数据：`validation/taiyi-jinjing-v44/README.md`）。
