# 主客生克出入：盘层、原文与保留差异

[玄空宅盘](fengshui-xuankong.md) · [有限解释](../skills/onda-fengshui/references/xuankong-interpretation.md) · [固定释义核验](../skills/onda-fengshui/references/calculation-reading.md) · [深度审计](fengshui-depth-audit.md)

`shen_2011_host_guest_v1@1.0.0` 为玄空解释增加明确的主客出入名称。默认不启用；它读取已经计算的三盘，分别比较地盘、运盘、山盘和向盘，保留另一项原文对照。相生、相克、出入和比和均不自动成为整体吉凶或现实事件预测。

此前已有的“山生向／向克山”等有序五行关系仍保留。新层补充的是某一宫、某一盘层谁为主、谁为客，不能把整盘一律当作山主，也不能用历史第六运的“六”替代某宫实际运星。

## 底本与署名

采用[《沈氏玄空学》整理本 PDF](https://www.vr-d.com/pdf-file/%E9%A3%8E%E6%B0%B4%2F%E6%B2%88%E6%B0%8F%E7%8E%84%E7%A9%BA%E5%AD%A6.pdf)，书内版本页标中央编译出版社2011年整理、2016年重印，ISBN978-7-5117-0801-4。这里固定的是所取得文件的身份，不新增出版社真伪认证。全文件 SHA-256 为 `b0c2a7af0a1b94f36cf1cc9f0d2ce4b65e8ea49bd793bc128b8fdc525b5ba847`。

| 来源 | 本次采用范围 | 署名限制 |
| --- | --- | --- |
| PDF901、909–910，《地理精纂·生克吉凶篇》 | 主客出入定义、盘层和旁六宫范围 | 篇内未署作者；“江阴杜振逵藏”的藏者不能作作者，也不改署沈竹礽 |
| PDF452–453，王则先谨按 | 论山山主、论向向主；保留另与运盘比较的口径 | 此按有具体署名；其吉凶评语与另篇并不全同 |

完整216条下卦生克句及七页定义图像在新增算法前冻结。首次提取遗漏30处字面“均”，修订只增加该语法；之后更正最初误取的PDF282为实际掌诀PDF283，216条句子未随计算结果修改。原始提取和修订记录均保留。冻结读稿 SHA-256 为 `4065bc975e47bfd583d302addfb55238177c2bce8a2546671abc73b3c54049a6`，224个文件的清单也单独固定；这不是独立专家盲审。

## 每个候选的八条关系

本版仅在实际坐山宫和向首宫赋予以下主客关系，各四条：

| 比较层 | 主 | 客 |
| --- | --- | --- |
| 地盘与运盘 | 该宫固定地盘数 | 该宫运星 |
| 运盘与山盘 | 该宫运星 | 该宫山星 |
| 运盘与向盘 | 该宫运星 | 该宫向星 |
| 坐山宫的山向二星 | 山星 | 向星 |
| 向首宫的山向二星 | 向星 | 山星 |

两宫以二十四山名字重新核对方向；旁六宫明确列为此版本不赋主客，中宫另外列为未覆盖。不是在九宫任意指定山主或向主。这里对替卦仅计算机械关系，不授予下卦原例的来源符合。

九星五行：1水，2／5／8土，3／4木，6／7金，9火。五黄在此仍为土，不借宫改变自身五行。

| 五行方向 | 名称 |
| --- | --- |
| 主生客 | 生出 |
| 客生主 | 生入 |
| 主克客 | 克出 |
| 客克主 | 克入 |
| 同五行 | 比和 |

这五个名称与王氏时令“旺生衰死”分开，不能把“生入”当作生气，或把“克出”直接改写成有利。原书不同篇按还有不同吉凶口径，本版不合并它们，也不提供81对专门断语。

## 原文不能靠逐例换基准配平

固定用 `axis_pair_as_defined_p453_p910` 比较每条下卦的山、向关系词：九运×二十四山×两个角色，共432槽。所有槽均保留：422吻合、6不同、4未定。两条原文都连续写了两个“山”、没有唯一“向”：七运辛山乙向PDF381、三运辰山戌向PDF399。它们各有两个无法唯一指派的角色槽，不能把第二个山自动改成向。

| 历史运与山向 | 比较角色 | 原文关系词 | 固定山向比较结果 | PDF页 |
| --- | --- | --- | --- | --- |
| 六运乾山巽向 | 向 | 克入 | 克出 | 317 |
| 四运坤山艮向 | 山 | 克入 | 生入 | 337 |
| 三运甲山庚向 | 向 | 生出 | 克出 | 427 |
| 九运甲山庚向 | 山 | 比和 | 克入 | 431 |
| 九运甲山庚向 | 向 | 克入 | 比和 | 431 |
| 六运壬山丙向 | 向 | 克入 | 生出 | 443 |

例如六运乾山巽向，东南向首宫向4木、山8土，向主克山客为克出；同宫运5土为主、向4木为客又是克入。原按确实另谈运盘比较，故原文“向克入”与前者不合，并不单独证明书中笔误。系统同时显示这两条计算；原文对照固定比较基准，不能为了逐行吻合改选后者。仅凭该句不能确定其采用哪个比较对象。

在独立的原书图数上重复同一比较，仍为422／6／4；说明这组差异不只来自当前程序排盘。它仍不证明各句原意已解决。完整关系词来源闸门继续为false，已有下卦顺逆、盘图和日时选局问题另行保留，不因81种机械关系通过而被清零。

## 请求与返回

在独立 `fengshui_xuankong_natal` 的 `interpretation`，或聚合入口 `fengshui_assess` 的 `xuankong.interpretation` 中显式选择：

```json
{
  "host_guest_ruleset_id": "shen_2011_host_guest_v1"
}
```

完整虚构请求见[示例文件](examples/fengshui-host-guest.json)。它未输入现实住宅事实，不补评价运；主客机械关系不要求先假定评价时令。

```bash
uv run --locked --extra dev fatebridge fengshui_xuankong_natal \
  --request-file docs/examples/fengshui-host-guest.json
```

MCP以同一JSON调用 `fengshui_xuankong_natal`；REST以相同JSON POST到 `/api/fengshui/xuankong_natal`。摘要可选择 `layers.xuankong_natal.interpretation.host_guest_analysis`、`coverage.natal_host_guest`、`rulesets`、`rule_trace`；读取固定释义需选顶层 `calculation_reading`。整包核验首次仍用 `fields=null`，并读取同run完整分页。

`axes.sitting/facing.relations` 中每项包含实际方向、主客盘层、星数、五行、名称及规则来源；`literal_clause_comparison` 保留原句、PDF页、字面标签、固定基准和差异状态。多宅盘候选各自返回，不能挑选较有利的一盘。没有实际宅盘时不补八条关系，也没有原文符合信用。

## 计算与释义分别校验

领域构建后及服务交付前都验证主客层。独立校验用冻结的25个五行定义格及原三盘重新核对角色、实际数字和方向，不调用关系构建器作为自己的预期。同五行换数、主客颠倒、用历史运代替宫位运星、改方向、把旁宫当主客宫或逐例改比较基准，均须返回 `fengshui_calculation_inconsistent`，非可重试，REST503、MCP错误、CLI退出1。即使关闭释义或只投影状态，错误也不能成为成功结果。

固定释义1.2.0对所选本版本增加每候选八段关系及两段原文对照。离线核验先检查这些事实，再核原run回执和全文；`host_guest_coverage_verified` 只表示八条关系与固定文本完整，原文差异／未定槽仍另计，不能变成全书符合。旧响应没有本层仍按旧事实核验，不追授主客覆盖；旧释义1.0／1.1也不取得新层文本覆盖。任意自由模型正文和现实预测仍未验证。

```bash
uv run --locked --extra dev pytest -q tests/test_fengshui_host_guest.py
uv run --locked --extra dev python scripts/audit_fengshui_sources.py \
  --output /tmp/fengshui-sources.json
```

来源审计应保留非零退出和全部未解项；不能把预期未通过改成工程故障，也不能通过删原句、改源值或缩分母取得全通过。

复采原文件可使用以下独立脚本。它不导入FateBridge，不覆盖已存在目录，也不会替换冻结验收读稿；新采集明确没有“算法前冻结”信用。本轮复采216条字面记录和223个图像散列均与冻结版相同，采集时间、脚本身份等元数据另留。

```bash
uv run --no-project --with pymupdf==1.26.5 python scripts/collect_fengshui_host_guest.py \
  --pdf /path/to/shen-modern.pdf --output /tmp/new-host-guest-capture
```
