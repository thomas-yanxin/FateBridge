# 紫微斗数：规则、计算证据与验收

[文档中心](README.md) · [能力覆盖](algorithm-coverage.md) · 机器审计结果（本地数据：`validation/ziwei-four-axes.json`）

FateBridge 把历法换算、指定文本的规则符合度、解释忠实度和现实预测效果分别验收。前一项通过，不能替后一项赋分。本页按规则与调用组织说明；各节对照数量属于具名版本，完整运行沿革见[历史记录](https://github.com/thomas-yanxin/FateBridge/blob/73ec8912677b2b687a4b11ccb06727332296e8e1/docs/ziwei.md)。这些结果不构成某位专家、某个机构或某部原典的认证。

当前持续目标是“算对历法、符合某部原典、解释忠于计算结果”三个专业维度。现实预测作为独立记录保留，不作为当前目标的完成门槛。三个专业维度仍须各自取得充分证据，不能用删掉预测要求把前三项的未完成部分算成满分。

四化表可独立显式选择：三个工具均接受`sihua_source`。默认`rule_profile`保留基础配置；`naj_ming_v1`只把四化表改为所列明刊原页，组合版本增加`+sihua.naj-ming-v1`，不表示切换成整部明刊算法。其他安星、亮度、岁序与目标时钟仍按基础配置及其已披露限制执行。

来源分别是 [iztro v2.5.8](https://github.com/SylarLong/iztro/tree/2.5.8) 与[《紫微斗数全书》卷二固定在线转录版本 oldid=1963110](https://zh.wikisource.org/w/index.php?oldid=1963110)，并参照所列明刊书影校核。转录“安身命例”写闰正月在二月内起安身命，“安禄权科忌四星变化诀”写壬干为“梁紫府武”。摘录配置还选择亮度表、长生方向、旬空双支与部分年度流曜，1.3.0 再采用邻宫起大限、火铃年支定点读法，详见第八轮。这不等于完整刻本配置；未覆盖项仍有软件回退，明刊四化、身主和亮度疑文继续分别保留。有效月序也用于月系安星，但安身命闰月条文不能认证全部月系规则。

已保留的疑点包括：魁钺口诀“丙丁猪狗位”与软件基线不同；木三局转录图疑有重复初九、缺初五；杂曜、庙旺、格局和完整运限断语没有完成指定版本的逐条审查。不能用当前程序输出倒改原文，再声称原典一致。不同配置可以比较真实差异，不能按已知事件挑出“较准”的盘后再报告命中。

三个工具 `ziwei_birth`、`ziwei_horoscope`、`ziwei_rules` 共用 `rule_profile`。运限从本命盘携带同一配置，动态四化和对应星位连接复用所选的四化表，这是软件约定。摘录的闰月条文约束本命安身命，不足以证明目标流月也应全月顺延，因此目标流月闰月仍保留软件半月规则，并在 `ruleset.target_leap_month_rule` 明示。结果 `ruleset` 给出版本、来源、覆盖范围和未解决事项；本命 `rule_trace` 给出安命身、五虎遁纳音局、紫微天府定位等步骤的输入输出。生年年干按农历正月初一；出生真太阳时和晚子时沿用明确的工程约定，不能假称这已被原典或历表认证。

  --fields analysis_context birth_context ziwei_horoscope.ruleset ziwei_horoscope.scopes \

MCP 的真实参数及首轮字段分别见生成的 [本命合同](contracts/ziwei_birth.json)、[运限合同](contracts/ziwei_horoscope.json)、[规则合同](contracts/ziwei_rules.json)。REST 使用相同 JSON 请求字段；`fields`、`strict_fields` 和 `include_snapshot_text` 是查询参数。数组按整个字段读取，不能用数字索引或 `scopes.流年` 投影。完整 JSON 首次使用 `fields=null`，从该 run 的 `result_delivery` 读取超长结果。

## 排盘规则与解释条件

### 确定性计算与边界

- 性别未知不再被当成某个顺逆方向。本命星位仍可计算，大限方向标为未定、年龄范围为空；六层运限需要明确性别，缺失则返回输入错误。
- 无法识别命宫纳音时明确报错，不再回退木三局。
- 运限校验目标的实际钟表时刻，不只比较农历年；同年但出生前的目标也会被拒绝。目标 `target_minute` 默认 0、`target_timezone` 默认 `Asia/Shanghai`，与出生时区独立；夏令时不存在或重复的钟时需消除歧义。
- 闰月使用统一的有效月序；闰十二月顺延时保留月序 13，地支运算模 12，月干运算模 10，避免提前归一化丢掉月干信息。这是合成规则边界用例，不声称支持区间内真的出现了闰十二月。
- 未起正式大限时，大限槽位标记 `status=not_started`，宫位、宫干及四化为空；童限单列，不拿童限宫生成大限四化。六个层级槽位仍在，不能称六层都已计算。

这些修改没有用修改参考期望值的方法消除与原有 iztro 运限参考的差异；既有比较继续独立运行。当前另冻结 1,080 张本命软件参考盘，核对 71,280 条星曜记录、25,920 个长生／博士宫位标记及命身、五行局、大限、命主身主；原有 18 个运限用例继续核对六层落宫与四化。此前文档的“400 组”未在当前资料中复现，不能作为验收数字。整盘软件比较仍不证明软件本身、原典或现实预测正确。

### 深度结构与解释链路

本命首轮用已发布的 `evidence_views.natal`：`reading_view` 保留全部 66 种星名及其实际落点、非空亮度／四化、十二宫干支、大限和循环标记。软件配置为 66 条落点，摘录配置自 1.2.0 起的旬空列两支，为 67 条落点；`distinct_star_count` 与 `star_occurrence_count` 分开。三方四正以地支引用连接，避免四次重复星曜明细导致默认 MCP 预算只剩分页回执。`null_star_fields_omitted` 明确省略的亮度／四化字段在完整宫位中为 `null`，不能解释成另有数值或规则。`major_stars=[]` 表示没有十四主星，仍需读同项全部 `stars`。该视图对全部 1,080 张软件参考盘还原星曜事实后独立比较；完整 `palaces` 继续提供全部展开证据，`evidence_views.structure` 用于明确结构问题，`rules` 用于规则轨迹。没有通过增大响应预算或删星解决首轮超长。

`ziwei_birth.palaces[].structural_evidence` 计算本宫、两个三合宫、对宫及其中的实际本命星位。`major_stars` 仅含十四主星；`is_empty_main_palace=true` 不是“宫中无星”。对宫星曜只作为对宫事实返回，不搬移、复制为本宫星。

`ziwei_horoscope.scopes[].palace_map` 提供该层全部十二个功能宫名，分别标注 `scope_palace_name`、`branch`、`natal_palace_name`、`natal_palace_ganzhi` 和 `natal_stars_detail`。本命星位和本命宫干仍保持原身份；这不是全部流曜、运限宫干重排或飞宫四化体系。

`mutagen_natal_links` 把每层四化连接到计算所得本命星位，并另外标注该星位在本层的 `scope_palace_name`。例如固定测试中，2027 年天机化科关联本命官禄，但该位置在流年功能映射中是夫妻宫；不能把它改写为“流年官禄化科，所以会晋升”。`stem_origin` 说明四化使用的是所临本命宫干、目标农历年干、月序五虎遁月干，还是目标日／时柱天干，避免把 `palace_ganzhi` 当成各层相同的天干来源。

这些结构可以支持更准确的有据解释，但尚未完成真实模型的独立盲评。星位、规则表、原文象意、现代职业或关系建议、现实预测是不同对象。只有读取到的计算连接才可称为返回事实；原典解释需逐条标注适用条件，不能把单星象意扩展成已验证事件规律。

### 整盘与原文表格核对

本轮增加 1,080 张独立软件参考盘（本地数据：`../tests/fixtures/ziwei_independent/natal_manifest.json`），生成器只调用独立安装的 `iztro@2.5.8`，记录 npm SHA-512 integrity、版本来源和全部输入；不导入 FateBridge，不按对照结果删除用例。npm 元数据没有提供 `gitHead`，清单保留空值，不据标签虚构发布提交。输入覆盖完整六十甲子年与时辰、全月／时辰组合、四个闰月的前后半月、历史历法和晚子时边界。已有星曜落宫／亮度／四化没有比较差异，确认缺项是天空、截路、空亡，现已补齐。天空不等于地空，截路／空亡也不等于旬空。

十二长生与博士十二神按各自规则独立计算。默认软件口径长生按阳男阴女顺、阴男阳女逆；所选原文写男顺女逆，因此阴年男命等输入会不同。博士仍按年阴阳和男女决定方向。第二轮当时将未知性别的两套循环全部留空；第十一轮改为保留两方向相同的标记，剩余位置仍未定。`changsheng12` / `boshi12` 是传统循环名称，包含“病”“死”等名目不表示临床状态或寿命判断。博士飞廉和年支蜚廉在不同层，不合并成一颗星。

命主按命宫地支，身主按出生年支；`chart_masters` 连回实际本命星位。原文安身主子午写“火玲”，没有书影裁定，摘录配置在此明确保留软件火星并标 `software_fallback_ambiguous_fire_ling_text`，不能把它引作无争议的原文裁定。

`quanshu_v2_excerpt` 1.1.0 按[固定卷二原文](https://zh.wikisource.org/w/index.php?title=紫微斗數全書/卷二&oldid=1963110)的“十二宫庙旺落陷表”核对全部 **240 个已给出单元格**，包括禄存的八个落支。表中未列出的星／支组合保留空值。酉宫太阳平、太阴旺、七杀旺与旧软件的陷、不、庙不同；[iztro 后续发布记录](https://github.com/SylarLong/iztro/releases/tag/v2.6.1)也明确修正了这三项。默认 `iztro_2_5_8` 为保持明确版本的兼容性保留旧值，不能把它称为最新上游或原典表格。表格与同卷散文另有矛盾，例如太阴寅宫表称旺、散文称庙；本配置明确选择表格，保留分歧，不据程序结果反改原文。相关资料及哈希见新增摘录清单（本地数据：`../tests/fixtures/ziwei_independent/additional_manifest.json`）。

流年 `flowing_stars` 新增禄存、擎羊、陀罗。所选原文的己丑年例明确流禄午、流羊未、流陀巳；实现按目标年干取位，再标明本层功能宫和所叠本命宫。本命星位不随流曜改写，其他层未返回全部流曜时仍属未计算。

解释事实可复用[同 run 结构化引用核验](prediction-validation.md#同次结果引用核验)：真实回执上的“年度天机所在本层夫妻宫”可以验证，篡改为本层官禄、换来源表或改业务结果会被拒绝。这仅验证引文值、类型与回执一致，不认证自由文本推论。新增回归使用真实计算回执，未伪造已验证的模型解读或现实结果。

本轮修改在本地源码工作区验证，未发布到 PyPI 或部署。原典仍为部分摘录符合；现实预测仍没有独立前瞻队列。已有[可证伪预测评估流程](prediction-validation.md#可证伪的现实预测评估)可用于真实登记数据，但不能把流程示例、事后命例或上述软件参考盘计入现实准确率。

### 双支旬空、流曜分层与书影校勘

摘录配置升级到 **1.2.0**；软件兼容配置保留 1.1.0 的计算口径。原文“安旬中空亡诀”明确列出每旬两支，因此摘录配置现在在两个实际宫位均列旬空，不能继续用软件按年干阴阳只取一支的规则冒充原文。`void_systems.xun` 同时交代原文两支、实际显示支和所选规则；六十甲子的 60 组推导检查分别核对，来源仍只有六个独立旬空对，不把重复年例算成新增原文。

“天德、月德”条文的输入是流年太岁，不是出生年。摘录配置的年度 `flowing_stars` 在禄存、擎羊、陀罗之外增加天德、月德、丧门、吊客、白虎、官府，共九项，并保留 `system_id` 和本层／本命两种宫位身份。十二年支共 72 个新增流曜位置按独立手列原文向量核对。本命月德、博士官府和年度同名标记仍属于各自系统，不能相互填补或搬星。

飞天三杀的所选条文给出三个星名和三个地支集合，未明确逐名一一配对。`annual_three_sha` 返回集合及 `individual_name_positions=null`，没有据列举顺序编造每颗位置，也不借博士将军、奏书补上流年位置。

古今同名需按原条文辨认：“天空地劫诀”中按生时逆行的天空，对应现用星名地空；软件另列年支顺一位的天空是另一项。该卷按本生年逆排的解神对应年解，不能拿软件月系解神替代。`void_systems.source_name_mapping` 明示这些映射。

`symbolic_properties` 增加 16 颗星的原文属性、实际本命落宫、亮度与四化连接，`calculation_path` 指向同次本命事实。武曲原文“化财”、天相“化印”、七杀“遇帝为权”等文字不等于本命禄权科忌赋值；例如甲年武曲本命标记仍为化科。天同“水金”、七杀“火金”、贪狼“水木”以 `elements_as_written` 保留原字，不据常见单五行简表自动改书。原文引句与现代事件预测分开。`evidence_views.symbolism` 用于读取该层，`voids` 用于空亡口径；超长仍读取同 run 分页。60 张盘的 960 个属性到本命星位连接均逐项核对，该数字是连接检查数，独立属性来源记录仍为 16 条。

已冻结[日本国立公文书馆明刊本](https://www.digital.archives.go.jp/file/1078787)第一册的六帧官方书影及 IIIF 清单，见校勘资料（本地数据：`../tests/fixtures/ziwei_independent/naj_ming/collation.json`）。其安星章节属于刊本卷三，不能把在线转录“卷二”当成这个刊本的原卷次。第 75 帧“安天魁天钺诀”读作马虎、猪鸡，与现有软件魁钺表相合，与固定转录的虎马、猪狗不同；20 个独立位置在两配置中各核对一次，不能计成 40 个独立来源。第 80 帧明确列旬空两支；第 82—83 帧的五行字样用于属性交叉核对，完整引句仍标在线转录出处。第 81 帧身主作“子午人火鈴星”，字形有了书影依据，但仍不足以决定应单取火星还是铃星，软件回退继续明确标记。当前是单读者的部分校勘，不是整部七卷本或独立双重审定。

历法新增 [NASA 原始朔望表](https://eclipse.gsfc.nasa.gov/phase/phases1801.html)，按公布的 UT 时刻加八小时建立民用日边界，覆盖 1900-01-31 至 1900-12-31 的 **335 个农历日数**，无差异；12 次朔最接近午夜仍相距 70 分钟。解析器只读取固定宽度的新月列，1901 年首行只有其他月相时不会误读成朔。此项只验证日数，未把它提升为月份编号、闰月、农历年、历史地方时或全部太阳时修正的认证。原始页面和哈希见朔望清单（本地数据：`../tests/fixtures/ziwei_independent/phase_manifest.json`），与 HKO 完整日期分母分开报告。

真实模型盲测已准备五个隔离题目与预先写定的人工判据，覆盖文本化义／四化、旬空双支、多五行、年度德曜与三杀缺项，位于评测集（本地数据：`../tests/fixtures/agent_behavior/cases.json`）。未运行的模型会话不记为通过，程序核验仍不能替代自由文本语义评审。

### 明刊四化异文与当前盘的分离

在[日本国立公文书馆第一册书影](https://www.digital.archives.go.jp/item/4468520)卷三“安禄权科忌四星变化诀”中，第 76 帧庚年刻作“日武同相”，而当前两个配置均为太阳化禄、武曲化权、太阴化科、天同化忌。按这个刊本的字面，后两项是天同化科、天相化忌。不能因为版本同名就把当前盘称为已经符合该明刊本，也没有据常见现代口诀擅自改刻本文字。壬年“梁紫府武”则与当前摘录配置相合，与软件配置的左辅化科不同。

### 区分排盘日期与民用历法日期

新增 `calendar_basis` 回执与两个工具的 `evidence_views.calendar`。本命同时列出输入钟表时间、校正后的排盘标签、二者相差日数、各自日期查表所得农历，以及同一物理时刻转换到固定 UTC+08 后的参考日期／农历。运限分别列 `birth`、`target`，并原样说明现有岁序公式；首次摘要的 `analysis_context` / `birth_context` 保留简短的 `lunar_date_basis` 与 `calendar_date_shift_days`，无需重算整盘即可发现跨日。

香港天文台明示农历年干支在正月初一香港标准时间零时交替，历法表也按民用日期发布；真太阳时是另一种时钟，不能据民用日期表无差异就宣布真太阳排盘约定得到认证。[天文台岁首说明](https://www.weather.gov.hk/tc/education/astronomy-and-time/time-service/00506-what-year-is-it-today.html)、[授时术语](https://www.hko.gov.hk/tc/gts/time/item_list.htm)、[公农历表及未来临近午夜的不确定日期](https://www.hko.gov.hk/tc/gts/time/conversion.htm)分别提供相应来源。回执的 `date_lookup_convention` 明示现行程序是日期表查询，没有在外国时区重新编算朔日；`reference_lunar_date` 才对应同一实际时刻的固定 UTC+08 日期查询。零时换日属于当前实现，不是明刊原典时钟制度已获证明；`classical_clock_rule_verified=false`。

例如人工测试输入 **1984-02-01 23:55，Asia/Shanghai，东经150度，启用真太阳时**：钟表日期为农历癸亥年腊月三十，排盘标签已跨至次日，采用甲子年正月初一。回执同时保留两者，本命实际年干、星位仍来自排盘农历，不能把钟表参考值替换成当前盘面。节气继续按输入所代表的物理时刻判断，不能再把校正后的太阳时标签当成另一个民用时刻查节气。

另复现了一个**尚未解决**的年龄边界：上述输入在同日23:59查看运限，实际晚于出生，但现有“目标钟表农历年－出生排盘农历年＋1”得到0。现在明确返回日期口径边界暂不支持，区别于实际早于出生的拒绝；没有钳成虚岁1、改掉出生年或把更准确的错误说明算成年龄计算修复。此范围仍阻止完整历法验收。正常输出仍沿用原计算和规则版本；回执版本为 `ziwei_calendar_basis_v1`。

冻结边界输入与来源（本地数据：`../tests/fixtures/ziwei_independent/clock_manifest.json`）含春节、入闰／出闰双向跨日、同日对照和两个外国民用时区，九组输入在两配置下产生十八份回执。农历期待值读取独立冻结的 HKO 原始单元格，不从实际盘面反推；日期、物理参考时刻、农历与真实盘面连接分别核对。错误参考日期及被篡改来源均须被检查检出。该批只验证日期依据是否忠实交付，不认证所有时区、均时差数值精度、原典时钟选择或年龄边界。

### 明确重复钟时对应的实际瞬间

`ziwei_birth`与`ziwei_horoscope`接受可选`birth_utc_offset`；运限另接受`target_utc_offset`。偏移须匹配出生／目标命名时区在给定钟时的真实规则，只用于选择或核对民用瞬间，不替换时区。格式`±HH:MM`或`±HH:MM:SS`；省略时重复钟时仍拒绝，不存在的钟时即使附偏移也拒绝。没有出生记录支持时不能为用户猜选偏移。

例如上海1991-09-15 01:30在回拨前后各出现一次：`+09:00`对应1991-09-14 16:30 UTC，`+08:00`对应17:30 UTC。给定东经120度、真太阳时开启，实际校正约为00:34与01:34，当前时支分别为子与丑。两次均时差按各自UTC瞬间重新计算，不复制第一次数值或按一小时整数强行平移；民用模式则保留同一个01:30标签与不同瞬间。这里的秒数为程序计算结果，不是出生记录精度或独立天文验证值。

`calendar_basis.civil_clock`保留实际偏移、fold、UTC瞬间、时区数据版本和TZif指纹；首次出生／目标上下文同时保留`civil_instant_utc`与`civil_utc_offset`，正文快照同步说明。太阳校正后的标签保持无时区语义，不能据它重查民用偏移或判断出生先后。运限比较统一转换UTC，因此回拨前01:40出生、回拨后01:20查看仍可计算；反过来则拒绝，即使目标钟面较大。

### 现实预测需要怎样的实验

在观察结果前固定任务、规则配置、算法版本、出生资料质量、预测时间窗和可核验结果定义；建立时间戳及内容哈希，禁止随访后修改预测。研究对象知情同意，出生资料与结果判定分离保存；结果判定者看不到命盘与预测。不能为了凑样本编造事件，也不能把名人传记的事后解释当成前瞻预测。

预注册主指标、样本量与排除条件。二元结果有概率预测时可比较 Brier score、校准与基准概率；只给类别的模型按固定标签比较准确率及混淆矩阵。至少同时报告基础发生率基准、仅用现实条件的基准和紫微方案，保留全体参与者、失败、弃权和失访的分母。按参与者隔离训练与留出集，多假设比较和不确定区间提前约定。不能用星曜规则分数替代概率或用合成规则用例代替真实结果。

最后还需在未参与调参的新样本上独立复现。即便某个具体任务的留出样本达到零错误，也只能报告该任务、样本量与区间，不能推导为对所有人、所有未来事件都满分或“最权威”。本轮没有这些现实结果，因而不会通过该项验收。
