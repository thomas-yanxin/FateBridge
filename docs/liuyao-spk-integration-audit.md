# 六爻：SPK 接入、未使用来源与同次结果证据

本轮基于第二十七轮的封存源，采用单独捕获的显式 SPK 太阳后端及必要缓存策略，修复非天文查文被星历回执拖垮的问题。规则计算、月破临日裁决、静态原文和民用日期窗口算法维持父源字节。运行包与当前整个工作树分别验收；未发布、未部署。

验收结束时观察到并行工作线新增打包 DE440 默认路径，触发了整文件一致性检查。新改动及裁决记录（本地数据：`validation/liuyao-v28/live-drift-adjudication.json`）单独保存，既有未使用来源回执意图仍保留。本轮测试与恢复包保持封存版本；本文的默认近界失败指该封存配置，后续并行默认版本另行验收。

## 计算与查文分别记录实际来源

配置 `FATEBRIDGE_SOLAR_TERM_MODEL=spk` 且星历文件缺失时，原先 `gua_lookup` 查询乾卦原文也会在制作回执时打开文件，实际 CLI 返回可重试的 500。查文结果不需要太阳交点，这项依赖由回执引入。

修复后，回执先读取未投影的业务结果来源。结果没有实际 SPK 来源时，只记录配置及 `source_resolution=not_observed_in_business_output`，不打开文件、不填写已使用模型或内核哈希。实际使用 SPK 的计算仍核对所选文件，缺失、损坏、越界、计算期间改变均不得用近似模型掩盖。显式配置错误也不能阻止纯原文查询；实际天文计算仍按原有严格模式检查配置。

## 保留近界失败，另验显式 SPK 路径

输入为 `1972-12-07 00:18:43.043390 UTC`，乾卦静卦、四爻、`timing_days=0`。既有 DE440 大雪参考是 `2441658.5134980883 TT`，输入比交界早约 7 毫秒，应为亥月。第二十七轮的原生和默认解析路径都取子月；解析路径的时间误差约 −0.014886 秒，虽通过原 1 秒 TT 门槛，精确月标签仍失败。

本轮实际 REST、原生 MCP、CLI 完整输出均为亥月；大雪交点与该参考在当前 JD 网格相等。月界的 `start_term`、`next_term` 及回执记录 `fatebridge_jpl_spk_solar_v1`，并记录内核 SHA-256 `a4ce9bf9b3282becc9f4b2ac3cebe03a2ae7599981aabd7265fd8482fff7c4b5`。未运行原生探针时不生成比较字段，不能假称两模型一致。严格投影和同次分页原文恢复另列工程测试。实际控制台进程（本地数据：`validation/liuyao-v28/os-cli-summary.json`）也在仓库外目录完成修复后查文与起卦，安装源逐字节核对后再调用；命令前缀漏写的启动失败单独保留。

另对既有近界结果进行判词核对（本地数据：`validation/liuyao-v28/near-boundary-fidelity.json`）：四爻午在新亥月下不再被标为原月破，快照从“月令层月破”随之改为“月令层休囚”。这是实现后的同例核对，读取层级选择错误的一次检查中止也保留，不能当作额外盲样本或模型解释通过。

这是一条显式选择的不同模型路径。原生 Moshier 的 501 个超差点、默认路径的近界失败和所有原始记录继续有效，不能改称“已修复原生 501 点”。该输入及四个既有分钟案例为已知问题复验，不是盲样本。

## 权威资料与比较范围

实现核对 [NAIF SPK Required Reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/spk.html) 中的 Type 2、段优先级、坐标框架及光行时处理。后端只读原始状态向量；参考交点不随运行包发布。文件类型、J2000 框架、实际覆盖、TT→TDB、光行时、岁差章动及实际依赖版本分别可追溯。

原始 4,872 个交点继续按 1 秒 TT 门槛验收，另复跑已声明 1800–2200 年的全部 9,624 个交点。原 501 点单独按原身份追踪，不改变分母、时间尺度或容差。两套参考有重合，不能把两者相加算独立样本。参考与运行路径共用 DE440 和 jplephem 读层；接近参考的数值误差不构成独立的物理观测或绝对精度认证。历史 UT1 约定及未来闰秒假设仍须随结果保留。
