# 人类图十进制时区与亚秒时刻复核

本轮修复两条会改变实际计算瞬间的路径：十进制小时偏移提前舍入到整秒，以及亚秒UTC偏移在原生进程传输、周期输入和解释重放时丢失。原典目录、解释规则及38项专业要求保持原样。完整证据、失败记录、安装包和验证范围见复核报告（本地数据：`validation/human-design-decimal-offset-verification.json`）。

原时区解析器先转为二进制浮点数，再将偏移取整秒。例如`0.00001`小时应为36毫秒，`5.50001`小时应为5小时30分0.036秒；原实现均丢失亚秒部分。`1.23456789`小时还丢失约0.444404秒。修改前先冻结24个输入与独立参考，覆盖正负偏移、9微秒、±15小时边界、历史UTC漂移、世纪闰年和UTC跨年至1799／2400；原24个输入全部保留。原结果只有6个UTC标签准确，11个通过原0.0002秒时标门槛；修复后均为24个通过。这里的24项是预先固定的有限工程案例，不是总体精度或预测成功率。

实际影响不限于显示时间：冻结的1976-03-14当地16:20:59、`-0.00001`小时虚构输入中，修正36毫秒后，设计地球由12.6变为15.1，对应通道的设计侧完整标记也改变。这是同一引擎在正确输入时刻的回归差异，不是新增独立黄经真值。另作修改后的因果复验：将旧的错误UTC瞬间用明确整秒偏移输入新代码，24份完整业务结果均与旧回执一致，只排除运行元数据及两处原始时区输入回显；六个未受影响的原控制案例则无需替换输入即可完整一致。

独立参考使用十进制／整数日历运算及未修改的[IAU SOFA 2023-10-11 C源码](https://www.iausofa.org/2023-10-11c)。1960年前只核对历史UT1约定的公历日，不认证独立Delta T或物理TT。1960年以后核对UTC→TAI→TT；2040和2400年的SOFA未来警告仍保留，不能据此宣称已知未来闰秒。生产代码修改前已保存参考及散列；后加的[维护生成器](../scripts/build_human_design_decimal_offset_reference.py)须复现相同参考字节，普通测试不编译或下载。主机编译器因Xcode许可状态不可用的失败也保留；实际独立编译和复现检查在无网络Linux容器中完成，没有修改主机许可配置。

解析现在精确处理十进制小时，在最终生成Python时区时按最近微秒、平局取偶量化。只有确实发生量化时，`clock_evidence.timezone_rules`增加`decimal_hour_rounding=nearest_microsecond_ties_even`、`offset_resolution_seconds=0.000001`和`rounding_error_bound_seconds=0.0000005`，数值均为十进制字符串。该0.5微秒是输入偏移量化上界，不是星历或出生记录精度；原0.0002秒验收门槛不改。显式偏移仍限±15小时，先按精确数值检查范围，`15.00000000000000001`不会再因浮点舍入而被当作15小时接受。IANA历史规则不套用这一显式输入限制。

初版修复曾错误要求所有十进制偏移必须恰好表示为整数微秒，导致原有29个Astrodice案例失败，也遗漏六种Unicode数字别名。这是本轮实现错误。初版源码、1966项人类图测试通过记录、共享回归的29项失败及原始计划均保留；该1966项通过不能代表共享时区修复成功。随后恢复既有有限十进制输入范围，在末端量化并披露上界，原29个案例及其独立参考字节不变。六种Unicode别名分别核对完整盘，只允许原始输入回显不同。

原计划中的7个暂定拒绝案例也全部保留。其中3个仅因“不是整数微秒”被初版列为拒绝，既有输入契约实际允许它们；补充计划明确更正这个新增要求，保留旧判断，不把旧判据重新标为通过。另4个确实超出±15小时，继续拒绝。原38项正式要求、已有失败案例及其门槛没有因此变化。原计划和补充计划分别固定散列，避免把评价器修正伪装成生产精度提升。

第二个缺陷来自已在本机和Linux运行时复现的[CPython issue152079](https://github.com/python/cpython/issues/152079)：零整秒偏移中的小数部分可能在`datetime.fromisoformat`中被吞掉。因此`+00:00:00.036000`的编码／解码会丢失36毫秒，原周期校验甚至把早于出生36毫秒的评估时刻当成相等。兼容解析函数只恢复这类偏移，保留普通ISO解析及无时区输入的行为。原生消息格式不变，也不通过预转UTC裁剪年1／9999的边界标签。

周期生产计算、原始输入排序及纯解释重放共用该兼容解析。完整周期复验先发现“计算正确但解释核验仍拒绝”的遗漏；该失败回执和检查结果均保留，修复重放入口后才重新验收。REST、MCP和CLI分别要求：出生前36毫秒返回校验错误，出生后36毫秒保留准确UTC及`relation=after`；完整固定解释须在禁止原生重算时通过。另以真实独立原生进程的印占位置入口核对±36毫秒时刻与等价UTC时刻的完整结果，避免只验证编解码函数自洽。

这不解决周期原典约定。复查[官方周期说明](https://jovianarchive.com/pages/cycle-analysis-in-human-design)、[词典](https://jovianarchive.com/pages/human-design-dictionary)及[Life Cycles Analysis出版页](https://jovianarchive.com/products/life-cycles-analysis)，公开资料仍不足以确认这几项具体接触采用Personality还是Design起点，以及逆行多次接触的阶段优先级；这是对所读材料的范围判断，不是宣称全文没有答案。太阳回归条目不能自动外推为土星、天王星和凯龙星的完整算法。程序保留全部候选及未裁定状态，不按年龄或首／末触擅自分配第六线阶段，也不把目录、商品介绍或未认证转载当作逐条原典验收。
