# 六爻交节边界与小数秒输出

旧六爻测试核对香港天文台的节气日期，并在程序自身求出的根前后检查月柱切换。这验证了切换逻辑，不能独立证明根所在的天文时刻。本轮补充[日本国立天文台2026年暦要項](https://eco.mtk.nao.ac.jp/koyomi/yoko/2026/rekiyou262.html)公布的全部24个节气分钟时刻，原始页面、抽取规则、首次失败及名称勘误分别保留在冻结资料（本地数据：`../tests/fixtures/liuyao_solar_v16/README.md`）。节气定义取[太阳视黄经达到指定值](https://eco.mtk.nao.ac.jp/koyomi/yoko/)，不是据行政日期零点换月。

## 已修复的信息丢失

原计算消费完整小数秒，`calendar_context.solar_datetime`、农历上下文的`solar_datetime/birth`及其下游六爻`nongli.birth`却只打印整秒。当前完整Swiss数据环境下，2026立春为北京时间`04:02:07.926618`；输入前一微秒与该瞬间，月柱分别为己丑、庚寅，旧时刻字段却都为`04:02:07`。按这些字段复算，交节后输入可能被误放到交节前。该秒数是此运行环境的数值结果，不宣称绝对天文真值。

共享历法现在保留实际消费的小数秒，整秒输入的字符串格式不变，现有独立时区字段继续给出所属时区。六爻快照同步保留完整输入时刻；`calendar_conventions.cast_at`原本已含小数秒和时区，现与其余时刻字段可交叉复核。对普通输入，没有改变日月干支、纳甲、卦码或传统判断规则。

## 两层对照的边界

国立天文台刊到分钟，本轮未核实出版舍入算法。事先声明的60秒比较门槛和公布分钟前后61秒的测试输入，只用于分钟级相符与十二节换月检查。24事件各作三个时区、两个侧边，共144次公开六爻输入；十二中气也必须验证不换月。这144次是工程探针，不是144个独立天文事件。时间精度有限不等于可以把公布分钟擅自补成精确的第0秒。

秒级对照复用[已冻结DE440/Skyfield TT参考](bazi-all-terms-audit.md)的2026年24点，保持原1秒门槛，分别记录完整Swiss数据目录及空目录的实际模型与全部差异。没有另外生成一套更容易通过的秒数。该子集已经用于开发，不称留出集；全时期原Moshier的501个失败仍保留，不因局部复测通过就认证全范围。

输出记录每点实际模型、民用时标政策及未来闰秒是否沿用最后已知值。TT一致性不能同时证明UTC政策、历史时区或未来闰秒正确。小数秒回环测试使用程序消费的根，专门验证输出忠实度，不能当作独立天文正确性证据。

本轮源码、两环境审计、三端投影及同次完整结果恢复的验收见第十六轮回执（本地数据：`validation/liuyao-depth-v16-verification.json`）。完整历法、全书原典裁决及自由模型解释尚未满分，现实预测效力也未由这些工程测试建立。
