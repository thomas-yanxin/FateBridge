# 时运缓存嵌套资料隔离修复

本轮修复了[上轮记录](bazi-envelope-comparator-and-elapsed-scale.md)中四项未关闭的缓存污染。原测试保留，原始失败日志保留；五组控制的初始完整结果均与修复前精确相同，修改一次返回值后也不再污染后续结果。这是计算资料完整性修复，未计作原40,219条包络失败或原41项TT冲突的修复。

## 缺陷与修改

`_copy_timing_info`对流月、流日缓存返回值，只复制外层、节气窗口及两个节气字典。后来加入的`solar_model_details`包含更深的字典和列表，仍与缓存共享；程序调用方递归修改返回值时，下一次命中的模型来源、精度声明等资料会被污染。流月时间线和交气时间线又会使用这些缓存结果，因而同样受影响。流时没有该嵌套窗口的控制保持通过。

此问题发生在程序内的可变对象共享；不能据此声称用户修改已经序列化的HTTP或MCP响应就能直接修改服务端内存。`SolarTerm.as_dict`本身已经复制模型资料，实际遗漏位于时运缓存返回层。

事前协议（本地数据：`validation/bazi-timing-cache-isolation-v1/protocol.json`）限定生产代码仅修改该复制函数及新增`deepcopy`导入：递归复制整个`solar_term_window`，其他标量仍按原方式返回。没有删去模型资料或缓存，没有更改日历运算、起运倍率、节气消费、周期选择或任何数值容差。

完整前后比较（本地数据：`validation/bazi-timing-cache-isolation-v1/cache-paired-comparison-first.json`）保留流月、流日、流时、流月时间线、交气时间线五组对象。原四项污染分别影响82、82、984、3,936条模型资料叶路径；修复后五组变化路径均为零。每组修复前初始对象、修复后初始对象、修改一次返回值后的后续对象，三者完整相等，没有用删字段获得相等。
