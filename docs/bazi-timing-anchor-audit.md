# 节气原始时刻、可回放分钟与夏令时

节气是计算得到的时刻；`analysis_anchor`是供现有分钟接口回放的取样点。
二者分别保留，不能把取样点当实际交气时刻或“最佳择时”。

共享提供者现在保留小数秒。流月`gregorian_window.start/end`同步保留该精度，
防止将边界向前截断到整秒，与实际用于计算的区间不一致。
小数位表示求解器分辨率，不能解释成独立验证过的微秒物理精度。
读取节气字符串使用`datetime.fromisoformat`，不再假设它只有整秒。
既有两项回放测试只更改解析方式，原有数值和干支断言保留。

## 两类实际问题

原锚点算法把当地钟时向上推到下一分钟，未校验该分钟是否存在或重复。
按锁定时区数据，纽约2025-03-09的01:59:30会产生不存在的02:00；
11-02重复小时内的第二个01:30:30，又可能生成第一个01:31，UTC时刻反而早于原事件。
程序现在跳过不存在或重复的钟时，并用UTC严格比较，选择最早可被现有字段无歧义回放的当地整分钟。
遇时区跳变时，它可能距离原事件超过一分钟，不能强行改称“事件后一分以内”。

测试同时保留历史上海秒级地方时偏移，按锁定的
[IANA规则资料](https://data.iana.org/time-zones/tzdb/asia)验证回放逻辑；
这不等于历史地方钟史已经全面独立考证。

在当前天文提供者及锁定IANA未来规则下，2083年Halifax立冬节点位于第二个01点时段。
旧锚点落回较早的UTC时刻；新锚点是当地02:00，回放后属于亥月。
[三端回归](../tests/test_bazi_timing_anchor_clocks.py)实际调用REST、原生MCP、CLI，比较完整返回及月支。
这是提供者与接口接线的一致性验证，不是未来观测或时区立法的独立预言。

本次仍不认证全部历法范围、历史时区或真实模型自由解释，验收范围继续见
三项要求（本地数据：`validation/bazi-three-axis-requirements.json`）。
