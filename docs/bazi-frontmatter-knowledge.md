# 八字原典编者术语与取用范围查询

FateBridge 新增三条可查询资料，补上《滴天髓阐微》旧扫描缺叶导致的解释语境缺口。它们保留李雨田《初学捷径》的作者层次及原文适用条件，帮助解释区分月令状态、全局生扶克泄和实际计算已裁定的事实。

| 查询键 | 具体内容 |
| --- | --- |
| 旺衰与强弱的编者分层 | 保留雨田按对用字混查的批评、得时与全局组合、常理与变法；同页承认的词义界限不清也保留。 |
| 得时得势得地的判读对象 | 分别说明季节、同党援助和根地证据，保留日主、用神、忌神各自的判读对象。 |
| 五行取用表的适用范围 | 完整呈现五行各六行，共30行；保留为上、次之和不足时的候选，以及正常五行之理和从、化、变格的范围限制。 |

原图来自[CADAL07005210数字扫描](https://commons.wikimedia.org/wiki/File:CADAL07005210_滴天髓闡微.djvu)，叶51—54、56，印刷页四十至四三、四五。完整源文件、叶图、校读记录均有SHA-256绑定。来源是额外数字见证及单读者校读，未取得独立版本或独立专家认证；详见[缺叶核查](bazi-source-leaf-alignment.md)。

## 查询方式

三条均属 `domain=bazi`、`category=source_vocabulary`，也支持只给查询键自动定位。REST、MCP、CLI 使用同一业务数据。例如读取完整取用表：

```json
{"domain":"bazi","key":"五行取用表的适用范围"}
```

将该JSON保存为 `/tmp/bazi-source-term.json` 后运行：

```bash
uv run --locked --extra dev fatebridge knowledge_read \
  --subject-file /tmp/bazi-source-term.json \
  --include-snapshot-text false --response-char-limit 0
```

REST路径为 `/api/knowledge/read`，MCP工具为 `knowledge_read`。按需读取来源及全部结构化行，可选择 `provenance.entry_curation.source_table_binding`；常用首轮仍可只读 `title`、`tips`、`citation`。预算限制下完整结果由 `result_delivery` 引用保留，沿同一run读取分页，不重算来拼接全文。

`provenance.entry_curation` 分别标注来源释义、工程说明及编辑提示。新扫描叶码使用 `source_djvu_leaves`，不冒充旧PDF页码；任氏另一段的20项四态关系另列出处，不与李氏30行表合并。

## 保留的验收范围

本轮新增独立知识补充包和加载声明。既有89条完整服务返回、原始知识包、基础术语补充包、命例比较补充包及历史索引保持原样。原典没有提供的数值阈值继续未知，生产强弱政策没有因这些术语而改变，原26处分歧也没有被重分类以减少失败。

首轮检查的67通过、9失败保留：副本漏带部分历史资料，且原有目录断言尚只声明两个补充包。补齐20份既有冻结文件，并按编码前的追加计划仅更新两个目录断言。另以反例验证初版生成器会接受审核文件和其哈希侧文件同时被改写，随后固定审核内容及交叉出处哈希，增加两项拒绝重绑定检查；生成的知识包内容没有随这项加固改变。

冻结副本上四个测试文件最终 **78项通过**，含既有Pydantic警告。检查涵盖89条完整旧返回、其他知识域保护、来源绑定、全部30行与例外、重复覆盖拒绝、REST／原生MCP／CLI一致性和同一MCP run的完整分页回读。这是知识与协议层验收，未执行新模型解释验收，也不证明历法总体验收、原典总体验收或现实预测能力。

本轮资料及首次失败见 `docs/validation/bazi-frontmatter-knowledge-v1/`。已连接客户端的加载状态与本地源码、构建包分开报告，未重启共享MCP服务。

`uv build --wheel` 从同一冻结源码成功构建wheel。独立进程从解包wheel读取三条新词条及全部30行，同时逐条核对原89条服务返回完全相同；新加载声明和新JSON的包内字节与已测源码一致，没有全局安装。对当前聊天已连接MCP的一次只读查询仍返回 `knowledge.bazi.unknown_key`，错误为不可重试；没有重试或把本地协议通过视作该连接已经更新。
