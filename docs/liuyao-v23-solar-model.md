后续[随包DE440默认路径](bazi-de440-default-audit.md)另行处理本模型的分钟判定反例。本页默认策略与数值是该轮历史快照，显式`analytic`对照及所有原始失败继续保留。

## 来源与计算

新模型 `fatebridge_analytic_solar_v1` 使用 ERFA 2.0.1 的简化 VSOP2000 地球状态、太阳质心状态、三次太阳光行时迭代、光行差，以及 IAU2006/P03 和 IAU2000B 的日期真黄道转换。固定提交与全部来源散列（本地数据：`../tests/fixtures/analytic_solar_v23/source-manifest.json`）可离线复核，完整许可随 wheel 分发；没有 ERFA、SOFA 或 IAU 对 FateBridge 的背书。

[ERFA epv00 原始说明](https://raw.githubusercontent.com/liberfa/erfa/9915ba38c9365f8b0738269b8c2ac1fdd5f8dee3/src/epv00.c)允许多数应用以 TT 代替 TDB，并说明其主要比较范围及范围外退化；运行结果明确保留此近似。[nut00b 原始说明](https://raw.githubusercontent.com/liberfa/erfa/9915ba38c9365f8b0738269b8c2ac1fdd5f8dee3/src/nut00b.c)给出 77 项章动模型及其适用范围。这些说明不能扩大成任意时代的秒级保证。

运行时只读取从固定上游源码提取的公开谐波系数。上游自身含向 DE405 定向的公开经验常数，原样保留；本工程没有对 DE440 残差、年份、节气、既有失败点拟合任何附加参数。二分起始区间按固定月份取日，不读取参考交点。40 次二分受浮点 JD 分辨率限制，约 40 微秒的末级区间只是求根收据，不能当作物理精度。

提取器 `scripts/build_analytic_solar_profile.py --check` 同时核对 JSON 系数和完整许可字节。运行实现不依赖 NumPy、Skyfield 或 pyerfa，主项目没有新增依赖。参考采集器在隔离研究环境运行，不导入 FateBridge；其数据与脚本不进入运行包。

## 默认策略与消费端

`FATEBRIDGE_SOLAR_TERM_MODEL=auto` 为默认：原生求解成功、实际选择 Moshier 且年份在 1800—2200 时，节气改用具名解析模型。实际 Swiss/JPL 文件仍按原选择使用。`native` 可精确复现原生控制组；`analytic` 显式选择解析模型，超出当前软件范围拒绝，与严格 JPL 配置冲突也拒绝。原生探测求解失败不能被静默升级为解析成功；线性值仍不能进入要求天文交气的起课与排盘。

新模型返回 `resolution_provider=fatebridge_analytic`、实际模型名、系数散列、上游提交、根区间、时标近似和作者范围警告，实际原生探测结果另列。它的原生返回标志为空，不借用 Moshier 的 `4`。总运行回执继续标记近似，配置策略和实际使用模型分别记录。缓存键包括策略和加载的系数散列；输出元数据深拷贝，避免客户端修改嵌套字段污染后续结果。

历法、风水、太乙，以及六壬/金口诀按已识别的具名模型消费。六壬接入前的六项协议失败保留；修复同时增加实际依赖中的模型细节及相应黄道定义，不能将解析模型写成 Swiss 默认 IERS2010。原有原生模型、返回选项、未知来源和线性失败校验保留。风水原有 5 秒操作防护不是新模型的误差保证，也没有把 1 秒验收线改成 5 秒。

TT 转民用时刻继续走现有明确的历史 UT1、历史 UTC 漂移、冻结闰秒表和未来闰秒末值假设；公开服务验证将实际输出时刻转回 TT 后比较。TT 交点比较不能替代完整历史民用历法审计。
