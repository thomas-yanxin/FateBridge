# 宿曜与宿占：当前历法、规则与来源

[文档中心](README.md) · [API 参考](api-reference.md) · [算法状态](algorithm-status.md)

`suzhan` 宿占与 `sukuyo_compatibility` 双人相性保留实际所选宿主历法、配宿档案与原典条文。历日宿名、天文角距与行为条文各有不同适用条件，不能互换身份。

## 历法与配宿档案

`calendar_basis` 选择现代中国农历UTC+08、HuTime日本逐日参考UTC+09，或NAOJ日本历史月朔参考UTC+09。HuTime逐日参考范围为1872-02-09至2031-01-22，2015年起属于出版方推算；NAOJ范围为公元0001-01-01至1872-12-31，早期纪年含重建，改历末月只有两天。固定参考时区不等于历史地方时；超出范围明确失败，不回退另一历法。

`calendar_profile=t1299_fullmoon27` 按T1299望日逆顺及生日加十三法配宿；`hinoo_t1299_host27` 是具名桧尾研究档案，应用T2465的闰月、小月分宿条件。涉及半日而信息不足时保留候选宿，不选定一个结果。另一宿主出版方异日及校订前后月键分别记录。

当地日期已知而出生时刻未知时，转换到所选宿主时区并保留全部可能日期；不填默认时刻。跨月、岁首、闰月及午夜分别按宿主历法处理。现代月日角距只表示天文角距；历日白黑分不能由角距替代。

`suzhan` 已知钟时的星图须提供完整经纬度：`lat`／`lon` 或对应 `gps_lat`／`gps_lon`，GPS 分量优先，0°有效；缺少任一分量明确报错，不填默认地点。钟时未知时可省略坐标，日期模式不计算星图或宫位。

星图的星座与落宫使用原始工作角度，显示值不再先舍入到四位小数。实际宫制键、整宫覆盖、正反宫序、原生投影和极点轴定义分别保留；`equal_mc` 表示实际 MC 锚定的共享模型。固定对照及未决范围见[本地宫位工作几何核对](local-chart-geometry-audit.md)。

果老模式的所选天文参考宫位不可用时，结果保留已算星曜、历日与所选宿位层；参考轴为 `null`、宫头列表为空、落宫为 `null`。`params.houseGeometryStatus` 和 `validation.calculation_layers.house_geometry` 标明这一层不可用，`houseStartModeApplied=null` 表示所请求布局未能应用。`validation.chart_source` 保留源引擎的原典验收与研究限制，`rulesets.chart` 保留相应来源；历法来源分组继续独立交付。

## 相性与条文

双人关系保留本命宿之间有方向的模环位置及三九关系，双方位置交换时按原典方向重新解释。候选宿会传播为候选关系，不能把多个候选平均成已确定相性。

原典位置资料还包括三九日、六宫宿、二十七宿四足与十二宫。显式足序只是按宿名查足表，不声称计算了真实出生足位。单个条文的七曜、黑白月日、昼夜、方向、衣着或行为前提须单独核对；原文的相反证言、字形疑读与版本差异均保留。

桧尾、三代格、766年记录、大衍、宣明与符天的研究档案保留具名来源和适用范围。其月首、名义时刻、朔望及积算是限定模型，不将缺失月份补齐，不据研究重建宣称恢复了当年的全部颁历或历史观测。

## 检验范围

`tests/data` 中的宿曜一手转录、书影、出版方历表与独立算式供当前检查使用。名称带“before-code”的独立参考可能记录了生产实现之前形成的原文或算式；它们不是旧FateBridge算法输出的兼容回放。旧协议摘要与旧软件整对象重放已经退役。

当前合成研究协议检验资料绑定、盲法、完整上下文承诺与统计门槛；合成结果不建立现实有效性。来源校读、软件正确性、解释忠实与真实预测分别验收，分数不表示关系成功概率。

历史历表比较保留原门槛：NAOJ 225 个范围内逐日控制、HuTime 210 个异日控制，要求各自原响应与所选参考或保留异文逐项零差；另留 1873-01-01 改历负控，不把新公历一月一日接为旧历。683,734 日的月首展开检查是同一 NAOJ 来源的实现互校，不能算独立书证。干净基线缺少 `tests/data/sukuyo_historical_calendar_v1/` 和 `tests/data/sukuyo_historical_daily_controls_v1/` 原始抓取档案，原测试因此三项失败；没有改成跳过、缩小分母或用生产 JSON 替代原响应。恢复可公开且指纹相符的档案前，225 日原响应验收和 210 日原响应验收仍未复证。

钟面新增控制独立于历表真伪：按 [NIST 2026 年 DST 公告](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst)的三月第二个星期日／十一月第一个星期日规则，2026-03-08 和 2026-11-01 的纽约当地未知时刻分别覆盖 23／25 小时；同一 UTC 原像在宿主 +08／+09 的午夜分别于 UTC 16／15 时切分。0806-09-20 的 NAOJ 月首承接小月，00、12、23:59:59 的已知钟面均不自动指派 T2465 文本半日。固定 `as_of` 的真实 REST POST、逐工具 MCP 与 CLI 对单人候选及双人交换方向进行完整响应与严格投影核对：轸→亢为衰、反向为友；角→亢为栄、反向为親。该验收证明软件保留具名规则与候选，不证明历史出生时制或关系预测效度。
