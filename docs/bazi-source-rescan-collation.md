此前将题注与癸巳年柱判为冲突，原因在转录输入。旧扫描的原尺寸裁剪与新扫描都可见“三”的三道横画；这不是靠人物生平或纪年公式改原文。首次输入、计算判据、失败报告和当时的错误判断继续保留，当前规范数据通过另一个有来源绑定的修订层更正。[前次报告](bazi-source-calendar-caption-constraints.md)已标注这项更正。

## 修订的限制与留证

规范数据通过 `source-case-input-resolutions-v2.json` 加载修订。检查器仍核对全部原始558个命例、1,380条陈述及源页哈希。新增题注修订仅允许 `source_metadata.source_caption_as_printed` 变化，其余元数据必须完全一致；干支修订仍要求原始完整四柱、图版凭据和所有关联陈述的审查。

原四条输入问题全部保留为库存。周侍郎例的字形问题另有明确的解决凭据，当前未解决项剩三条印本冲突。解决记录必须指向原问题、在同一修订文件中附带对应的单柱字形修订；不能用题注修订、重复记录或公式结果解除印本冲突。其余22条原有未决记录保留，全书比较门槛仍未通过。

相同的独立参照现显示：三十八年的名义干支与癸巳相合，庚日辰时的时干与图中庚相合。这里只验证输入与符号对应，不证明完整出生历日、天文交节时刻或预测有效。前次对错误题注的失败结果没有重评分。

全量对象保护检查在修订后首先报出两项旧预期失败，日志保留，再仅按独立冻结的两命例、两陈述字段修订精确预期。之前八项命例修订、七项关联文字修订和“土官令→土当令”的校正继续核对。所有已知／未知强弱标签不变。

完整验证记录、首次失败、修订计划、原始与对照图像、规范视图和冻结副本信息见 `docs/validation/bazi-source-rescan-collation-v1/`。当前整个工作区存在并行变动，副本上的检查不升级为全工作区或已连接服务的验收。原40,219条包络失败、41项边界冲突、26处分歧及5例解释的判据和历史结果均未由本次修订替换；未执行新模型或新强弱候选比较。

验证结果：同一套七个测试文件共 **168项通过**，伴随一个已有 Pydantic 警告，4,315份冻结输入前后完全一致，266个加载的项目模块全部来自副本。原工作区检查期间检测到执行层并行变动，结果为163通过、5失败，保护失败完整保留。首次副本缺少一个仅由子进程读取的校验文件，结果为167通过、1失败；补齐七份已有哈希侧文件后取得上述168项通过，源码、测试和首次4,308份输入字节均未改变，也未删选测试。

冻结副本上的全书 CLI `--require-complete` 仍退出 **1**，与修订后的规范视图完全一致；这不是全书验收通过。本次只变更离线资料校读与审计机制，未修改生产历法、强弱内核、知识词条或共享接口，也不新增部署验收声明。
