# 本地宫位工作几何核对

`suzhan` 的已知钟时星图和 `otherbu` 的附加天象复用共享天文引擎。这里验收原始角度到星座、宫位和交付记录的转换；星历物理精度、传统规则来源和现实效度各自保留原验收范围。

## 已复现的问题与修复

旧适配器先把星体、ASC 和宫头舍入到四位小数，再决定星座与落宫。原始 `29.999999999999996°` 因而可能被当成 `30°`；接近 `360°` 的整宫轮也可能交付越界值。等宫轮的浮点逐步加法、宫头多数方向猜测、容差扩张和空区间默认第一宫，又混淆了工作几何、原生投影和最终显示。

`HouseGeometry` 统一保存十二个有标签的精确工作宫头及方向。正常宫头必须构成一圈分区，使用无容差的半开区间；整宫从原始 ASC 所在星座开始，等宫从原始第一宫宫头开始。翻转保留第一宫并反转后续宫序。非分区的原生宫头保留原标签，落宫使用同次原生投影的工作相位，不能以黄经排序猜测其空间含义。缺少所需投影时报错，不猜宫号。

原始有限浮点输入按其精确有理数值处理，线性派生角度先完成计算，再生成同侧的浮点交付值。共享的黄经显示边界保证 `lon` 在 `[0,360)`、`signlon` 在 `[0,30)`；更多位数不代表更高物理准确度。南交点保留原始北交点的对点，福点保留所选共享公式、实际昼夜与来源。

R／C／T 投影保留原来的模型、收敛线和误差检查，将已有 mpmath 工作值精确转换成有理数继续使用。100 位十进制文本及最终浮点宫位不再充当翻转的输入。核心星体与上下文复用同次 `HouseCoordinate`，派生交点、福点另算；这不会建立新的天文参考模型。

## 模型与公开字段

- `houseSystemResolved` 保留实际共享模型键，例如 `equal_mc`；不能改名成另一种等宫模型。
- `houseAssignmentBasis` 和 `houseGeometryModel` 区分原宫头分区、原生相位、原始 ASC 整宫覆盖与原始首宫头等宫覆盖。
- 原生投影保留实际 `housePositionMethod`、`housePositionProjection`、工作相位及来源。精确地理极点的原生约定继续明确标注，不能认证为唯一物理解。
- `angleDefinition` 及快照保留极区轴的定义，包括显式整宫覆盖；日期模式不生成宫位，缺少已知钟时星图所需坐标仍拒绝。

## 固定对照与范围

改代码前冻结标准、原始数学输入、124 个共享选择器请求，以及 62 个 REST／CLI／新 stdio MCP 请求。完整档案在 `/Users/thomas/.codex/artifacts/fatebridge-local-house-precision-20261112/`；仓库携带[固定参考及来源说明](../tests/data/local_house_geometry_cgal_v1/README.md)和[应用检查](../tests/integration/test_local_chart_geometry_reference.py)。档案分别保存原失败、后续补充、最终源码绑定和安装包结果，不把工程调用成功记作独立物理验收。

数学参考实际执行 CGAL 6.2.1 的精确 `Direction_2` 圆周次序谓词，另以有理数区间公式交叉核对。相位到有理菱形方向的单调映射是本项目的明确胶水代码，不能算成 CGAL 独立提供的天文转换。240 个解析轮、159 个星座输入、31,784 个宫位／资格案例产生 35,447 项重叠检查；原 15,331 项失败照实保留，修复后该组无差异。另有 2,256 个非分区控制只验输入资格，不算数值成功。

124 个实际共享请求覆盖普通纬度的九种宫制、两种黄道、正反宫序及首宫选择，并单列 R／T 的六组正负高纬度和极点输入。原始来源的 1,588 项下游点位决策有 127 项不符，修复后均与固定圆周参考一致。原生天文和非线性投影在此作为输入，不能据此声称全部宫制或原著已经独立认证。

62 个公开案例含 60 个合法请求和两个原有错误控制，并含真实 UTC 求根邻域的太阳／ASC 星座边界。原始三端结果在改动前保存；730 项原始来源点位及工作相位后来从与初始源码逐文件相同的封存 wheel 补取。另加 36 个构造的工作相位控制，明确在首次实现后冻结，不并入原始 35,447 项分母。原有 45 项 R／C／T 投影检查也有通过记录，原始阈值与来源限制保持。

仓库应用回归显式向三端注入上述冻结的原始核心输入，隔离原生天文库构建造成的末位差异；实际原生来源与安装包协议另存实测及各自的精确 CGAL 输入。最初直接把 Python 3.12 天文输出作为 Python 3.10 的逐位预期产生失败，原日志与首份夹具均保留。修正的是测试输入归属，没有放宽圆周谓词的零差异标准，也不以注入测试代替真实来源验收。

## 来源与未决范围

圆周次序见 [CGAL `Direction_2`](https://doc.cgal.org/latest/Kernel_23/classCGAL_1_1Direction__2.html)；原生宫位和坐标语义见 [Swiss Ephemeris 程序员手册 §16](https://www.astro.com/swisseph/swephprg.htm)。工作数值转换使用锁定的 [mpmath 1.3.0 `libmpf.py`](https://github.com/mpmath/mpmath/blob/1.3.0/mpmath/libmp/libmpf.py) 的 `to_rational`，保留该工作数值，而非宣称它等于精确物理解。完整原始来源、编译依赖、输入、输出、校验和与实验代码保留于档案。

本轮不改变 Polich／Page 原著完整验收、极点几何唯一性、天体物理精度和此前反例的状态。[星骰天文限制](astrodice.md)及[整体精度验收](precision-acceptance.md)继续有效。算法清单仍为初审，不能把局部精确圆周谓词、三端一致或安装检查通过写成全仓专家／SOTA／预测认证。

## 后续：所选参考宫位缺失的分层交付

追加果老极点控制发现，核心已将不可用的天文参考轴、宫头和落宫分别保留为 `None`、空列表和 `None`，适配层仍尝试把空轴转换为角度，导致整次请求成为内部错误。初始安装包也复现该问题。修复将缺失的工作宫位几何明确表示为可选值；整宫只在实际 ASC 可用时生成，普通参考布局只在其宫头可用时生成。

星曜记录、历日以及请求的现代／旧等分宿位继续交付。没有参考落宫的星曜在快照中独立列出；`chart.ok` 表示已有星曜记录生成，宫位可用性由 `houseGeometryStatus` 和各空值字段表达。请求参数与实际应用状态分别保留，已知钟时仍是已知钟时。

本地星图展示核心行星列表的七政记录；四余与功能宫属于源引擎的其他结构。`validation.chart_source` 保留规范引擎的原典命度未重建、研究口径和 `classical_acceptance_passed=false` 等限制；`rulesets.chart` 附加其五项来源分组。历法 `rulesets` 字典及已知钟时的三个计算层状态保持原合同。

改动前固定 35 个请求：24 个缺失宫位控制、8 个普通果老控制、2 个无效请求和 1 个日期模式控制。三个真实接口原有 72 次内部错误，修复后这些请求返回各自可用层；两个无效请求仍按原合同拒绝。独立数值几何沿用原固定 CGAL 门槛，缺失宫位只做边界／来源保真检查，不算数值落宫成功。便携回归显式注入一份改动前的规范源结果，覆盖 24 个参数组合，见[固定来源说明](../tests/data/local_partial_house_v1/README.md)。实际协议、原始失败和源码绑定另存 `/Users/thomas/.codex/artifacts/fatebridge-local-partial-house-20261112/`；本项不认证完整果老原著、物理来源或预测效度。
