# 实测工位布局与条件判断

[风水入口](fengshui.md) · [虚构请求](examples/fengshui-workstation-measured.json) · [调用合同](contracts/fengshui_assess.json)

`fengshui_assess.workstation_layout` 将有尺寸的人工标注空间连接到已有风水计算，返回 `layout_analysis.workstation_layout_analysis`。四项交付分别是工位条件解释、空间关系计算、受约束候选生成、显式作者桌面规则；没有新增独立工位接口。

## 覆盖与职责

| 层 | 输入与实际计算 | 独立边界 |
| --- | --- | --- |
| 几何 | 有面积且无自交的房间多边形；旋转矩形家具；坐者与视野；门窗、背靠线、通道、梁柱；桌面物件和保留区 | 只处理登记的米制空间，二维投影与实际高度分别运算，不从照片自动建模 |
| 工位条件 | 工作/学习取向星角色，原历史宅运、显式评价运、有向山向五行、可选王亭之基本时令、独立入口/背靠与外部水形观察 | 向星角色不是坐者朝向或水元素；未当令不直接判凶；其他活动明确未覆盖 |
| 原有方法 | 同一批确认的落宫/朝向进入八宅；明确砂水分类进入金锁；宅、年、月星分别关联实际方区 | 计算复用现有领域服务，不改变历史定运、来源版本或既有校勘差异 |
| 桌面 | 明确另选 BTB 九格或 WOFS 罗盘/坐者规则；植物状态独立记录 | 坐者远左不等于东南；手机、杯子、玩偶不自动产生元素/摆放规则 |
| 搜索 | 明确网格自动产生位置域，或显式提供位置；与角度域完整组合并逐个重算 | 网格需要明确尺度与步长；不继承上一方案的入口、背靠或砂水方区，不生成风水总分 |

确定性空间运算集中于 `spatial_geometry.py`、`spatial_scene.py` 和屏幕透视的 `spatial_visibility.py`；`spatial_domains.py` 在输入边界解析位置域，`spatial_layout.py` 适配既有领域计算；条件、桌面、搜索、交付各自独立。输入在 `spatial_inputs.py` 收窄，由 `spatial_request.py` 组合请求与已解析位置域，避免基础输入与几何之间的循环依赖；服务层只编排。

## 输入语义

`scene.boundary` 支持凹多边形；不自动修复自交，也不把包围盒当房间。家具 `footprint` 是完整矩形包络，`bottom_m/top_m` 是实际高度区间；声明的实体包络之间不允许面积及高度同时重叠。贴边允许，`1e-12 m²` 仅为浮点面积容差，不是传统距离阈值。桌下/空心结构须按实际实体分别标注，不能把实体包络碰撞解释为完整家具结构测绘。

图纸平面 +y 为本地前方，角度顺时针。书桌局部 +x 为坐者右、+y 为远沿，-y 为近沿；坐者偏移、操作净空和桌面物件均在该桌的局部坐标下。书桌搬转时重新变换到图纸坐标。物件占多个桌面格时保留所有格，不能将中心所在格当整件物品唯一落区。BTB 作者规则仅用于实际近沿、面向远沿的参考系；已知不适用的坐者方位直接说明未覆盖。WOFS 的坐者左右按实际位置与朝向计算，不用桌面中心代替坐者。

坐者眼高用于视野遮挡，头顶高度用于身体净空。入口可见性在门洞端点、遮挡物顶点和明确视野边界形成的角区内求解，不使用固定像素/角度步长抽样。`blocks_view` 必须明确；入口平视模型仅在实际高度覆盖眼高时遮挡。门洞向内方向须垂直于门洞线段。门的直线带、走道末端的延长带与坐者实体相交分别记录，侧边经过不会自动成为直冲。门扇活动等保留空间用 `keep_clear_zones`，键盘/书写禁占区用桌面局部 `protected_zones`。

物件完整世界包络还须避开其他家具及梁柱，分别核对平面与高度；不能因桌子低于梁就放过桌上高物。多工位同时保留的坐者包络、操作区域及其他坐者与操作区域之间也互相检查，不把逐桌通过当作整体无碰撞。

### 显示面视线

桌面物件可独立提供 `items[].screen`：物件局部中心、朝向观察者的水平法线 `front_degrees`、宽高、距桌面的底边高度，以及明确的 `required_visible`。显示面当前只支持竖直平面，须在所登记物件完整包络内，并关联同桌实际坐者的眼高；不从设备名称补尺寸、金属材质或朝向。

对每个明确不透明的家具/物件，先裁出眼点与显示面深度之间的实体，再将其凸透视遮挡锥与整块显示面相交，求所有遮挡影的并集面积。返回 `geometry.screen_visibility` 的模型可见面积比例、实际遮挡对象、正面朝向和声明水平视野检查；不是中心/四角或稀疏射线抽样。低于眼高的障碍仍可能挡住屏幕下部，屏幕后、眼后及视线高度外的实体不会被误算。

`required_visible=true` 才将正面、整面处于声明水平视野且无遮挡列为候选硬约束；未知清单不确认无遮挡，照片/坐标误差仍是候选。模型面积比例仅描述所给包络，不代表像素可读性、眩光或光照强度，也不用于风水评分。倾斜/曲面显示器、透明度和光照反射尚未建模。可运行[网格与显示面示例](examples/fengshui-workstation-grid-screen.json)。

梁的水平投影与坐者相交、且位于头顶以上时，产生独立梁上方观察；低于身体净空则另产生实体碰撞。家具/柱角只有明确 `has_sharp_corners=true` 才计算外角平分射线是否指向坐者，保留既有作者分歧，不新增尺寸吉凶阈值。实体背靠须用独立 `solid_backing_segments` 登记，不将房间边界都当实墙；返回实际后向射线距离，不据距离造吉凶分界。

多扇窗时用 `seats[].window_id` 明确本次核对对象；不任取第一扇。宽门窗跨多个相对方区时保留各候选，不用中心点的“身后”覆盖实际可见部分。背靠线不自动代表眼高处的不透明墙；视野遮挡另用带高度、明确 `blocks_view` 的实体。`inventory_confirmed=false` 时，未登记的梁、背靠、通道保持未知，未完整核对遮挡时不确认正面的可见结论；已知事实仍可先解释。未确认完整清单会限制候选执行状态。

### 罗盘、立极与误差

`compass` 独立声明图纸 +y 的罗盘角、真北/磁北、角误差、参考中心、参考层级和绑定依据。`chart_binding_confirmed=true` 才能将所给立极关联到本次明确的宅/年/月盘。它是调用方确认，算法不自动选择质心或另一种立极。已绑定宅盘的北基准必须一致，不自动换算。

`seats[].sector_anchor=seat|desk_center` 显式选择实际坐者或书桌中心，不将两者混同。误差跨宫时保留全部相交角区与宅盘候选；正好分界的精确点沿用左闭右开，非零误差使用闭区间。`coordinate_uncertainty_m` 另传播为坐标误差引起的角度范围。照片或非零坐标误差只产生名义几何候选，不注入确定的既有 `Placement`，不产生 ready。

`bodies[].sand_water` 保存独立砂水分类及证据，几何仅计算其实际方区；不按桌子、植物或高低猜分类。分类为未知/混合、位置未绑定或照片时保持对应层部分可答。完整金锁24山细断仍未实现。

### 避免两份事实

同一实测对象不再同时提交另一份顶层 `placements/form_observations/features` 或 `environmental_context.objects/interior_relations/workstation_review/observations`，也不叠加另一份 `floors` 位置绑定。参考层级与中心由本次场景独立确认，不借旧层级跳过确认。这些几何和身份由场景层负责；独立材质事实、未移动的其他对象、住户和明确宅盘仍可使用原字段。`seats[].subject_ids` 可独立选择本次已提供的实际使用人，省略沿用全部使用人的既有合同。原 `layout_alternatives` 继续服务人工候选；实测对象候选用 `workstation_layout.search`。

`workstation_conditioned_v1@1.0.0` 采用 Kartar Diamond 的用途/角色和时令、形态、用途分开核对的范围。评价运与证据成对提供；可沿用本次明确的玄空评价运，两处不得矛盾，不从系统日期或历史宅运补值。可另选 `wang_zhongzhou_timeliness_v1`，保留原作者版本及来源。已有沈氏主客分析仅在该候选、该坐向轴实际覆盖当前宫时引用，不推广到其他宫。年、月星及其时间上下文独立列出，没有年/月/宅星相加。

实测植物/屏风的入口关系适配已有 `afsi_entry_barrier_v1`：入口直线、隔挡是否在入口和坐者之间、视野、通行、操作和实际容纳分别重算；不会因允许移动就补出这些关系。隔挡位置的保留参考和生成方案实际搬动许可分别读取。

`desktop_bagua_btb_v1@1.0.0` 沿用既有登记来源。`wofs_desktop_compass_v1@1.0.0` 是新显式选择的有限作者版本：东鲜花、东南健康小植物、西南光滑水晶球、南灯；同桌的明确金属办公设备按坐者右侧、左侧有更高物件核对。后者是相对高度关系，没有固定厘米数。非本版本物件返回 `not_covered`。旧 `workstation_analysis.non_btb_desktop_reference` 继续只是参考，不能当作新版本已经开启。

植物/鲜花的 `healthy` 是独立观察。身份、位置和状态分别返回；物件匹配位置不证明状态良好，状态未知可以先解释位置，不补造成健康事实。物件完整包络及角误差可能覆盖多个罗盘方向；此时保留候选，不强选某个方向。所有作者规则都不承诺职业或财富效果。

来源与明确范围在 `src/fatebridge/data/fengshui/workstation-layout-v1.json`，实际输出保留 `rulesets/rule_trace`。几何和有限搜索采用工程规则 `workstation_layout_v1@1.1.0`，不会冒充传统流派。

## 搜索与完整回执

`search.domains` 为实际允许考虑的家具/物件分别提供位置和角度；最多6个对象、4096个完整组合。位置为图纸坐标；桌面物件位置为该桌局部坐标。不会自动移动门窗、梁柱或房间边界。搬位与转向分别读取原 `layout_constraints.can_relocate/can_rotate`；附着物件明确锁定时，搬桌也不能绕过它的约束。附着物件随桌发生实际世界位置或朝向变化时，相应许可未知或缺记录会保留待确认；没有发生变化的动作不索取许可。

位置域在 `positions` 和 `grid` 中二选一。`grid` 必须明确 `origin`、`step_x_m/step_y_m`；可另传 `center_region` 限定中心搜索区。省略中心区时，家具自动用场景凹多边形、桌面物件自动用所属桌面，沿各自坐标系生成整数格点。十进制格点运算保留如0.3/0.1的闭边界；不自动添加现状位置、改变原点/步长或补旋转角度。中心入区不等于完整包络可容纳，全部组合仍有后续几何回执。每个网格包围盒最多4096个采样点，解析后总组合也不得超过4096；超限或空域明确报错，不静默采样/截断。`search.resolved_domains` 保存实际生成的位置、角度、来源和参考系；不声称穷尽连续空间。

每个组合重新计算房间包含、带高度的实体碰撞、椅位净空、通道/保留区、桌面容纳、物件碰撞和保留区。`required_checks` 只采用调用方明确要求的入口/通道/梁/背靠条件；未知不能当作满足。没有许可、完整清单或确认测量时保留 conditional/candidate，不据此阻止现状解释。

`search.receipts` 保留所有组合、拒绝原因、未知条件和逐来源比较维度；`enumeration_complete=true` 表示整个声明搜索域已计算，不表示现实所有布局已穷尽。每条规则独立作为比较维度，同时记录直接变更对象数、平移和旋转量。明确工作/学习与评价运时，也保留用途所取向星是否与评价运相同的独立条件维度；非当令不被解释为凶，不能因少搬动而丢掉该条件不同的取舍方案。未知/候选规则和未知植物状态不可比较，不获得已满足的维度值。

`feasible_count` 是未被明确阻断的组合数，包含 conditional/candidate；不能当成确认可执行数。实际执行按各回执 `status`、`pending_confirmations` 及几何检查的三态分别读取，未知检查不会变成满足。

返回互不支配的 Pareto 候选，并按变动量排列显示；这只是可核验的取舍集合，没有唯一风水赢家。`max_results` 只限制显示，完整前沿ID、未显示数量和全部回执仍保留。`ready` 只表示登记几何、明确搜索条件及实际动作许可满足；仍需分别查看规则、材料条件、来源范围与部分结果。

## 调用

```bash
uv run --locked --extra dev fatebridge fengshui_assess \
  --request-file docs/examples/fengshui-workstation-measured.json \
  --fields layout_analysis.workstation_layout_analysis coverage.analysis_progress rulesets rule_trace \
  --strict-fields --no-include-snapshot-text
```
