# 八字出生秒数与输入分量

当前源码新增可选的 `birth_second`，将已知的整秒出生钟时传入八字与时运计算。底层交节、真太阳时与起运原本保留秒数；此前公开八字输入只能给出小时和分钟，无法表达同一分钟内交节前后的两条已知记录。

支持范围是综合 `analyze_destiny`、标准 `bazi_birth`、九个八字专题及七个时运入口。综合按实际目录提供 MCP／CLI，其余上述入口提供 REST／MCP／CLI。其他系统是否支持秒数，以各自 Schema 为准。

## 已知分量与兼容参考

`birth_second` 仅接受整数 0—59；提供秒数时必须显式提供 `birth_minute`。未知秒数应省略或传 `null`。省略分钟仍沿用旧的 00 分、省略秒数仍用 00 秒作为确定性计算参考，但不会把这些默认值登记成用户确认的出生分量。

| 输入 | 计算参考 | 回执中的省略分量 |
| --- | --- | --- |
| 只有小时 | `HH:00:00` | `minute`、`second` |
| 显式 `birth_minute=0` | `HH:00:00` | `second` |
| 显式分、秒均为 0 | `HH:00:00` | 无 |
| 给秒数但省略分钟 | 拒绝请求 | 不替未知分钟填 0 |

新增 `calendar_context.birth_time_input` 返回输入分量、兼容默认值、实际计算参考钟时与校正钟面。标准命盘的路径是 `bazi_birth.calendar_context.birth_time_input`，九专题分别在 `career_analysis` 等实际专题根下，综合与时运在根级 `calendar_context` 下。MCP 适配层保留可选分钟的省略事实，公开 Schema 仍声明原默认值 0。

`run_metadata.input_sha256` 同时包含出生分钟的省略事实，避免不同输入依据落入同一个规范化请求身份。未知秒数的省略与 `null` 保持相同语义；重放仍须保留原始输入，再应用同次回执的 `as_of` 与 `overrides`，不能用填满默认值的模型转储替代原档案。

分量的存在不证明出生记录具有对应测量精度。没有记录约定时，不能把缺秒自动解释为向下截断、四舍五入，或推定某个 60 秒区间。[RFC 3339](https://www.rfc-editor.org/rfc/rfc3339.html)处理时刻表示，不规定出生记录的不确定区间；本软件的省略回执属于明确的软件兼容约定。

实际出生范围仍须单独提供。已有 `birth_time_uncertainty_minutes` 逐分钟网格现在保留名义输入的已知秒数，继续声明未证明采样间秒级无变化，样本频次也不是概率。它不因新增秒数而成为连续区间穷举。

范围采样保留原 IANA 时区，以每个候选瞬间的实际偏移核对重复钟时。此前将历史秒偏移改写成固定时区字符串，会使部分有效输入被拒绝；同一批失败钟时与重复小时控制继续保留，不通过舍去偏移秒数来修复。

## 传递与交付

秒数经过请求绑定、`PersonInfo`、民用时刻、真太阳时校正和八字出生上下文；年／月仍按原民用瞬间，日／时按既有校正钟面政策计算。起运的出生至交节时距继续保留秒数，沿用现有三日一岁及民历相加约定，不新增事件预测规则。

已知秒数会出现在结构化出生时间与快照中。旧的分钟展示字段在未提供秒数时保持既有格式，完整钟面值另在输入回执中提供。时运说明放入已登记的“查询信息”节，避免快照导出过滤未知节名；九专题也交付简短的钟时依据。

以下是虚构工程输入，不能代替用户资料：

```bash
uv run --locked --extra dev fatebridge bazi_birth \
  --birth-year 1990 --birth-month 5 --birth-day 15 \
  --birth-hour 10 --birth-minute 20 --birth-second 59 \
  --birth-timezone UTC --use-true-solar-time false \
  --fields bazi_birth.calendar_context.birth_time_input \
  --strict-fields true --include-snapshot-text false --response-char-limit 0
```

本轮不增加闰秒标签支持。[Python datetime](https://docs.python.org/3/library/datetime.html)的秒分量范围是 0—59，60 秒明确拒绝，不作截断。历史钟时、时区数据库与未来闰秒政策的适用范围，仍由各自时标与来源回执负责。

## 验证方法与边界

方案（本地数据：`../tests/fixtures/bazi_birth_seconds_v1/protocol.json`）先冻结输入行为、来源、全队列和门槛；相邻秒参考（本地数据：`../tests/fixtures/bazi_birth_seconds_v1/reference-preparation.json`）继承原 DE440／参考系与钟时政策，覆盖出生服务年份 1900—2100 的全部 4,824 个交节点，取每个交点两侧相邻整数秒，共 9,648 条输入。原四项参考标签全部保留，最近输入距参考交点约 34 微秒，没有排除这一病例。

这是共享星历与既定时标政策下的实现比较，不能据微秒级接近程度认证物理绝对精度、真实出生记录或历史 UTC。测试与源码冻结分别保存，未放宽原参考标签、重写原失败，或将重叠队列累加成独立观测。

出生精度改进不改变旺衰权重、原典判据，也不解决原典现存分歧、独立解释审查或现实预测效度。新的秒数参数不是整体满分证明。
