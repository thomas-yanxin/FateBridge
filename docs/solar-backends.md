# 太阳计算与可选后端

[文档中心](README.md) · [API 参考](api-reference.md) · [算法状态](algorithm-status.md)

`FATEBRIDGE_SOLAR_TERM_MODEL` 选择共享太阳交节模型；默认 `auto`。普通安装在适用年份使用随包 DE440 系数，无需另行下载或编译。更改此变量会影响八字、时运、六壬、数算和风水等消费方，具体路径见[架构依赖表](architecture.md#历法与星历依赖)。

## 默认模型与选择顺序

| 模式 | 实际选择与准备 | 年份和失败边界 |
| --- | --- | --- |
| `auto`（默认） | 已配置严格原生 JPL 时优先使用 JPL；否则 1700–2300 年使用随包 DE440，范围外进入原生路径 | 软件允许年份和各消费方公开输入仍分别校验；无可用交点时明确失败 |
| `de440` | 显式选择随包 DE440，无需 `jpl` extra 或外部 SPK | 公开模型输入 1700–2300 年；内部相邻边界及参评投影使用各自具名资料，不扩大公开年份 |
| `native` | 可用 Swiss／JPL 文件保留原生模型；原生探测返回Moshier时改用下述内置DE441 | 读取实际模型与来源，不能用原生库可导入推定文件已就绪 |
| `swiss` | 必须实际使用 Swiss 文件；[下载分段](ephemeris.md) | 1800–2200 年；缺文件、返回 Moshier 或来源未核查时拒绝 |
| `analytic` | 显式选择 `core/analytic_solar.py` 的具名解析模型 | 1800–2200 年；与内置DE441及其他太阳模型分别验收，不能沿用另一模型的验收成绩 |
| `spk` | `FATEBRIDGE_SOLAR_SPK_FILE` 指向外部 SPK，安装 `jpl` extra | 以所选文件、加载器和消费方支持范围为准 |
| `aa1996` / `vsop2013` | 按下文构建并指定清单 | 各自范围、平台及来源单独核验 |

选择逻辑见 [`solar_model_policy.py`](../src/fatebridge/core/solar_model_policy.py)。默认系数来自 DE440 的无损裁取，主模型、扩展年份及派生边界保留各自模型身份；来源指纹由内部资料维护。TT 网格符合不能认证绝对 UTC、全部连续时刻或现实预测。

主／扩展profile的完整公开年份及相邻上下文已有[独立TT参考](../tests/data/solar_tt_de440_v1/README.md)：原始JPL DE440、Skyfield 1.53官方API及完整生成源码一并记录，共14472个固定交点。实际年网格使用的双部TT与单JD求根两条路径均对照全队列，原1秒线及预声明10毫秒诊断线均符合；最大差分别约72.6／80.5微秒。参考自身约40.233微秒的浮点夹区间、原始轨道误差及钟时政策仍分别适用。历史／Canping专用profile和范围外原生模型没有由此取得新的验收。

`native`／`swiss` 的环境回执只描述配置，不为生成回执加载太阳系数；纯知识文本查询不因此依赖未使用的太阳模型。实际交节计算仍校验所选来源，内置DE441所需的原网格系数、TDB或坐标资料缺失、损坏时仍明确失败。

外部数据准备见[星历安装](ephemeris.md)，固定有限队列及仍未通过项见[分项精度验收](precision-acceptance.md)。需要可选模型时先完成[源码环境准备](development-guide.md#环境准备)；SPK／视位置对照所需依赖可用 `uv sync --locked --extra dev --extra jpl` 安装，后续命令也保留这两个 extra。

共享民用年表只接受1—9999年。首尾节月只按实际需要求内部相邻年0／10000的交点，使用同一上下文和钟时政策保留真实标签；这不扩展所选太阳模型、个人出生服务或精度认证范围。独立对照与原失败见[历法边界核对](calendar-boundary-audit.md)。

## 严格 Swiss 文件模式

需要原生 Swiss 视位置流程、并希望在缺少文件时停止计算，可选择 `swiss`。公开节气输入为1800—2200年；首尾输入所需1799／2201年边界仅在原上下文内读取，不扩展公开年份。`native` 有文件时沿用实际 Swiss／JPL；回退使用下述内置DE441同源视位置。

```bash
uv run --locked --extra dev python -m fatebridge.fetch_ephe --profile fengshui_calendar
export FATEBRIDGE_SOLAR_TERM_MODEL=swiss
```

该文件配置含所需的 `sepl_12`／`semo_12`／`sepl_18`／`semo_18` 分段；自定目录通过 `SE_EPHE_PATH` 选择。严格模式复用现有 TT 求根及文件来源核查，不拟合参考交点，也不修改 Moshier 的系数。缺文件、返回 Moshier 或不能取得交点时，三端返回非重试503及 `solar_swiss_files_required`；无法核查文件来源时保留相应来源错误。与显式原生 JPL 配置冲突时返回配置错误。

参评1800年初所需的1799年立春沿用已核对的相邻年组件；120年投影若越过2201年边界，则返回 `solar_swiss_range`，不交付缩水年序或更换模型。风水等领域另需范围外历史边界时也须按该领域的模型支持范围选择来源，不能从文件存在推定已扩展资格。

每个交点仍返回实际旗标、TT 括区和观测到的行星／月球文件身份；环境回执的 `analytical_fallback_allowed=false` 仅描述选择政策。能使用文件不自动证明任意年份或全部交点达到一秒；数值验收必须同时绑定所用文件、参考和样本。依据为 [Swiss 请求与实际返回模型的区别](https://www.astro.com/swisseph/swephprg.htm)。

当前数值门槛为与固定 DE440 参考比较的1秒 TT，参考输入与原数值见 96点当前参考（本地 `tests/data/solar/de440-guard-tt.json`）。原版 Swiss Moshier 同一队列的12项失败继续单列；FateBridge内置DE441按独立身份验收，不将旧模型失败改判。

当前原生求根使用 `native_swiss_tt_solar_bisection_v2`：返回首个达到或越过目标太阳黄经的可表示 TT 浮点点，其前一浮点点仍在交点之前，策略为 `first_post_crossing_tt_float`。这是同一太阳模型数值方程的边界取点约定，不修正星历系数，也不把浮点分辨率当作物理精度。实现见 [`almanac.py`](../src/fatebridge/core/almanac.py)，当前前后侧验证见 [`test_ci_regressions.py`](../tests/integration/test_ci_regressions.py)。

## 内置 DE441 太阳回退

当前 `native` 路径的原生探测返回Moshier时，交节使用 `fatebridge_de441_solar_v1`，提供者为 `jpl_de441`。实际Swiss／JPL文件模型继续保留自己的来源和数值；严格 `swiss` 不允许回退。当前选择仍依赖原生探测可用，内置源本身覆盖1—9999年并不等于全部这些年份的原生入口或精度均获验收。

新路径复用已有 [`de441_source.py`](../src/fatebridge/core/astro/de441_source.py)、[`AnalyticObserver`](../src/fatebridge/core/astro/analytic_observer.py) 和公共日期框架，同一原始网格上的DE441地月质心、地心月球、EMRAT及质心太阳共同提供接收地球和发射太阳。完整地心Fairhead模型将TT映射到TDB，小光行时偏移保持双部精度；相邻本地TT光锥求解与Lorentz光行差作用于同一条光线。Vondrák长周期岁差、标量黄赤交角、完整Simon77项章动及IAU2006偏置沿用具名原生框架。源码入口为 [`de441_solar.py`](../src/fatebridge/core/de441_solar.py)，没有新拟合、逐年补偿或参考交点运行时依赖。

运行时读取从原始 DE441 网格裁出的有界分块，所选系数按原 binary64 字保留。内部回执区分完整 JPL 文件与包内表示，并分别绑定系数清单、原始准备文件、TDB、日期框架和章动。每块系数都有字节校验，内置回退的 `ephemeris_retflags` 为空。 [原始系数与同源状态对照](precision-acceptance.md#lossless-de441-round35)

早期整数表示的九个控制点由 CALCEPH 5.0.1 和 Swiss 原生 JPL 读取器对照，内置地球和太阳位置与原文件最大差约 0.48 毫米。两个读取器之间最大差约 0.034 毫米，同几何定义下 Swiss 压缩文件与原记录最大差约 761 米。原始 JPL 参考使用已确认返回 `JPLEPH` 旗标的文件配置。 [Swiss 返回旗标说明](https://www.astro.com/swisseph/swephprg.htm#_Toc112949031)

<a id="de441-fallback-source-selection-round58"></a>

`native` 缓存键使用可能回退的包内来源身份。实际选中 DE441 后，计算再读取并校验所用字节。固定缺失和损坏两臂中，Swiss 文件齐备时恢复两张 2000 年年表的 48 个节气和 6 个河洛三端响应，分别与无故障时逐值相同。实际选用 DE441 时，清单、所用分块和 TDB 注入保留原来源拒绝。固定 72 根继续通过原始 JPL 系数经 CALCEPH、Skyfield 和 ERFA 求根的 1 秒 TT、0.001 角秒两项门槛，最大差分别为 40.233 微秒和 `1.64e-6` 角秒。该样本覆盖显式 `native` 及实际消费的 DE441 路径。 [JPL 原作者说明](https://ssd.jpl.nasa.gov/doc/de440_de441.html)

[独立参考包](../tests/data/solar_de441_v1/README.md)包含1684—2304年全部14904项及原1200年小寒。维护的生成器独立安装CALCEPH／Skyfield，按每月15日前后30个TT日括区，实际计算原始JPL光行时、引力偏折、光行差和同定义框架；未导入FateBridge，也未用其根作起点。全部事件及控制点的当前源码／安装包正向视黄经最大差约0.000000396角秒，原0.001角秒线全部符合；实际根与独立CALCEPH／Skyfield最大相差一个TT浮点间隔，约40.233微秒。对原生原始JPL的最大差约1.730毫秒，包含其TT数值参数与TDB来源时标处理差异。这不是全连续域或观测证书。

原DE440参考值没有替换：全部14904项对其仍符合原1秒线，最大约0.234秒；额外10毫秒诊断线仍有9016项未过，保留跨日期框架和模型差异，不把较接近的新参考替代旧门槛。原压缩Swiss文件下有1167项未过0.001角秒线的原型记录也保留；文件几何表示、完整光学和参考系分别核对，不能改判成原始JPL对照已消除全部第三方差异。

维护入口 [`audit_solar_model_reference.py`](../scripts/astronomy/audit_solar_model_reference.py)默认复跑原96点，也支持所选独立参考包。CI读取完整14905项正向黄经，并实算上一修订全部16／21项一秒失败的并集和1200年补充交点；完整实际年表逐根、源码／安装包、REST／CLI／新stdio MCP分别验收。风水原5秒候选保留策略保持原值，不能当作1秒或毫角秒数值验收线。

### 验证范围与入口限制

2026-11-13，最终源码与锁定依赖的新安装包分别完成全部14905项实际年表求根，TT点、模型及返回标志逐值相同；14914项正向角度（完整原队列、九个控制点和1200补充点）也逐值相同。对同一CALCEPH／Skyfield参考，新路径在全部14905项的绝对TT差不大于原生Moshier；后者仍有1909项超过原1秒线，最大约2.643679秒。旧压缩文件参考下1901项原生失败和旧完整修订的16／21项失败按各自原参考保留。

原96与576项DE440参考继续原值复跑，分别零一秒超差，最大约0.087588／0.089800秒；原生Moshier的12／74项失败分别保留。实际ASGI REST、独立CLI和新stdio MCP共462次调用中，源码／安装包业务字段相同，960条TT诊断符合原一秒线；14个新stdio目录均有92个公开工具，168个子进程核对了28个实际载入模块。空目录配置的24个六壬／金口诀案例没有所比判定字段差异，完整／部分Swiss文件配置下原4个跨模型判定差异均保留。完整文件配置原120条TT逐值保持，部分文件配置的4条1799年冬至依赖改用DE441，实际移动约0.250894秒；没有重写原判定或参考。

原生文件交点的`ephemeris_library_version`记录实际运行库。内置DE441不发布原生太阳旗标或SDK版本，该字段为null；实际源、光学方法与日期框架在`solar_model_details`分别声明。具名有界模型仍保留`engine_is_approximate`状态；有限数值通过不自动升级成全域物理认证。已有长期服务进程需重新载入当前代码，独立新stdio通过不能证明既有聊天连接已刷新。

### 缺文件、无原生库和端点来源选择

前轮空目录6000／9999年失败的根因是原生在其解析范围外直接报缺文件，尚未返回Moshier类别。现在仅对SDK明确的缺`.se1`文件错误选择既有内置DE441；损坏文件及严格Swiss／JPL错误不改选来源，严格JPL缓存也不加载未选用的DE441。缺SDK时可直接使用内置源；同一TT求根和首个穿越后浮点规则保持。

[补充独立参考](../tests/data/solar_de441_availability_v1/README.md)包含9个端点／远期年份的全部216个交点及4个实际相邻边界。原始JPL记录由独立CALCEPH／Skyfield求根；220项的当前最大TT差约0.322毫秒，正向黄经差约0.000013581角秒，均符合未改的1秒及0.001角秒线。native、auto与无SDK配置合计658次实际求根通过相应固定参考，重复配置不是新增独立天文样本。

没有原生库时，2000、6000、9999年的原子偏移钟时与DE441路径可用。1960年前原有历史UT1／DeltaT钟时政策仍需SDK，缺失时报`solar_root_clock_unavailable`，不以UTC充当未知TT。未来民用标签保留末次闰秒假设；补充年份通过不认证1—9999年全连续域、绝对UTC或SOTA。

### 被替换的 Moshier 修订及失败

旧 `fatebridge_complete_moshier_solar_v1/v2` 使用作者1996年地月质心级数及完整原生Moshier月球。原作者C算术对照、原96／576项通过、v1全队列15项一秒失败以及v2的21项DE440／16项同框架Swiss文件失败均保存在独立审查档案；v2最大误差分别约1.304962／1.281667秒。原13906项毫角秒失败及3656项不优于原版Moshier仍为旧修订结果，不因替换而通过。无调用方的旧Python太阳实现、重复地球系数与专属实现测试已移除；原数值参考、失败证据、原生Moshier行星和显式AA1996模型继续分别保留。替换是采用已独立对照的更完整动力学来源，不是给旧级数改名。

来源：[JPL星历与TDB定义](https://ssd.jpl.nasa.gov/planets/eph_export.html)、[CALCEPH时间和读取接口](https://calceph.imcce.fr/docs/latest/html/c/calceph.multiple.cusage.html)、[Skyfield视位置](https://rhodesmill.org/skyfield/positions.html)和[固定Swiss源码](https://github.com/astrorigin/swisseph)。共享轨道谱系和软件一致不证明全时域SOTA、历史／未来UTC或现实预测效度。

## AA1996

在项目根目录构建到尚不存在的绝对目录：

```bash
uv run --locked --extra dev python -m fatebridge.fetch_aa1996 --output /absolute/new-aa1996-build
export FATEBRIDGE_SOLAR_TERM_MODEL=aa1996
export FATEBRIDGE_AA1996_MANIFEST=/absolute/new-aa1996-build/manifest.json
```

构建器下载并核验固定原包、32个计算源码文件，再调用本机 C 编译器。离线原包可用 `--swiss-archive`、`--aa56-archive` 指定，字节须匹配来源配置。构建须使用当前来源配置与范围；不载入不同配置生成的清单。

已记录的实际构建平台为 macOS arm64；Linux 构建分支尚未验收，Windows 不支持该构建器。算法来源与当前构建参数见[AA1996来源配置](../src/fatebridge/data/astronomy/aa1996-solar-v1.json)。

1.2.0沿用相同的32个计算源码文件，只增加逐年、315度和2月1—12日 TT 括区约束的派生立春资格。2205—2320年116个所需立春与独立 Skyfield/DE440 对照均在原1秒 TT 线内，最大约0.876秒。[完整2905项原队列](../tests/data/solar/aa1996-projection/README.md)仍保留19项超差、最大约1.274秒；普通太阳观测与全部节气范围没有据此扩张。此核对未认证所有历元、未来 UTC 闰秒或预测有效性。

## VSOP2013

```bash
uv run --locked --extra dev python -m fatebridge.fetch_vsop2013 --output /absolute/new-vsop2013-build
export FATEBRIDGE_SOLAR_TERM_MODEL=vsop2013
export FATEBRIDGE_VSOP2013_MANIFEST=/absolute/new-vsop2013-build/manifest.json
```

离线构建用 `--source-dir` 提供匹配来源配置的文件；`--compiler`、`--linker` 可选择已有工具链。系数与时间转换代码编入本地库，运行时无需 Python ERFA、jplephem 或外部星历文件。清单须由当前构建器按已声明来源生成。

直接计算输入为 TT 儒略日，求根括区须跨越向前的目标太阳黄经：

```python
from fatebridge.core.vsop2013_solar import longitude_crossing_tt, solar_longitudes_tt

points = solar_longitudes_tt([2451545.0])
crossing = longitude_crossing_tt(285.0, 2451545.5, 2451556.5)
print(points["longitudes"], crossing["jd_tt"])
```
