# 人类图时区来源一致性复核

本轮修复命名时区规则与结果指纹脱节的问题。正常来源下的历法算法、数值门槛、原典资料及固定解释模板不改；本轮不能关闭完整历法、完整原典或完整自由文本解释验收。

Python的[PEP 615](https://peps.python.org/pep-0615/#behavior-during-data-updates)规定，`ZoneInfo`创建时读取规则，已有对象不会随数据更新变化。旧实现缓存该对象，却在生成时区证据时重新读取文件指纹。实际反例先以纽约规则换算1980-07-01当地12:00，得到16:00 UTC，再换入有效UTC规则字节；结果保留纽约换算，却记录UTC文件指纹，完整固定解释核验仍通过。反例在测试原生上下文内注入有效TZif流，不修改安装文件，也不声称认证了原生执行真实性。

现在转换对象与其指纹来自同一次读取的不可变字节，包版本及IANA版本一同保存。命名时区被再次使用时检查来源；人类图计算开始、结束也核对同一身份，中途清空或淘汰解析缓存不能把新规则混入旧计算。来源变化、不可读、损坏分别返回`timezone_rules_changed`、`timezone_rules_unavailable`、`timezone_rules_invalid`，沿用不可重试的`ephemeris_source_inconsistent`错误及HTTP 503。它们需要维护者恢复一致数据并重启运行环境，不要求用户修改正确的出生资料。

首次接口检查还发现，pytz的公开时区列表会根据文件可读性惰性过滤名称；冷启动缺失文件时，有效名称因此被误报为用户错误。现在由pytz生成的声明名单识别名称，再独立读取并检查文件。这个依赖细节仅封装在时区适配器；[pytz官方实现](https://github.com/stub42/pytz/blob/master/src/pytz/__init__.py)及当前锁定依赖均可核对。未知名称仍是输入错误，固定偏移无需读取命名时区数据。

原始混源回执保存在`tests/fixtures/human_design_timezone_source_v1/mixed-source-run.json.gz`，原业务哈希不改，新增回归要求拒绝该回执。提前冻结的18组正常结果涵盖原有15组IANA文本参照与3组固定偏移；修复后完整业务值及固定解释核验逐字段一致。不同有效文件、版本变化、不可读、损坏、缓存清空和淘汰均有反向检查，首次失败日志保留。

具体运行结果、安装包、完整测试清单、散列及原验收状态见复核记录（本地数据：`validation/human-design-timezone-source-verification.json`）。完整回归与有限协议对照只验证其明示范围：开始与结束的文件检查不证明原子读取，文件指纹不认证数据库来源或历史钟表记录；未来时区按已锁定规则外推，不预测未来法律变化。

原38项专业要求与失败案例继续保留，7项未完成要求没有降级为通过。原典标签、课程分期与多次交会优先序、2001版29.1／29.2的10角分分歧、完整384线意义及固定规则、全历法范围和任意模型解释仍需各自证据。此前8题真实模型开发验收沿用原答和原评分，本轮没有追加模型调用。现实预测样本仍为0，不以通过测试数量折算预测准确率。
