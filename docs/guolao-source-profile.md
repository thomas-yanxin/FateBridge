# Moira 完整源规则的显式领域方法

本方法解释 Moira1.50Final 所选规则目录，公开工具默认仍为 v3 条件子集。领域调用者显式提供 `CompiledProfile`，再调用 `guolao.build_chart(..., moira_profile=profile)`。规则从调用者指定文件载入，没有自动搜索目录或新增公开请求参数。

## 来源与范围

规则与软件语义来自 At Home Projects 的 [Moira1.50Final](https://github.com/Horace-Maxwell/Moira_APP_MacOS_ARM)，包括 UTF-16 规则文件、RuleEntry、RuleParse 和 EvalRule。所选目录含 298 条源声明，展开为 547 个条件和 163 条逻辑别名；反向别名和五组正常目标的后写覆盖使原生映射表实际为 321 项。

原来源版权告示为 GPLv2-or-later。完整源规则数据、原许可文本和独立对照保存在外部研究资料中，不随项目打包。默认接入及规则数据分发边界仍待确认。软件语义对照只裁定该版本行为，不能认证果老原典、完整整盘天文或预测效力。

## 职责与规则定义

[编译器](../src/fatebridge/core/guolao/guolao_moira_profile.py)载入显式版本并生成不可变 profile；[解释器](../src/fatebridge/core/guolao/guolao_moira_rules.py)实现目录使用的类型化语法，每次求值另持状态，不使用 Python `eval`。[原生事实适配器](../src/fatebridge/core/guolao/guolao_moira_native.py)接收同次保留的坐标和宫位，不从公开 JSON 恢复计算输入。

条件值、是否求值、隐藏状态和展示资格分别记录：

- 原 `computeRules` 可跳过已隐藏节点；未求值不是假值。诊断查询不能补写原始 canonical 状态。
- `&`、`|`保留急切求值顺序；命名引用可读取隐藏规则的条件。递归求值中保留缓存 null，不改为固定点求解。
- 显式 `~` 和文字扫描生成的自动抑制边分别保留；嵌套拼名引用不自动成为抑制边。
- 抑制逐跳比较 level 和完整三段 rank，可经过条件为假或未求值的节点；never-output 节点仍可供引用及别名展示。
- 外层按 Java Hashtable 顺序求值，最终按 level、rank、内部名称排序，再应用别名、性别换名及展示政策。
- 作者未定义的布尔名返回原 `f` 并记录未定义符号。未提供的原生事实须声明 unavailable，保持未知。源式错误、未知事实和未定义符号分别交付。

`moira_rule_evaluation` 保留全部条件和别名状态、缺项、抑制来源与可能抑制来源。`moira_patterns` 只投影本次确认可展示的条件；数量不表示完整原软件的命中总数。

## 原生事实的限定

适配器保留十一曜顺序 `日月金木水火土计罗炁孛`和相等坐标的稳定次序，按完整坐标计算近邻和原 `__sp` 扫描。近宫界阈值严格小于 1°，恰好 1°不纳入。选定黄道的精确输入与 Java binary64 输入分别说明。

身宫采用源默认 self_mode0 的月曜口径。未注入提供器时，研究安命、太阳高度昼夜、太阳节气季节及三个神煞沿用已声明政策。其余三十神煞、源月柱、源农历晦朔弦望、命度、命宿和源黄经宿界保持缺失。现代赤经研究宿位不作为 Moira `%` 黄经宿位。适配器只声明所选目录的事实闭包。

## 有限独立对照

原作者 Java 参考覆盖 16 组完整目录条件事实、6 组小写语法机制和 4 组原大写未定义引用控制。额外神煞宫位与等分宿界是合成前提。16 组分别使用三种展示政策，其余 10 组各一种，共 58 次 canonical 比较；26,282 个条件—政策状态的 evaluated、result、valid、hidden，以及编译身份、外层顺序、rank、原别名映射和完整有序喜忌列表均相符。

逐一查询全部 547 条件时，初始 16 个上下文中 246 条有真假两侧，301 条未见真。来源提供器扩展使其中 92 条新增真值见证，209 条仍未见真；三个预先指定案例未达到其真值目标。这些有限输入不覆盖全部条件分支、动态边或完整传统理论。自包含语法控制见[冻结参考](../tests/data/guolao/moira_rule_semantics_v1.json)与[当前回归](../tests/guolao/test_guolao_moira_tool.py)。完整外置规则和 Java 对照需要本地研究资料。

## 显式来源提供器

[来源提供器](../src/fatebridge/core/guolao/guolao_moira_provider.py)读取同源外置资源，处理原生年表、年干／支、月支、月时、卦气、分组、主表资格和成对别名。历法字段是明确前提，提供器不从公历推断原软件年月日时。

`MoiraNativeProvider(profile, calendar)` 只能与同源规则 profile 一起注入。未传 calendar 时，仅使用本次已有立春研究年柱和所选时支，并回显政策；月柱和农历日保持缺失。传入 calendar 后，每个 `None` 保持缺失，不补本次年柱。提供器先移除其命名空间中的研究值，再覆盖已知事实；未知前提和已知无位置分别记录。源月柱缺失时也移除旧太阳节气四季布尔。陆位 `god_positions` 及证据保持独立。

444 组完整来源前提的 14,652 个神煞单元与原 Java 相符，包括有序宫支列表、别名后宫位、主表资格和成对映射；两组部分历法投影分别与 144／60 个已保存完整上下文相符。原软件完整说明表、流年主表和日期转换不在此范围。

给定完整 28 宿界时，纯区间提供器按源序、精确给定值、圆周半开区间和严格小于 1°判定。504 个角度输入的 6,048 个十一曜／身投影等于独立整数参考。原 Java 在两组 anchor26 的 `nextDown` 点返回 `?invalid?`，精确区间应为室火；两项差异保留。投影字段数不等于独立星位样本数，命度、命宿仍未知。

恒星天文候选未接入 builder 或公开默认。同目录、TT、flags 和物理文件下，安装 SDK 与独立 C 的 56 个向量有 42 个逐位不同，336 坐标字段中 62 个不同，56 个校正宿界有 7 个不同。给定 SDK 操作数的后续精确算术相符不能消除这些来源差异；Java1.64 与 C2.10 模型也不能混同。该候选源码及失败资料已在仓库外归档。当前纯区间提供器仍要求调用者给定完整宿界，原生接线不注入宿界。

## 历法口径与瞬时边界

原作者 27 例区分调钟标签与当地标准历法标签，并将后者的数值日与北京偏移后的节气／新月数组比较。默认 LAT2、标准钟0和 LMT1分别处理；旧 EOT、Java 时标及嵌套次年事件仍有范围限制。

同 9 个民用输入的现行 v3 领域结果，GMT 标签与原标准分支一致，年柱符合从保存源操作数独立推导的瞬时成员关系。GMT2024-02-04 12:00例现行取甲辰，原软件按当地钟／北京偏移政策取癸卯；差异保留。纽约民用12点与原标准11点属于不同钟制。这组对照不填入缺失源月柱和农历日，也不认证全部历法域或原典唯一性。
