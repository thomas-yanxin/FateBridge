# Moira 完整源规则的显式领域方法

本方法补全 Moira1.50Final 所选规则目录的解释能力，**尚未替换公开工具默认的 v3 条件子集**。领域调用者必须显式提供 `CompiledProfile`，再调用 `guolao.build_chart(..., moira_profile=profile)`。没有从审计目录、环境变量或固定机器路径自动加载规则，也没有新增公开请求参数。

## 职责与规则定义

[解释器](../src/fatebridge/core/guolao/guolao_moira_rules.py)只实现该目录实际使用的类型化表达式语法；不使用 Python `eval`，不引入 JVM、UI 或新依赖。[原生事实适配器](../src/fatebridge/core/guolao/guolao_moira_native.py)接收同次保留的坐标和已判宫位，不从公开 JSON 恢复计算输入。源规则由显式载入器编译为不可变 profile，每次求值另持状态。

条件值、是否求值、隐藏状态与展示资格分别记录：

- 原 `computeRules` 可能跳过已经隐藏的节点；未求值不是条件为假。诊断查询不能补写原始 canonical 状态。
- `&`、`|`保留原急切求值顺序；命名引用可读取隐藏规则的条件。递归正在求值时保留缓存 null，不改为固定点求解。
- 显式 `~` 和原程序文字扫描得到的自动抑制边分别保留。嵌套拼名的逻辑引用不自动升级为抑制边。
- 抑制在每一跳比较 level 和完整三段 rank，并可经过条件为假或未求值的节点。内部 never-output 节点仍可供引用及别名展示。
- 外层求值按原 Java Hashtable 顺序，最终按原 level、rank、内部名称排序，再应用别名、性别换名和所选展示政策。无限、cap6 和原 level3/cap6 分别比较。
- 作者未定义布尔名仍返回原 `f`，同时记录未定义符号。真正未提供的原生事实必须显式声明 unavailable；它们保持未知。原式求值错误、未知事实与未定义符号分别交付。

`moira_rule_evaluation` 保留全部条件和别名状态、缺项、抑制来源与可能抑制来源。`moira_patterns`只投影本次确认可展示的条件；其数量不是完整原软件的命中总数，且不转换为事件概率。

## 原生事实的限定

适配器保留十一曜的原顺序 `日月金木水火土计罗炁孛`及相等坐标的稳定次序，按完整坐标计算近邻和原 `__sp` 扫描。宫界阈值为原软件严格小于 1°，恰好 1°不纳入。选定黄道的精确输入约定与原 Java binary64 输入计算分别说明，不据此声称原生事实逐位复现。

身宫明确采用源默认 self_mode0 的月曜口径。未注入来源提供器时，研究安命、太阳高度昼夜、太阳节气季节和三个已提供的神煞均沿用各自已声明的研究政策。其余三十神煞、源月柱、源农历晦朔弦望、命度、命宿及源黄经宿界没有被补造。现有现代赤经研究宿位不作为 Moira `%` 黄经宿位输入。该适配器只声明所选 298 条目录的事实闭包，不声称复现原程序全部 provider。

## 2026-11-18 有限独立验收

原作者 Java 在候选读取之前冻结源、observer、输入与门槛，独立运行一次。26 组输入包括 16 组完整目录条件事实、6 组小写语法机制和 4 组原大写未定义引用控制。额外神煞宫位与等分宿界明确是假设前提，不能用于认证神煞历法或真实宿位。

候选首次执行 58 次 canonical 比较：16 组各三种展示政策，另 10 组各一种。全部 26,282 个条件—政策状态的 evaluated、result、valid、hidden，以及编译身份、外层顺序、rank、原别名映射和完整有序喜忌列表均零差异。没有修改门槛、重生成参考或重跑旧 51,484 网格。

R23 的 16 个完整事实上下文另逐一查询全部 547 个条件；246 个有真假两侧，301 个从未为真，未取得全部条件分支或动态边的独立覆盖。因此仅接受这组冻结前提下的解释器能力补全，不宣布全算法 SOTA。

两组原生领域调用均交付 547 条件、163 别名，约 160 条件保持未知；类型合同通过，没有源式求值错误或错误纳入的未决展示。直接领域结果与此前公开响应各有五处原始哈希字段差异，该原始门槛仍保留失败；另对已保存结果应用既有公开序列化边界后，没有预期源规则变更之外的差异。缺失公开哈希不算公开哈希验证通过。

现有公开 v3 的两组请求 before/after 各执行六次 REST、新 stdio MCP 与 CLI，跨端完整业务结果一致。这只确认现有公开路径连续性，不是新显式源方法的三端验收。本轮没有运行项目测试、收集、CI、格式、类型、项目构建或合同／清单检查器；新增回归只编写，按累计超过 50 项后再运行的约定保留。

## 显式来源提供器

`guolao_moira_provider` 读取外置、具名版本的资源，分别处理原生年表、年干／支、月支、月时、卦气、分组、主表资格及成对别名。资源仍来自同一 [Moira1.50Final 源版本](https://github.com/Horace-Maxwell/Moira_APP_MacOS_ARM/blob/9bb126fd84997aa26fed6e91b4bdf438fceb0e38/moira_s.prop)，不随项目打包。历法字段是明确前提；提供器不从公历日期推断原软件的年月日时，也不认证该版本是原典唯一标准。

`MoiraNativeProvider(profile, calendar)` 只能与同源的显式规则 profile 一起注入 `build_chart`。没有传 calendar 对象时，只沿用本次已有的立春研究年柱和实际选定时支，并回显其研究政策；月柱和农历日保持缺失。传入 calendar 对象后，其每个 `None` 都保持缺失，不补入本次年柱。未知前提和已知无位置分别记录；来源提供器先移除其命名空间中的旧研究值，再覆盖已知事实。源月柱缺失时，旧太阳节气四季布尔也被移除。陆位 `god_positions` 及其证据保持独立。

固定 444 组完整来源前提的 14,652 个神煞单元均与原 Java 软件一致；实际有序宫支列表、完整别名后宫位、主表资格和成对映射也零差异。两组部分历法投影分别与 144／60 个已保存完整来源上下文相符。原软件完整说明表、流年主表功能和历法日期转换不在这项验收范围。

R24 另有 16 个完整规则上下文和 8 个原生事实投影，只扩充有限条件覆盖，不计新根因。原 301 条中新增 92 条真值见证，209 条在该扩展后仍未见真；三个原计划案例的真值目标失败原样保留，不以其他案例命中替换。完整分支和传统理论仍未通过。

给定完整 28 个宿界时，纯提供器按原序、精确给定值、圆周半开区间和严格小于 1°判定。504 个角度输入及其 6,048 个十一曜／身投影均等于独立整数参考。原 Java 在两组 anchor26 的 `nextDown` 点各给一次 `?invalid?`，精确区间应为室火；原两项差异完整保留。6,048 是投影字段数，不能当作独立星位样本数。命度、命宿仍未知。

恒星天文层尚未通过。相同目录、TT、flags 和物理文件下，安装 SDK 与独立 C 的 56 个向量有 42 个逐位不同（336 坐标字段中 62 个），56 个校正宿界有 7 个不相等。给定实际 SDK 操作数的后续精确算术 56 项都正确，不能因此将原 C 比较改判通过。该恒星路径未接入原生 builder 或公开默认；原 Java1.64 与现代 C2.10 的模型也不能混同。

该恒星候选没有生产消费者，完整源码及失败结果已归档到外部审计证据，生产目录不保留未验收入口。归档不计修复，也不消除上述失败。当前可用的纯区间提供器仍要求调用者明确给定完整宿界；原生接线没有注入这些宿界。

三次 God-only 原生领域观察和一次合成合并控制通过预定门槛，类型合同有效；两份原领域结果的陆位、天体、安命及其他计算字段保持，未知月柱／农历日／宿位没有补造。这仅接受有范围的来源提供能力，不认证完整果老盘、古典解释、物理精度、预测效度或全项 SOTA。公开默认仍为 v3，许可与默认集成方案未作更改。

## 历法口径与瞬时边界

原作者27例明确区分调钟标签与当地标准历法标签，并将后者的数值日与北京偏移后的节气／新月数组比较。它不是所有地区都同时发生的物理年界；默认LAT2、显式标准钟0与LMT1也不能混称同一前提。旧EOT、原Java时标与嵌套次年事件的限制分别保留，完整原软件日期映射仍未获验收。

另对同9个民用输入实际执行现行默认v3领域方法，9个GMT标签与原标准分支一致，9个年柱均符合事先从已保存源操作数独立推导的瞬时成员关系。GMT2024-02-04 12:00例中现行取甲辰，原软件因其当地钟／北京偏移政策仍取癸卯；原差保留，不要求现行算法按此旧政策改年。纽约民用12点与原标准11点仍是不同钟制。这组对照不认证星历物理精度、全部历法域、原典唯一性或预测效度，也不填入尚未提供的源月柱和农历日。
