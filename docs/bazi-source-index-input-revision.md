# 六条校读修订进入产品查询

后续核对已从当前连接实际资源确认旧v3输出契约不接受新版结果，14组冻结结果均受影响；两次追加诊断仍为500。见[连接契约漂移及恢复边界](bazi-connected-contract-drift.md)。本文其余内容保留本组件当时的验收范围。

源码及独立安装包的`bazi_source_compare`现已采用新的v6索引，将审计中确认的6条错录接入实际查询。367条记录、重复登记、全部强弱标注和3条禁止档位约束保持。原始v5索引、转录文件、历史计算及原26处分歧另行保留。

本地REST、MCP、CLI及隔离安装包验证通过。当前聊天已连接的MCP另有一次真实调用返回`internal_error`、500，尚未通过更新验收，不能把安装包通过说成该服务已经生效。本轮没有重启共享服务。

## 查询行为与来源链

六条读法及图版依据来自[上一阶段的完整输入修订](bazi-corpus-input-revision.md)，对应五个不同输入；通关末例在两组重复登记，继续返回两条。新的生成器先核对完整旧索引、事前计划、当前v9来源视图和图版散列，仅应用限定的六个完整记录修订，其他361条逐项相等。

查询修订后的字面四柱，可取得校读后的记录与`input_reading_revision`：原录文、原索引条目、校读理由、两份扫描的图版散列及页叶定位。引用中`registered_document_scope=original_transcription_before_input_revision`明确原登记文档仍是历史转录；正确读法的校读链另列，避免让旧文档散列冒充修订文本。

六条记录原本均无已裁定的三档标签，仍保留`null`，比较为`unadjudicated`。文字摘要说明校读不补定强弱。输入旧错误四柱仍可计算，但不会自动指向校读后的命例；历史复核使用原v5索引。没有改动旺衰参数、生产历法、出生资料或强弱等级。

新索引方法标识为`registered_literal_source_annotations_reviewed_inputs_v5`。版本用于区分查询资料与校读路径，不表示预测正确率或经典认证等级。

## 完整回归与三端结果

修订前先保存全部367条旧输入及6条修订输入的实际公开服务输出。验证保留旧输入的完整数值计算；当前367条输入则逐条与上阶段v9的完整计算比较，全部相等。123条明确标签、244条未知／未标注记录与当前24个不同输入的分歧均未改变。原26处分歧的完整对象另存，不以当前24条或本次错录修订抵扣。

本地三端覆盖六条修订的完整结果和发布摘要、原典明确分歧、禁止档位违反与满足、错误专业事实拒绝，以及旧错误输入不冒充当前命例。模型输出合同另验证未知不补定、无独立版本／专家认证、无独立样本信用。

最终源码副本115项检查通过；安装包81项检查通过。这些集合有重叠，不能相加为独立案例或预测准确率。两次隔离真实MCP各执行29次有效调用、1次错误调用，分别完整恢复220页同run结果，核对结果身份、分页偏移、全文散列、原回执和冻结预期业务散列。没有重新计算补齐分页，也没有提高原定4,096字符预算。

最终构建视图含2,341份冻结输入。其中2,338份与通过源码及MCP检查的视图完全相等，只增补项目声明的README、LICENSE、NOTICE；没有更换产品字节或测试预期。最终包的1,218份包内文件逐字节对应冻结源码，许可文件和README元数据另外核对。安装包未安装覆盖共享环境。

调用合同由正式生成器重新生成并通过`--check`，34份文件内容均未变化；109份黄金文件没有改写。旧黄金业务JSON仍通过新输出Schema校验。本轮不声称全仓库、Linux黄金字节、托管CI或已连接服务已经验收。检查保留一项Pydantic已有警告及MCP客户端字段弃用提示。
