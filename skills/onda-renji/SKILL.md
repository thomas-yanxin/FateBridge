# 人际与合作

先按用户事实区分朋友、工作合作、家人与伴侣，不因有两个人就套合婚。不以“合伙靠不靠谱”把规则分数当信用审查。

## 共用规则与资料

先读[按用户问题组织咨询](../_shared/consultation-routing.md)、[硬边界](../_shared/safety-boundaries.md)、[引擎调用](../_shared/fatebridge-engine.md)和[解读层](../_shared/onda-counsel.md)。涉及日期、阶段或变化时读[共享时间选择](../_shared/timing-selection.md)；采用西占主题解释时读[西占证据参考](../_shared/western-topic-evidence.md)。发现入口可能为软链接，先以 `pwd -P` 解析真实目录，再读相对引用。

资料使用当前聊天已确认内容，一次核对所选计算真正必要的缺项；不猜出生时刻，不把其他方法的缺项升级为必答。普通首轮严格字段投影、关闭快照；完整导出首次 `fields=null`，读同 run 交付。追问复用未变结果，只补所需新层。

## 按问题选择依据

| 任务 | 候选依据 | 如何解释 |
| --- | --- | --- |
| 个人交往方式／支持资源 | `analyze_destiny`、`ziwei_birth` 或 `astro_chart` 相关配置 | 选择与当前问题相关的特点；贵人象意不指认现实人物性别、身份或必然帮助 |
| 朋友／合作双方互动 | `two_person_compatibility`、`astro_relative_chart`；按需要 `sukuyo_compatibility` | 真正跨盘依据与各自特点分开，双方方向性保留 |
| 合作阶段／某年关系安排 | `timing_analysis`、`ziwei_horoscope`、`western_timing_analysis` 或 `firdaria` | 按共享时间规则加入，不由个人时运推对方行为 |
| 分工、创业角色、共同款项 | 接事业或财务的相关任务 | 只补当轮需要的角色与责任，不附带完整事业财务报告 |

## 读取关系与评分

关系类型按已说明事实选 friendship／business／family，未知用 general。星盘关系模式按实际 compare／synastry／composite 读取，非浪漫关系不强套性吸引。宿曜读取双向关系，不只读一方。

配合度读实际 strengths/challenges、`detailed_analysis` 和 `score_basis/source_scope`；某格局分混合个人内部事件时如实说明，不把总分当纯跨人评价，也不自行删项重算“净分”。空 recommendations 不编成引擎建议。

## 交付与后续

围绕一处能配合之处与一处实际存在的张力解释，只有返回支持时才两边都写；再联系真实分工、决策、开支或回应给一项核对。保留用户判断权，不推测对方心意、忠诚、违约或现实可信度。
